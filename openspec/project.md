## 项目概述

即时软件缺陷预测系统（Just-in-Time Defect Prediction，JIT）：从真实开源仓库及审计过的公开数据构建用途分离的训练集，训练机器学习模型预测「某次提交是否会引入缺陷」，对外提供在线预测服务与可视化前端，指导代码评审员优先审查高风险提交，实现质量保障左移。

## 目标用户

- 代码评审员：按风险排序审查提交，优先处理高风险项。
- 研发团队负责人：查看缺陷引入趋势，掌握代码库质量变化。
- 算法工程师：训练、对比与切换预测模型。

## 技术栈

- 后端：Python 3.11 + FastAPI + SQLAlchemy。
- 数据：用 PyDriller 和原生 Git 命令解析仓库，结果存 MySQL 8。
- 任务：Celery + Redis，支持幂等、心跳、重试、取消和断点恢复。
- 工件：首期用本地持久化卷，通过存储接口预留迁移到 MinIO 的能力。
- 模型：scikit-learn、XGBoost、LightGBM、PyTorch；解释用 SHAP。
- 前端：Vue 3 + ECharts + Element Plus。
- 部署：Docker Compose。
- 工程：GitHub Actions 持续集成，OpenSpec 规格驱动开发；当前基线见 `docs/README.md`。

## 团队约定

- 分支规范：main（稳定，由维护者管理）、wang（个人独立开发）、feature/<us-id>-<slug>（可选短期功能分支）。
- 本项目以当前有效的规格、最新规划和已经验收的 wang 实现为准，不迁就外来的旧材料。只推送到 origin/wang；合并到 main 以及其它分支的维护不由本流程负责。
- 提交信息格式为 `type(scope): subject`，例如 `feat(szz): 支持行号追踪`。
- 合并前至少一位非作者成员在 PR 中审阅，审阅记录留在平台上。
- 所有需求变更必须先创建或修改 OpenSpec change，不允许只改代码不更新规格。
- 看板任务必须标注 Sprint 和对应的 OpenSpec change 或 task。
- 每个核心功能都要有正向验收，以及至少一个异常或无效输入的验证。
- 原始设计、外来原型和旧工具已经隔离到 `archive/external`，不再参与默认检索和构建。开发只依赖 `docs/` 下当前有效的规格、决策与指南。

## 当前实施边界

v1、v2 和旧迁移都不改，数据库结构停在 `0010_dataset_numbers` 这一版。公开 CSV 离线资产和复核材料保留；应用研究用的数据集、任务、RBAC、A17～A19、页面，以及无损导出 12 个数值，都已经实现。

真实 106,674 条数据只做过结构校验，不等于金标、不等于历史回放合格，也不等于具备候选资格。旧的 false 判定和 2 条未决记录不回写。

下一批要做的是逻辑回归和随机森林的注册、任务与评估工件，再做真实语义和冻结编码器融合的 P1 与候选发布。质量线持续做有限核验。这一批只在 wang 分支进行，不依赖被隔离的材料。
