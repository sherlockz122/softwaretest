# Change: add-dataset-table-and-feature-choice

## Why

数据集详情页现在只给每行看「仓库、提交、分区、标签」四列，12 个数值特征明明已经算好存在库里，页面上一个字都不显示；想看数据长什么样只能整包下载 CSV 再自己开表。训练模型时，12 个特征也全部固定参与、每个特征用什么形式（原始值、取对数还是标准化）由代码写死，用户没有任何选择权——想做「少用几个特征」或「给长尾的计数特征取对数再训练」的对照实验，只能改代码。

这是 Sprint 2 里「研究模型可配置」的一块：让用户先看清数据，再自己决定拿哪些特征、以什么形式去训练。两个能力共享同一个前提——12 个数值特征的人话命名与取值口径——所以放在同一个 change 里交付。

## What Changes

- 数据集详情页把「数据样例」升级为二维表：每行是一个提交，列是仓库、提交、分区、标签加 12 个数值特征；特征列用界面术语表里的人话命名，数值按口径格式化，支持横向滚动、分页、按分区与标签过滤、每列独立显隐。
- 模型训练请求新增两个可选字段：`features`（选哪些特征）与 `forms`（每个特征用什么形式：原始值 / 取对数 / 标准化）。缺省保持现状：全部特征，逻辑回归全部标准化、随机森林全部原始值。
- 训练产物（模型工件与评估报告）记录本次训练实际使用的特征、形式与标准化统计，界面在模型详情里展示这份契约，方便对照实验的复现。
- 标准化统计只在训练分区拟合，验证与测试分区只用拟合好的统计做变换，杜绝数据泄漏。

## Capabilities

### New Capabilities

- `dataset-2d-table`：数据集成员以二维表展示与查询，特征列可显隐、可按分区与标签过滤。
- `training-feature-choice`：训练时可选择特征子集与每个特征的形式，契约随产物记录并可追溯。

### Modified Capabilities

- `model-training`（训练入口的请求体扩展两个可选字段，旧请求语义不变）。
- `dataset-detail`（成员查询新增可选过滤参数，缺省行为不变）。

## Impact

**数据库**

无迁移。已训练模型与已冻结数据集全部保持原样；旧训练请求不含新字段，按缺省（全特征、插件默认形式）处理，产物契约字段兼容读取。

**后端**

训练请求新增 `features`/`forms` 的准入校验与归一化（顺序固定为数据集字段顺序，缺省按插件补全），并入幂等键的请求回放比较；训练子进程按所选特征与形式构造矩阵，逻辑回归不再内置标准化（标准化成为可选的 per-feature 形式，缺省等价于旧行为）；评估报告的契约字段随工件一起密封。

**前端**

数据集详情页的样例表升级为二维表；训练页新增特征勾选与形式选择；模型详情页展示训练契约。文案全部走 `terms.js` 术语表，保持日常说法。

**不在本次范围内**

不改变候选预测链路的特征合同（其特征来自仓库历史的 14 维口径，与本 change 的研究数据集 12 维口径无关）；不放开研究模型的发布资格；不实现按特征重要性的自动筛选；数据集二维表不做排序与多条件组合查询。

**关联追踪**

受影响文档：`docs/04-API与数据库规格.md` 的模型训练请求体与数据集详情参数、`docs/08-界面与交互规格.md` 的数据集详情与模型训练页面、`docs/07-需求设计测试追踪矩阵.md` 的 US-11 与 US-08 行，以及 PRD 的「模型训练与评估」需求域。

对应 User Story US-11（模型训练与评估）与 US-08（数据集查询与审计）。
