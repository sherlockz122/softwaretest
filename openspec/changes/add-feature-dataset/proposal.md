# Change: add-feature-dataset

## Why

系统已经有了可审计的 SZZ 候选证据，也有了 Kamei14 的计算内核、持久化任务和 A15、A16 两个页面。
但还缺两样东西：成熟度判定和不可变的时间数据集。
用户故事 US-06 到 US-09 要求先把公式、历史覆盖范围和信息的可用时间固定下来；
如果不先固定，就会出现最严重的一类错误——把「缺失的历史」和「事后才知道的标签」当成 0 填进训练数据。

## What Changes

- 交付 US-06 要求的十四维计算内核，以及 US-07 依赖的质量统计基础，并用真实 Git 历史逐项手算，覆盖时间、覆盖范围和重命名的边界。
- 纠正 NUC 的歧义：它统计的是相关文件上次修改提交的去重数量，不是全部历史修改次数。
- 交付多轮完整观察的成熟度判定、双时间数据集内核，以及只读的真实样本审计。
- 接入固定快照、可靠任务、持久化和 A15、A16 页面。
- 更新 docs/03、docs/05 到 docs/07、开发指导、规划、文档记录和阶段报告。

## Capabilities

### New Capabilities

- `feature-dataset`：版本化的特征内核、覆盖与缺失审计，以及带观察窗口的时间数据集约束。

### Modified Capabilities

没有。这次改动不改变任何已经验收过的能力行为。

## Impact

**数据库**

成熟度判定和只读审计只使用标准库以及现有的冻结解析器、特征、SZZ 和修复（Fix）输入，不新增依赖、迁移或服务。
特征纵向集成通过迁移 `0008_features` 新增特征轮次和特征项两张表，唯一键包含根轮次与提交哈希或序号。
数据集纵向接入还需要一张固定多轮观察关系的表；A17～A19 的接口和页面由独立的用途分离数据集变更交付。

**后端**

后端新增特征内核、成熟度判定和只读审计入口。
接口覆盖 A15（启动特征提取，携带特征版本、用途和可选的 Fix 轮次）、同路径的分页查询，以及 A16（读取质量统计、分页结果，并按特征缺失或有效值降序下钻）。
页面显示历史或候选用途、覆盖范围、源摘要、缺失原因和运行状态，并复用现有任务链接的取消与重试。
A17～A19 的数据集接口由独立的用途分离数据集变更交付；数据集纵向接入部分验证的是原生生产的十四维特征和历史观察资格。

**存储与资源**

固定快照使用仓库自己的私有裸仓库，目录树缓存采用最近最少使用策略，最多保留 64 项，累计原始树字节不超过 8 MiB，Python 对象本身占用的内存另算。
特征内核的复杂度保持在 O(N²)，超时时间要按真实资源重新估算。
祖先和文件回溯过程中会周期性检查租约、取消、磁盘空间和总时限。

**不在本次范围内**

模型训练与效果发布、只在训练集上拟合的填充缩放采样工件，以及外部公开数据的审计和语义版本路线，都不在这次改动里。
这次改动也不做 US-08 和 US-09 要求的数据集与模型，它们要等合格数据之后才进入模型阶段。
