# Design: add-feature-dataset

## Context

US-06～US-09 依赖的是已接受的 HEAD，而 A11 是已入库记录的并集。
两者不是一回事——把 A11 的并集直接当成输入，等于跳过了「这份记录是否真的对应已接受快照」的验证。

所以首批采用纯函数式的输入契约：内核只接受已经冻结好的输入，
由后续服务负责验证 HEAD、私有存储键和完整窗口。不能直接把 A11 的并集传进来。

v2 在线特征已经交付，v1 合同保留；完整的标签来源认证和数据集 A17～A19 属于单独的后续验收。
当前差异见
[在线可知特征与来源绑定验收](../../../docs/development/在线可知特征与来源绑定验收.md)。

## Goals / Non-Goals

**Goals:**

- 交付十四维特征内核，结果可复现、可审计、每个缺失都有原因。
- 固定公式、覆盖范围和可用时间的口径，杜绝「用缺失填零」。
- 交付成熟度判定和不可变时间数据集内核，并对真实来源做只读审计。

**Non-Goals:**

- 不新增 A17～A19、数据集迁移、线上数据集页面、模型训练或语义 tokenizer。特征表和接口已经交付。
- 成熟标签只由版本化的完整观察、确认和时间审计内核产生，还没有作为线上数据集发布。
- 未知、候选 SZZ、以及没有证据的提交，都不转为 clean。
- 不合并到 main 分支。
- 不用工程 fixture 冒充真实精度。

## Decisions

### 决策 1：输入契约与不可变性

- 输入是冻结的提交、文件和修复信号。
- 身份只用一个不含个人信息的标识，不带姓名、邮箱、提交消息和 diff。
- 快照要校验：解析版本与身份版本、SHA、重复项、DAG 环、HEAD 可达性。
- full 模式缺父提交就拒绝；recent_window 允许缺父，但六个历史特征置 null，不伪造零。
- 摘要绑定仓库、HEAD、覆盖范围、算法与源码摘要，以及实际输入。
  提交的输入顺序不影响摘要；文件序号沿用解析器冻结时的顺序。

### 决策 2：历史范围的因果定义

- 历史范围等于「DAG 严格祖先」和「提交时间、SHA 前序」的交集。
- 同一时间的 SHA 之间有明确次序；非祖先分支不能污染当前提交的历史。
- 遇到时间倒置的祖先，六项历史特征置 null 并记录原因。
- EXP 和 REXP 用唯一祖先提交；SEXP 用作者相关子系统的提交去重。
- 子系统取首层目录，根目录记作 `.`。
- 目录使用 Git 的 POSIX 路径表示，不按宿主 Windows 的规则折叠大小写。

### 决策 3：十四维的计算口径

- 普通提交的文件按「新路径或旧路径」计入 NF、ND、NS；重命名只计一次目的路径。
- LA、LD、LT 原始求和，不除以 NF、不取 log、不做缩放。
- Entropy 按 churn 分布除以 log2(NF)；全零 churn 记为零。
- 任何当前文件不是 parsed 状态（含二进制、编码异常、超限、submodule）、
  当前是 merge、或者内容无效时，依赖它的特征置 null。
  绝不把「被略过的文件按零贡献」拼出一个看起来有效的向量。

### 决策 4：历史类特征的具体定义

| 特征 | 定义 |
|---|---|
| NDEV | 相关文件的祖先开发者的并集 |
| NUC | 各文件上次修改 SHA 的并集数量，不是全部修改次数 |
| AGE | 本项目定义的 churn 加权天数；首次文件或零 churn 无定义时置 null |
| REXP | 连续的 elapsed_days / 365.25 |
| SEXP | 祖先文件不完整时置 null |

- AGE 和论文里的算术平均、年份分桶并不完全相同。
  所以明确命名为 `kamei14-dg-v1`，不声称逐字复现了论文。
- 重命名沿单父链回溯；新增会终止旧的同名历史；删除后重新新增不混用。
- 存在 merge 祖先或无法完整解析的祖先时，文件历史置 null；EXP 和 REXP 仍可独立计算。

### 决策 5：历史 FIX 的取值

- 只接受与当前记录绑定、并且标签可用时间不晚于事件时间的版本化冻结信号。
  晚到或者缺失的记为 null。
- candidate 模式统一取 FIX = 0，并明确写入原因和默认值；模式进入摘要。
- 不读取 SZZ 标签；人工复核不能回填历史 FIX。

### 决策 6：输出、摘要与确定性

- 输出是冻结的元组；转成字典时返回独立副本。
- 每个 null 都带原因；质量报告提供缺失数量与原因、分位数、最小值和最大值。
  绝不填充，也绝不构造标签分布。
- 同一份输入重算，摘要和结果完全相同。
- 代码摘要按 UTF-8 统一换行，避免 Windows 与 Linux 的差异造成假漂移。

### 决策 7：只读适配不能直接把数据库记录扔进内核

- 现有的解析表没有记录文件在 Git 里是什么类型，所以光看「解析成功」并不能断定它是普通文件。
- 只读适配改成去本地 Git 里查一遍目录清单，确认每个条目的类型和内容之后，再显式地取出来。
- 符号链接、子模块和类型变更一律当作未知。
- 缺字段，或者对不上原始内容，都直接拒绝。
- 下一批的服务实现会补上目录清单的缓存，以及固定私有快照的校验。

### 决策 8：纵向集成——迁移、任务与接口

表与轮次方面：

- 新增迁移，加 feature_run 和 feature_item 两张表，
  唯一键由根轮次、提交号和序号三样组成。
- 启动事务冻结已接受的 HEAD 与存储、初次解析覆盖、用途，
  以及可选的同 HEAD 已完成 Fix 的复核与证据摘要。
- 标签可用时间取轮次生成、判定、复核、Issue 观察时间里的最大值；
  未复核且内容不完整时，不能形成否定的 FIX 结论。
- 没有 Fix 也可以提取，这时历史 FIX 缺失。

Worker 执行方面：

- 在固定的私有 bare 仓库上运行受监督的可达计划，与 A11 的并集求交集；full 模式缺解析直接拒绝。
- 初次计划在验证模式和 blob 之后，原子冻结最小的提交输入；
  重试从冻结输入重算并校验摘要，不重新去取当前复核。
- 来源摘要另外绑定私有存储键、Fix 根轮次和 Fix 冻结摘要。
- 对外响应不带私有存储信息，也不带原始身份。
- 目录清单的缓存最多留 64 项，累计原始数据不超过 8 MiB（Python 对象本身的开销另算）。
- 祖先和文件回溯时，周期性调用租约、取消、空间和总时限检查。
- 数值公式保持一致；源码摘要变化会产生新轮次。

原子性与互斥方面：

- 每 10 个结果连同检查点和进度在同一事务提交；最终批次同时发布完整质量和成功状态。
  部分完成的轮次没有总体质量。
- 复用现有协调器的自动续跑和人工重试。
- 解析、同步、Fix、SZZ、特征五类任务互斥。
- 拒绝旧令牌，以及最新任务、根任务、HEAD、存储、源码、解析、身份的任何变化。
- 数据库迁移的完整降级路径先检查数据，再执行 DDL。

接口方面：

- 启动特征计算的接口可以指定用哪一版特征、什么用途，以及要不要挂上某一轮 Fix；
  同一个地址用 GET 就能分页查已跑完的轮次。
- 质量查询接口返回完整统计和分页结果，
  还能按特征、按缺失原因往下钻（按数值从大到小排，相同数值的先后顺序固定）。
- 页面显式展示历史与候选用途、覆盖、来源摘要、缺失情况，以及运行中和失败状态，
  复用现有的任务链接做取消和重试。不增加标签或预处理。

### 决策 9：并发读必须在同一个快照下

MySQL 在这个隔离级别下，创建事务里的幂等查询可能先读到一份较早的数据快照，
之后才等到仓库锁、拿到 Fix 的最终发布状态。

后面读 Fix 轮次和判定时看到的是最新已提交的状态，
所以查证据也必须读最新状态，不能混入前面那份旧快照。

特征和 SZZ 一起修正这一处，并用受控的双事务时序用例验证：
晚发布的证据摘要和标签可用时间被完整冻结，同时不改变已有轮次和追溯算法。

### 决策 10：成熟度内核的时间语义

- 单次在今天完成的 SZZ，不足以证明「历史训练截止时就已经知道是 clean」。
- 内核支持多轮完整观察；历史 HEAD 必须是已接受 HEAD 的祖先，而且它的输入恰为该完整祖先集合。
- 覆盖结束时间取绑定私有快照的实际克隆或同步的启动时间，作为保守下界。
- 发布时刻取实际成功任务的完成时间和证据可用时间的最大值。
- 没有可核对的来源，就不得宣称完整覆盖。
- 以下情况会让相关祖先变成 Unknown：未复核的候选、不完整的解析、Issue 不可用、过时的复核。
  只有确认过且完整合法的追溯才产生 buggy。
- 默认 W = 90 天是预先声明的工程政策，不是从测试集优化得来的。
  允许显式配置正整数，并纳入标签版本和内容哈希。
- clean 的可用时间不得早于 W 届满和完整观察发布；buggy 不得早于 Fix 复核、证据和 SZZ 发布。
- 未来才知道的修复可以纠正新轮次，旧数据集不改写。

### 决策 11：切分与 purge

- 只有完整历史的特征可以进入训练审计。
- 按事件时间分组后做 70 / 15 / 15 的确定边界；同一时间的 SHA 排序不跨分区。
- 再按标签可用时间严格早于下一分区首事件来剔除晚到的标签；测试集不晚于快照。
- 不根据剔除结果反过来移动边界。
- 每个分区必须有两类；训练集中任一维十四维全缺失，就明确判定为不可训练，不用填 0 掩盖缺失。
- 冻结原始向量与原因、来源与规则、配置、切分和剔除的摘要。
- 类权重按 N / (2 × N_class) 计算，只在训练集上。
- 填充、缩放和采样工件留到模型阶段才在训练集上拟合，本批不拟合。

### 决策 12：下一批的边界

- 只读 MySQL 适配和命令行工具是本机的审计入口，不新增并行任务框架、线上接口或迁移。
- 读取完整冻结轮次时使用共享加锁读，校验解析、身份、公式、SZZ 源码与输入集合和摘要；
  对当前的 Fix 复核做保守核对。
- 工程时间线夹具可以验证成功路径，但不能冒充已有的真实成熟两类数据。
- 真实已存轮次如果不满足条件，就输出不足的原因；A17～A19 在下一批接入。

### 决策 13：失败恢复与安全

- 纯函数部分不写数据库、不联网、也不动仓库；校验失败时给出固定的错误码，不留下半成品。
- 输入不可变，输出是副本，不含原始身份或 diff。
- 中断只丢失当前内存里的计算，重算结果确定。
- 后续任务复用现有的执行令牌、租约和检查点原子批次，不新建平行任务框架。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 纯函数接收者没法证明调用方真的用了已接受 HEAD | 真正的权限、快照栅栏、空间、超时和恢复由后续服务承担。本批只能保证内核自身正确。 |
| 祖先集合需要逐提交扫描 | 首批以正确性优先，不承诺大仓库性能。缓存不得改变因果与路径边界。 |
| O(N²) 复杂度边界保留 | 用真实 400 提交的 Worker 故障恢复和合成规模探针验证；不以夹具声称大仓库无限性能，超时需要按真实资源重新估算。 |
| 外部 13 维研究数据与产品 14 维不兼容 | 不能伪装成过去系统观察到的数据，也不能混入生产内核。 |
| 历史证据今天才生成 | 历史的训练截止点可能根本没有可用样本。必须明示「不可构建」或「类别不足」，禁止回填时间。 |
| W = 90 天是政策而非最优值 | 不按测试集调参以保持可复现，代价是可能不是最优窗口。 |
| 把缺失当成 0 的危险 | 一旦某个环节这么做，整条数据链就失去意义。这里用「留空并写明原因」和「判定为不可训练」两道闸门来堵。 |

## Validation

- 真实 Git：用一个两文件、多作者的小仓库做夹具，逐项手算十四维来核对。
- 边界用例：重命名、删除再新增、根提交、零 churn、merge、二进制、编码异常、超限；
  缺父、full、recent、未接受分支；同时间 SHA、倒置时间；晚到 Fix；
  输入冻结；摘要顺序与版本变化；质量缺失与分位数。
- 真实 MySQL、Worker、浏览器、规模探针与回归。
- 本机验收目录里保留脱敏后的证据。
