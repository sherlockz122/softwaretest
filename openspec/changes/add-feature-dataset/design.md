# Design: add-feature-dataset

## Context

这次改动建立在已经交付的十四维特征内核、持久化任务、鉴权和 A15、A16 页面之上。
前半部分还包括成熟度判定、不可变时间数据集内核，以及对真实来源的只读审计。
第一版（v1）特征合同继续保留，第二版（v2）在线特征已经交付；
两者的差异写在[在线可知特征与来源绑定验收](../../../docs/development/在线可知特征与来源绑定验收.md)里。
完整的标签来源认证、数据集迁移和 A17～A19 的后续验收由独立变更承担。

用户故事 US-06 到 US-09 依赖已接受的 HEAD 提交，而 A11 返回的是已入库记录的并集，两者并不等价。
所以首批只定义纯函数的输入契约，调用方必须交出固定的提交、文件和修复信号。
真正校验 HEAD、私有存储键（storage_key）和完整窗口的工作由集成层完成，不能把 A11 的并集直接传进内核。

相关的独立变更各自负责一段范围。
历史重放的内核和来源核验由 add-historical-replay 完成；
第二版在线特征的任务、质量和已接受 Git 绑定由 add-online-causal-features 接入；
首条「public 研究 12」应用由 add-purpose-separated-datasets 交付，包含 0010 迁移、A17～A19、任务、权限、页面和导出；
外部公开数据的审计由 add-public-dataset-audit 负责，要先核验历史回放时间和特征是否可知，再继续数据集纵向接入；
扩大来源之前的数值前置批次由 optimize-causal-file-history 承担，性能等价不等于成熟两类或训练资格。
公开资产、语义准入和独立语义版本按[公开数据与语义模型衔接指南](../../../docs/development/公开数据与语义模型衔接指南.md)设计，
公共导入和语义路线的接口与迁移还等后续功能切片。

数据集纵向接入还需要 A17～A19 的接口、数据集迁移和页面，其中 A17～A19 先由 add-purpose-separated-datasets 交付；这一段会把用途、来源和质量审计显式化。
旧的第一版、第二版特征和成熟度内核不改写。
模型工程可以并行推进，但效果和发布仍要等合格的真实数据。

数据集纵向接入部分仍然指原生生产的十四维特征和历史观察资格，不能把新研究结构的就绪当成原生产能力完成。
外部研究使用的 13 维特征与产品十四维不兼容，也不能拿来伪装成过去的系统观察，实际观测合同不改写，外部研究基准也不能绕过它。
相关口径见[2026-10-11 公开数据与历史评估口径](../../../docs/decisions/2026-10-11-公开数据与历史评估口径.md)。
后续模型沿用当前指南，来源知识、完整负例和旧的 false 资格标记都保留。

这次改动不重复实现已经验收的登录认证、异步任务与 outbox（待投递事件）投递、执行令牌、租约和检查点，
也不重建提交解析器、SZZ 追溯和 Fix 证据冻结。
特征轮次复用这些机制，只追加自己的业务参数、快照校验和发布事务。

## Goals / Non-Goals

**Goals:**

- 冻结十四维特征的公式、输入、时间、路径和覆盖规则，让同样的输入永远得到相同的结果和摘要。
- 让特征轮次绑定已接受的 HEAD 提交与私有快照，按原子批次发布，并在中断之后可以接着计算。
- 按预先声明的观察窗口和双时间规则区分有缺陷（buggy）、无缺陷（clean）和不可知（unknown）三种标签，不把今天才知道的证据回填到历史截止点。
- 用分位数、取值范围和缺失原因描述质量，不填充，也不构造监督标签。

**Non-Goals:**

- 不训练模型，也不在这次改动里拟合填充、缩放和采样工件；效果和发布要等合格的真实数据。
- 工程夹具只能验证成功路径，真实精度和两类成熟数据要等合格的真实数据。
- 不把外部公开研究基准或新研究结构当成原生生产十四维能力和历史观察资格。
- 只读审计不新增并行任务框架、线上接口或迁移。
- 移动端验收只修正布局，不新增任务、接口或页面功能，也不替代数据集和模型验收。

## Decisions

### 决策 1：输入只接受冻结的提交、文件和修复信号

内核接收的输入是冻结的提交记录、文件变更和修复信号。
身份只保留现有的身份键（identity_key），不携带姓名、邮箱、提交消息和差异内容。
快照校验会检查解析版本、身份版本、提交 SHA、重复记录、提交图里的循环，以及每个提交是否可从 HEAD 到达。

全量模式缺少父提交时直接拒绝；最近窗口模式允许缺少父提交，但六个依赖历史的特征留空，不伪造成零。
输入摘要绑定仓库编号、HEAD、覆盖范围、算法与源码摘要以及实际输入，
提交的输入顺序不影响摘要，文件序号沿用解析器冻结的顺序。
特征版本（feature_version）、公式摘要和规范化输入摘要一起隔离未来的规则变更。

这么选是因为内核不能靠调用方的自律来保证没有未来信息，只能把证据挡在输入之外，并让同一份输入可以复现。
放弃的是自证能力：纯函数无法证明调用方给的是已接受的 HEAD，权限、快照栅栏和完整窗口留给集成服务。

### 决策 2：历史范围只认严格祖先和提交时间前序的交集

历史范围取提交图上的严格祖先集合，再与「提交时间、SHA」前序的交集。
同一时刻的提交按 SHA 明确排序，非祖先分支不能污染当前提交的历史。
遇到时间倒置的祖先，六项历史特征留空并记录原因。

三个经验特征（EXP、REXP 和 SEXP）里，EXP 和 REXP 使用唯一的祖先提交，SEXP 使用作者相关子系统里的提交并去重。
子系统取第一层目录，根目录记为 `.`；目录使用 Git 的 POSIX 路径，不按宿主 Windows 的规则折叠大小写。

重命名沿单父链回溯；新增会终止旧的同名历史，删除之后重新新增的两段历史不混用。
遇到合并祖先或无法完整解析的祖先时，文件历史留空，但 EXP 和 REXP 仍可独立计算，SEXP 在祖先文件不完整时留空。

这样选是为了让历史范围可解释，牺牲的是扫描成本：每个提交都要沿祖先和文件路径回溯，仓库越大越慢。

### 决策 3：十四维按项目口径冻结为 kamei14-dg-v1

普通提交的文件按新路径或旧路径（`new_path or old_path`）计入文件数（NF）、目录数（ND）和子系统数（NS），重命名只计一次目的路径。
新增行数（LA）、删除行数（LD）和变更前总行数（LT）直接求和，不除以文件数，不做对数变换，也不缩放。
Entropy 按改动量（churn）分布除以 log2(NF)，全部 churn 为零时结果为零。

NDEV 是相关文件祖先开发者的并集，NUC 是各文件上次修改 SHA 的去重数量。
AGE 采用这个项目自己的 churn 加权天数，首次出现的文件或零 churn 没有定义时留空；
REXP 按连续的经过天数除以 365.25 计算。

历史修复信号只接受与当前记录绑定、且可用时间不晚于当前事件时间的版本化冻结信号；晚到或缺失都留空。
候选模式统一把修复信号记为 0，但保留明确原因，并让模式进入摘要。
内核不读取 SZZ 标签，人工复核也不能回填历史修复信号。

这些口径和论文里的 AGE 算术、年份桶不完全相同，所以规则版本明确命名为 `kamei14-dg-v1`，版本名只表示项目自己的冻结口径，论文只作参考。
放弃的是和论文结果的直接可比性，换来的是每个数字都有确定的来源。

### 决策 4：缺失和略过的文件一律留空，不填零

只要当前文件不是已解析状态，包括二进制、编码异常、超限和子模块，或者当前提交是合并提交、内容无效，依赖它的特征就留空。
不能把被略过的文件当成零贡献，再拼出一个看起来有效的向量。

输出是冻结的元组，转成字典时返回独立副本，每一项空值都带原因。
质量统计提供缺失数量和原因，以及分位数、最小值和最大值，只用有效值计算。
同样的输入重算，摘要和结果完全相同；代码摘要先按 UTF-8 统一换行，避免 Windows 和 Linux 的差异。

校验失败会产生稳定的 FeatureInputError 错误码，不留下半成品。
内核不读写数据库、网络和仓库，中断只会丢掉当前内存里的计算，重新计算是确定的。
这么选是因为填零会掩盖缺失，而缺失被掩盖之后，训练和评估都会得到错误的结论；放弃的是一部分不可训练的向量。

### 决策 5：用有界的 ls-tree 校验文件类型和内容

现有解析表没有保存 Git 的模式（mode），无法只凭「已解析」推断一个文件是不是普通文件。
只读适配层通过受监督的原生读取器执行有界 `ls-tree`，核对模式与 blob 之后再显式投影；
符号链接、子模块和类型变更都记为 unknown。

缺字段或者无法匹配原始 blob 时直接拒绝。
下一批服务实现目录树和模式缓存，并校验固定的私有快照，不能把数据库里的文件变更记录直接扔进内核。

这么选是为了避免把 Git 语义猜错，代价是多一次受控读取，而且旧数据在补齐之前不能用于计算。

### 决策 6：特征轮次在同一个事务里冻结快照，并按原子批次发布

迁移 `0008_features` 新增特征轮次和特征项两张表，唯一键包含根轮次与提交 SHA 或序号。
启动事务冻结已接受的 HEAD 与存储、初次解析覆盖、用途，以及可选的同一 HEAD 上已完成的 Fix 复核和证据摘要。
可用时间取轮次生成、判定、复核和 Issue 观察时间里的最大值；未复核并且内容不完整的证据不能形成否定的 Fix 结论。
没有 Fix 轮次也可以提取，只是历史修复信号缺失。

Worker 在固定的私有裸仓库上运行受监督的可达计划，再用 A11 的并集做交集过滤。
全量历史存在解析缺口时直接拒绝。
初次计划验证模式和 blob 之后，原子地冻结最小提交输入；重试从冻结输入重新计算并校验摘要，不重新读取当前的复核状态。
重算沿用同一套数值公式，源码摘要变化会产生新的轮次。
源摘要另外绑定存储键、Fix 根轮次和 Fix 冻结摘要，公开响应不带私有存储或原始身份。

每十个结果连同检查点和进度在同一个事务里提交，最后一批同时发布完整质量和成功状态，部分轮次没有总体质量。
自动续跑和人工重试复用现有协调器，解析、同步、Fix、SZZ 和特征任务互斥；
旧令牌、最新的任务编号、根任务、HEAD、存储、源码、解析或身份发生变化时一律拒绝。
数据库迁移的降级路径先检查数据，再执行任何建表或删表语句。

为什么把发布做成这样：批次失败不能留下半份可读结果，重试也不能改变已经冻结的输入。
放弃的是更大的单批事务，因为那样失败时会回滚更多工作，恢复时间更长。

### 决策 7：成熟度按预先声明的观察窗口判定

系统同时限制事件时间和标签可用时间。
观察窗口 W 默认是 90 天，这是预先声明的工程政策，不是从测试集里优化出来的；
它允许显式配置成正整数，并进入标签版本和内容哈希。

clean 的可用时间不能早于窗口届满和完整观察发布，buggy 的可用时间不能早于 Fix 复核、证据和 SZZ 发布。
未来的已知修复可以纠正新的轮次，旧数据集不改写。

覆盖结束时间取绑定私有快照实际克隆或同步的开始时间，这是保守的下界；
发布时间取实际成功任务的结束时间和证据可用时间的最大值，没有可核对来源时不得宣称完整覆盖。
未复核的候选、不完整的解析、不可用的 Issue 和过时的复核都会让相关祖先变成 unknown；
只有已确认且完整合法追溯的证据才产生 buggy。
现阶段的 SZZ 候选本身不直接当作确定标签。

判定之前要冻结已接受的快照、特征轮次、SZZ、Fix 复核版本、身份、公式和标签版本，后续计算不能改写这些输入。

单个今天完成的 SZZ 不足以证明历史训练截止点当时已知 clean。
历史 HEAD 必须是已接受 HEAD 的祖先，而且它的输入恰好是那个完整的祖先集合。
这么选的代价很直接：历史证据今天才生成时，历史训练截止点可能一个可用样本都没有，只能明示不可构建或类别不足。

### 决策 8：训练、验证和测试先分组，再按标签可用时间剔除

只有完整历史的特征可以进入训练审计。
按事件时间分组之后，以 70/15/15 确定训练、验证和测试的边界，同一时刻的提交按 SHA 排序，不跨分区。
然后用标签可用时间执行 purge（剔除）：训练标签必须严格早于验证集首事件，验证标签早于测试集首事件，测试标签不晚于快照。
不能根据剔除结果反向移动边界。

每个分区都必须有两类。
训练集里任意一维全部缺失时，明确标记为不可训练，不用填零藏起缺失。
冻结原始向量和原因，以及来源、规则、配置、切分和剔除的摘要；
类权重 `N/(2*N_class)` 只在训练集上计算。
填充、缩放和采样工件在模型阶段只对训练集拟合，这次改动不拟合。
验证集只用于确定阈值，测试集只做最终评估。
这么选是为了保证时间因果和可复现，代价是剔除之后可用样本会变少。

### 决策 9：接口和页面复用现有任务与权限

验收项 A15 的 `POST /repositories/{id}/feature-runs` 接收特征版本、用途和可选的 Fix 轮次编号，同路径的认证分页查询返回轮次历史。
验收项 A16 的 `GET /repositories/{id}/feature-quality?run_id=...` 提供完整统计、分页结果，以及按特征缺失或有效值降序的下钻，有效值按数值降序、序号稳定。

页面明确显示历史或候选用途、覆盖范围、源摘要、缺失、运行中或失败状态，并复用当前任务链接的取消与重试，不增加标签或预处理。
Member 和 Admin 可以发起，Viewer 只读。

复用现有任务和权限是为了不引入第二套状态机，代价是页面交互要受现有组件的约束。

### 决策 10：只读审计复用现有轮次，并统一使用当前共享锁

本机的只读审计入口由 MySQL 适配器和命令行工具组成，不新增并行任务框架、线上接口或迁移。
它读取完整的冻结轮次，校验解析、身份、公式、SZZ 源码、输入集合和摘要，并保守核对当前的 Fix 复核。
工程时间线夹具只验证成功路径，真实的两类成熟数据要等合格数据；真实已存轮次不满足条件时输出不足原因。

MySQL 的可重复读（REPEATABLE READ）隔离级别下，创建事务的幂等查询可能先建立旧快照，随后等待仓库锁直到 Fix 最终发布。
Fix 轮次和判定的加锁读会看到当前已提交的轮次，所以证据读取也必须使用当前的共享加锁读，不能混入旧的一致性快照。
特征和 SZZ 同时修正时，用受控的双事务时序验证晚发布的证据摘要和可用时间被完整冻结，不改写已有轮次，也不改变追溯算法。

只读复用的原因是审计不能改动源数据，也不能再造一套任务状态；代价是不满足条件的轮次只能判为不足。

### 决策 11：资源与容量按可解释的上限控制

目录树缓存采用最近最少使用（LRU）策略，最多保留 64 项，累计原始树字节不超过 8 MiB，Python 对象本身占用的内存另算。
祖先和文件回溯过程中会周期性检查租约、取消、磁盘空间和总时限。

特征内核的复杂度保持在 O(N²)，真实 400 提交的 Worker 故障恢复和合成规模探针验证过这条边界。
不拿夹具声称大仓库有无限性能，超时时间要按真实资源重新估算。
放弃的是大仓库上的吞吐，换来的是内存和排查成本可控。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 严格祖先和逐提交扫描优先保证正确性 | 大仓库的扫描成本很高，这次不承诺它的性能；线性资源探针和分支因果用例会记录代价，集成前再做规模和内存探针。 |
| 纯函数无法证明调用方给的是已接受的 HEAD | 权限、快照栅栏、空间、超时和恢复都由集成服务承担，内核只能校验输入自身的完整性和摘要。 |
| 观察窗口默认 90 天 | 历史证据如果在今天才生成，历史训练截止点可能一个可用样本都没有，只能明示不可构建或类别不足。 |
| 缺失一律留空 | 部分向量会直接不可训练，换来的是不把缺失伪装成真实的零。 |
| 文件历史在合并祖先或不完整祖先处留空 | 某些提交无法得到 NDEV、NUC、AGE 和 SEXP，只能等解析补齐。 |
| 目录树缓存最多 64 项、累计 8 MiB | 内存可控，代价是大仓库会反复读取目录树，超时要按真实资源重新估算；缓存不得改变因果和路径边界。 |
| `kamei14-dg-v1` 与论文口径不完全一致 | AGE 和年份桶的算术不同，结果不能直接和论文逐字对比。 |
| 只读审计保守核对当前复核 | 可能把实际可用的轮次判成不足，换来的是不把未复核证据当成确定标签。 |
| 外部 13 维与产品 14 维不兼容 | 不能拿外部研究数据伪装过去的系统观察，语义转换另走独立路线。 |

## Validation

- 用受监督的 NativeReader 读取真实 Git 的两文件多作者夹具，逐项手算十四维，覆盖重命名、删除后重新新增、根提交、零改动量、合并、二进制、编码异常和超限。
- 验证缺失父提交、全量和最近窗口、未接受分支、同一时刻的 SHA、倒置时间、晚到的 Fix、输入冻结、摘要的顺序与版本变化，以及质量统计的缺失和分位数。
- 在真实 MySQL、Worker 和浏览器上走通特征轮次、质量页面和取消重试，并做规模探针。
- 在本机只读审计已有的特征、SZZ 和 Fix 轮次，核对摘要、覆盖范围和当前复核；条件不满足时输出不足原因。
- 用受控的双事务时序复现 MySQL REPEATABLE READ 下的快照差异，确认晚发布的证据摘要和可用时间被完整冻结。
- 在独立的新卷上跑全量后端、静态检查、规格和契约回归，并在窄屏上确认页面没有横向溢出，质量表保留内部滚动，最后写验收报告。
- 本机的 runtime/acceptance 目录保留脱敏后的证据。
