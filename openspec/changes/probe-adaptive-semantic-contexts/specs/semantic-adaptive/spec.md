## ADDED Requirements

### Requirement: Immutable content-aware declaration
The probe SHALL declare exactly the prior96 members and executing sources before computation, bind v3/v2/weights, reject source/input/selection drift before publication and reconstruct both old versions exactly.

#### Scenario: No easier member substitution
- **WHEN** labels or scores change or an input is reordered
- **THEN** membership SHALL remain the declared identities and canonical prior order, or inconsistent input SHALL be rejected

#### Scenario: Mid-read drift
- **WHEN** source or an input manifest changes during declaration or contexts
- **THEN** no accepted artifact SHALL publish and the attempt SHALL remain distinguishable

### Requirement: Preserve floor and available content
The selector SHALL preserve every v2 whole line and require the highest declared content class for each hunk/role, within the unchanged32-candidate cap and4032 actual joined-token budget.

#### Scenario: Floor symbols while code exists
- **WHEN** floor lines are blank/symbols and an eligible alphanumeric line exists
- **THEN** required-class content SHALL be added or marked unsupported rather than counting floor alone as satisfied

#### Scenario: Cheap unchanged base context
- **WHEN** a nonempty old changed range exists alongside unchanged context
- **THEN** a changed old line SHALL take priority even if unchanged context is cheaper or lexical

#### Scenario: Legitimate symbols or whitespace
- **WHEN** the eligible changed range contains only symbols or whitespace
- **THEN** its actual best class SHALL remain valid without inventing code or deleting the member

#### Scenario: Cap or budget prevents support
- **WHEN** required class is outside32 candidates or proposed selection exceeds4032 tokens
- **THEN** the member/reason SHALL remain in the96 artifact and SHALL NOT enter encoding or be replaced

### Requirement: Bounded complete independent encoding
The encoder SHALL use a new contiguous function with at most32 code windows and zero selected-token omissions, keep old2-message windows and reject unsupported before loading the model.

#### Scenario: Old window contract preserved
- **WHEN** code needs9 through32 windows
- **THEN** new windows SHALL cover all tokens while old limits and artifacts remain unchanged

#### Scenario: Complete repeat
- **WHEN** all96 supported contexts encode in independent processes
- **THEN** both SHALL perform new full forwards with exact population/sources/CPU protocol and byte-identical files under RSS/time supervision

#### Scenario: Scientific scope
- **WHEN** coverage or repeat passes or fails
- **THEN** the report SHALL separate structural/lexical/eligible/full-change/model-utility claims, retain negative results, perform no classifier fits or oldtest scores and preserve product gates
