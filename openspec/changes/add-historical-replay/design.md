# Design: add-historical-replay

## Context

当前合同见
[docs/decisions/2026-10-11-历史回放与可知特征合同.md](../../../docs/decisions/2026-10-11-历史回放与可知特征合同.md)。

背景问题是：公开数据集提供的是「事件时间」和「可用时间」，
而生产合同要求的是在某一时刻真正可知的信息。两者并不等价。
如果不区分，回放出来的结果会被误当成生产标签。

这次只交付内核，不接生产链路。

## Goals / Non-Goals

**Goals:**

- 提供一套固定视野、可复现、不可变的历史回放内核。
- 明确每个标签的可知时间，让结果不依赖事后信息。
- 把公开数据里时间和特征口径的真实问题查清楚并记录，而不是顺手修掉。
- 资源消耗有明确上限，超出时安全停止。

**Non-Goals:**

- 不接入在线持久化，不做数据集 A17～A19 的迁移。
- 不做来源认证，也不做真实的两类产品数据。
- 不训练、不评估模型，不做治理。

## Decisions

### 决策 1：消息用途特征 v2 的语义边界

`kamei14-dg-message-v2` 沿用原来的数值工程公式。

其中 FIX 这一维的口径是：当时那次提交的消息关键词、否定词和文件上下文启发式。

- 不读取后来的 Issue、复核结果或缺陷标签。
- 取值为 0 表示「没命中启发式」，不代表「已确认不是修复」。

### 决策 2：回放目标和生产标签必须区分

`historical-horizon-replay-v1` 是一个固定视野目标，它兼容的是「已经观察到的链接」，
不能和生产环境里「永续实际观察」得到的标签混为一谈。

W90 和 L7 是预先声明的实验默认值，不是实测结论。

### 决策 3：负例（clean）的生成条件

- 在 W 之内：验证正链接，并用 L 重建知识。
- 在 W 末加 L：只有同时满足「完整兼容覆盖」和「没有未决项」时，才允许出现负例；
  否则一律 Unknown。
- 来源的实际取得时间不回填。
- 调用适配器时，严格校验祖先关系、覆盖度和金标。

两类 fixture 不能证明真实数据可训练。

### 决策 4：切分与 purge

- 原始完整事件按 70 / 15 / 15 固定切分；同一个时间组必须整组切分，不能拆开。
- 先划边界，再清理晚到的标签。
- 训练集和验证集严格早于下一个集合的首个事件；测试集不晚于观察截止时间。
- 保留 Unknown、清理记录和缺失，不因为缺类就改动边界。
- 类权重只在训练集上计算，而且不参与拟合。

### 决策 5：不可变性与证据绑定

回放的运行结果和审计记录返回的都是副本，调用方改不动里面的内容。
下面这些摘要全部绑在一起，任何一项变了都会对不上：

来源、原始向量、版本、规则、政策、证据、切分摘要。

### 决策 6：资源与安全边界

| 项目 | 上限 |
|---|---|
| 提交 | 1000 |
| 文件与链接 | 10000 |
| 回放向量 JSON | 32 MiB |
| 合作式监督超时 | 30 秒 |
| native Git | 300 秒（另有既有的输出上限） |

- 拒绝重解析、alternates 和覆盖源。
- 禁止网络懒获取、读取全局配置和执行 hook；不检出代码。
- 持续监督 D 盘的预计增长和中途余量；不足时停止，不转移到 C 盘。
- 旧的 O(N²) 实现没有做优化；上面这些规模限制不是全局的存储紧缩策略，只是这个内核的边界。

### 决策 7：来源核验方式与已知限制

- 固定原作者 revision，并用 Git blob 和 SHA256 做静态来源与 UTC 关联。
- 用两个 ActiveMQ 深度 8 的窗口，只能证明当前的 LT 和 message 是可计算的。
- 六项历史缺失和标签 Unknown 如实保留，不粉饰。
- 实测 ActiveMQ 的修复消息信号为 0，说明启发式的覆盖存在明确限制。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| FIX 靠启发式，AMQ 实测信号为 0 | 消息关键词口径在真实项目上覆盖很低，FIX 这一维可能长期接近全 0。已经记录在案，不在这里调参美化。 |
| W90 与 L7 是预先声明的默认值 | 没有经过实测校准，可能不适合真实数据的规模。 |
| 负例要求「完整兼容覆盖且无未决」 | 条件苛刻，负例会很少，多数样本是 Unknown。这是刻意的，宁缺毋滥。 |
| 只证明「可计算」，没证明「可训练」 | 两类 fixture 只验证内核正确性，不代表真实数据可用。 |
| 旧 O(N²) 未优化 | 大规模回放会很慢，靠规模上限兜住，不是长期方案。 |
| Git 探针限定为本地只读 | 换来安全，代价是核验不了远程来源。 |

## Validation

- 固定原作者 revision，以及 Git blob 与 SHA256 的静态来源和 UTC 关联。
- 边界测试、资源测试、完整回归、独立浏览器验收。
- 首次失败记录和最终 JUnit 保留在本机，只把安全副本做成脱敏索引，
  不产出 Actions artifact、HAR 或 trace。
