# Change: add-historical-replay

## Why

公开数据集里的「事件时间」和「可用时间」、负例覆盖情况，以及历史提交的 FIX 可知性，
这三样跟生产合同要求的并不等价。
直接拿公开数据当训练输入，等于把它们的假设当成了我们的事实。

所以需要一套独立、可核验的历史研究回放能力，它要同时成立两件事：

- 不回填实际观察——不许把「事后才知道」的信息塞回历史；
- 不因为等不到完美数据就停掉模型工程——回放的价值就在于让模型工作能先用受控假设推进。

## What Changes

- 新增独立的消息用途十四维特征版本。数值工程规则保留不变；
  后来的 Fix 复核结果不进入新输入，也不进入摘要。
- 新增不可变回放内核：固定的预测视野、假设的知识延迟、银标与金标、覆盖度和 Unknown 判定，
  以及预先声明的分组清理规则。
- 新增真实来源核验：固定原作者代码版本和真实 Git 窗口，
  把「时间口径」和「特征口径」问题的真实来源查明并记录，而不是静默修改数据。
  实测发现 ActiveMQ 有 177 个修复时间并不是原始最早时间。
- 新增本地只读 Git 探针，容量和执行时间都有上界，配套边界测试、资源测试、全量回归和遗留问题记录。

## Capabilities

### New Capabilities

- `historical-replay`：以固定视野和假设的知识延迟为契约的不可变历史回放内核，
  包含可知特征版本、负例判定条件、分组切分和来源核验。

### Modified Capabilities

没有。这次改动不改变任何已有能力的行为。

## Impact

**数据库**

不新增迁移，也不改表结构。生产用的 `time-labels-v1` 和 `kamei14-dg-v1` 及其哈希都不变。

**后端**

不新增接口，也不新增在线任务。回放能力以本地只读探针和离线内核的形式提供。

**存储与资源**

探针的容量和执行时间都有上界，不会因为仓库变大而无限跑下去。

**不在本次范围内**

不做模型训练，回放结果也不写回在线链路。

**关联追踪**

对应 User Story US-06、US-08；测试为 REPLAY-CAUSAL、REPLAY-TIME、REPLAY-SOURCE、REPLAY-RESOURCE，用例见 `tests/test_historical_replay.py`。
