## ADDED Requirements

### Requirement: 仓库克隆
系统 SHALL 支持把通过安全校验的公开 HTTPS 仓库异步克隆到隔离的本地存储。

#### Scenario: 克隆成功
- **WHEN** 用户提交一个有效的仓库 URL
- **THEN** 系统创建唯一的仓库记录和异步任务，返回仓库编号与任务编号
- **AND** Worker 完成克隆，记录规范化 URL、默认分支、HEAD 提交号和最终状态

#### Scenario: 不安全的 URL
- **WHEN** URL 使用了不允许的协议、内嵌凭据或异常端口，或者域名解析与重定向指向了回环、内网、链路本地或保留地址
- **THEN** 系统在建立任何不安全连接之前就拒绝请求
- **AND** 返回稳定的脱敏错误，不创建仓库记录，也不创建任务

#### Scenario: 重复的创建请求
- **WHEN** 同一个作用域用同一个幂等键重复提交同一个仓库
- **THEN** 系统返回第一次创建的那个资源
- **AND** 不重复克隆，也不产生重复的仓库记录

#### Scenario: 克隆失败
- **WHEN** 合法的仓库因为不可达、超时、超出大小限制或 Git 执行出错而失败
- **THEN** 任务进入失败状态，保存固定的错误码和脱敏摘要
- **AND** 错误信息里不出现凭据、本机路径、命令行或依赖版本

### Requirement: 受控的 Git 深路径支持
系统 SHALL 只通过子进程配置，让 Windows 深存储路径下的受控 Git 命令启用长路径支持，
并保留原有的 URL、证书校验、凭据、钩子和容量限制，不修改全局 Git 或系统设置。

#### Scenario: 深层私有存储路径
- **WHEN** 在合法长度的项目存储根和 UUID 私有路径下，Git 的打包文件或索引文件超过 Windows 常规的 260 字符限制
- **THEN** 受控的裸克隆和元数据核验可以成功，配置只在 Git 子进程里生效，网络安全、证书校验、发布与取消的限制都不变
- **AND** Python 侧的容量扫描会计入长路径下的打包文件，发布的字节数与实际一致；读不了的目录直接拒绝而不是漏算；扩展路径只用于本地文件访问，清理之前先校验路径落在本轮的 UUID 范围内

### Requirement: 提交解析
系统 SHALL 按确定的顺序解析提交的哈希、作者身份、作者时间与提交时间、消息、父提交和文件变更，并分批持久化。

#### Scenario: 正常解析
- **WHEN** 系统扫描一个已经克隆好的仓库
- **THEN** 每个提交的元数据和文件变更都写入数据库
- **AND** 「仓库 + 提交哈希」的唯一约束挡住重复提交
- **AND** 检查点只在对应批次成功提交之后才推进

#### Scenario: 解析中断后恢复
- **WHEN** 解析过程被打断后重新执行
- **THEN** 系统从上次的进度继续，不重复导入已经入库的提交

#### Scenario: 异常的文件变更
- **WHEN** 某个提交包含空消息、重命名、删除、二进制文件或超大的变更内容
- **THEN** 系统按版本化的策略记录或跳过这些受限内容
- **AND** 单个异常文件不会破坏已经提交的批次

#### Scenario: 固定初次解析窗口
- **WHEN** Member 对已克隆的仓库启动初次解析，选择全部历史或者最近 N 个提交
- **THEN** 系统固定 HEAD、窗口范围、规则版本和执行计划摘要
- **AND** 按提交时间再按 SHA 稳定排序，记录作者身份的哈希值和原始时间偏移
- **AND** 同一个幂等键重放同一个任务，另一个窗口的请求不会改写已经建立的窗口

#### Scenario: 取消或资源不足后继续
- **WHEN** 解析被取消、超时、输出超限，或者磁盘装不下预计增长和余量
- **THEN** 系统保留此前已经提交的批次和已发布的 Git 数据，记录稳定的错误或取消状态
- **AND** 后继任务从同一个检查点继续，过期的执行令牌写不进去
- **AND** 最后的批次、检查点、进度和成功状态在同一个事务里提交

#### Scenario: 查询已入库数据
- **WHEN** 已登录用户查询提交列表或文件列表
- **THEN** 系统返回有界且稳定的分页结果，并标明哪些内容被略过
- **AND** 不返回原始作者邮箱、存储路径、执行令牌或原始命令输出

#### Scenario: 独立快照的增量同步
- **WHEN** 初次解析完成后，Member 请求同步默认分支
- **THEN** 系统创建任务、投递记录、审计记录和独立的同步窗口，固定基线并安全克隆到一个新目录
- **AND** 新 HEAD 的增量按「新可达集合减去旧可达集合」计算，不按时间戳过滤
- **AND** 最后的批次、检查点、正式 HEAD 和成功状态在有效的租约检查下同事务提交

#### Scenario: 同步中断和回执丢失
- **WHEN** 同步被取消、资源不足、Worker 中断，或者快照发布的回执丢失
- **THEN** 已提交的批次、旧基线和已发布的候选快照都保留下来，后继任务继续同一个窗口
- **AND** 旧的执行令牌不能推进状态；同一个幂等键的请求重放原任务，不重新选择远程 HEAD

#### Scenario: 同步无新提交与历史覆盖度
- **WHEN** 新旧 HEAD 相同，且默认分支没有改变
- **THEN** 同步以零个新提交成功结束，不重复入库
- **AND** 初次按最近 N 个提交建立的窗口仍然标记为有限历史，不会因为同步就变成完整历史

#### Scenario: 默认分支历史被改写
- **WHEN** 增量同步发现已记录的 HEAD 不再是新 HEAD 的祖先
- **THEN** 仓库进入待复核状态
- **AND** 系统不静默删除或重写已有历史

#### Scenario: 默认分支变化或历史消失
- **WHEN** 默认分支发生改变、旧 HEAD 对象不在新快照里，或者非空历史变成空
- **THEN** 同步进入待复核状态并保留候选快照供人核对
- **AND** 不导入分叉提交、不推进正式 HEAD、不自动解除复核，也不删除旧快照

### Requirement: 缺陷修复提交识别
系统 MUST 依据可审计的证据规则识别候选的缺陷修复提交，
并保存证据类型、取值、置信等级、规则版本和人工复核状态。

#### Scenario: 关键词命中
- **WHEN** 提交消息命中带单词边界的缺陷修复关键词，并且不属于排除语境
- **THEN** 系统保存 medium 等级的关键词证据
- **AND** 这条提交是否纳入 Fix 集合，由当前规则版本决定

#### Scenario: 已确认的 Bug Issue
- **WHEN** 提交关联的 Issue 被确认具有 bug 类型或标签，并且存在修复、关闭或等价关系
- **THEN** 系统保存 high 等级的 Issue 证据，并把这条提交纳入候选 Fix 集合

#### Scenario: 只出现普通 Issue 编号
- **WHEN** 提交消息里只包含普通 Issue 编号，无法确认该 Issue 是 bug
- **THEN** 系统不自动把这条提交标记为 Fix
- **AND** 可以保存一条 low 等级的线索供人工复核

#### Scenario: 误报语境
- **WHEN** 关键词出现在文档修正、拼写修正、否定语境或回滚里
- **THEN** 规则按已声明的排除条件处理，并保留判定依据

#### Scenario: 固定接受快照与规则重算
- **WHEN** Member 运行 Fix 识别，或者改变版本化政策后重算
- **THEN** 系统固定已接受的 HEAD、解析与规则版本及其摘要、覆盖度和政策，按可达的已解析集合生成一轮独立的结果
- **AND** 不纳入未被接受的同步批次，不覆盖旧证据和复核结果，也不把有限覆盖或没有证据的情况认定成 clean

#### Scenario: Issue 观测不确定与资源边界
- **WHEN** Issue 确认失败、被限流、返回的是 PR、连接不安全、发生重定向，或者超出查询与响应预算
- **THEN** 系统只保存受限的 low 线索，不伪造 high 证据
- **AND** 调用公开 HTTPS 接口时校验全部地址和证书、固定对端，不发送凭据，也不执行远程写操作

#### Scenario: Fix 批次与外部观测恢复
- **WHEN** 在已提交批次之后发生取消、空间不足、Worker 被强杀，或者 Issue 观测与最终事务的回执丢失
- **THEN** 已提交的判定、复核和首次冻结的观测都保留下来，后继任务沿用同一个根任务和计划继续
- **AND** 批次与检查点在有效的令牌、状态、租约、最新任务和根任务检查下同事务提交，旧的执行写不进去

#### Scenario: 人工复核并发与审计
- **WHEN** Member 提交确认、拒绝或恢复待复核状态，并附上理由
- **THEN** 系统检查预期的版本号，并在同一个事务里保存状态、版本号、操作人、理由和审计记录，保留规则给出的原始证据
- **AND** 相同的已接受决策可以安全重放，其它冲突返回 409；Viewer 的写入被拒绝；系统不自动生成 SZZ 标签

#### Scenario: Fix 查询与页面恢复
- **WHEN** 已登录用户查看 Fix 轮次与证据，或者遇到查询与写回执错误
- **THEN** 系统提供有界且稳定的分页、覆盖度和复核历史；页面刷新后能关联查询，同一个幂等键跟踪实际任务，并隔离迟到的响应
- **AND** 对外响应里不包含私有路径、令牌、作者邮箱或 Issue 的原始载荷
