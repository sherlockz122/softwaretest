# Design

## 证据及兼容

保留外部A/B字节、SHA256和packet/case绑定，副本及来源路径仅留本机runtime/review-intake。其completed/independent_attestation仅为提交者声明；当前记agent辅助、尚未确认符合双人独立人工标准。B的额外范围/日期声明保留，若适配既有1024字符rationale限额，须留全文附件与有来源绑定的摘要，不截断覆盖原件。

技术核验在已取得的固定Git对象中禁网络/懒取/替换对象，记录命令/范围及结果；区别原始意见与开发方补证。第二例默认blame不命中17e22cff的差异不可静默抹平；祖先关系及修复属性不证明缺陷因果。未做执行复现不冒称做过，原始SZZ选项/筛选缺证保留未知。

## 阶段控制

工程、覆盖/资源/性能与合格资产受限研究继续按当前版本/用途/限额和回归执行。agent意见可提出研究假设，不直接触发改标/剔除或test驱动选择。若探索筛选，另立版本/子change和预声明对照，保留原始标签/基线及限制。

来源独立认证、Gold/噪声率和依赖该来源的产品终验/发布在使用其结论前需要适任人员独立核验、分歧处理及受控修订，其它readiness不继承。人审可用工具辅助，但须实际承担核验责任，开发助手不能补造人审。

## 责任、停止与验证

开发方先做技术补证并在准备触及门槛前提出有限人员/工作量请求；用户当前无需为工程赶交，届时协调两名审阅及必要仲裁。复核不足则保持Unknown/争议、换源/用途或停止对应发布，不允许后补追认。

本轮仅文档与少量本机证据（预算0.05GiB），用现有包装器检查strict/本地链接/API合同及保护哈希；不启服务/下载/重跑业务回归。后续子change须验证人审缺失/工具回表不能提升资格、可继续限定工程、原件及旧状态不改、错误/不足/身份不符拒绝及版本兼容。
