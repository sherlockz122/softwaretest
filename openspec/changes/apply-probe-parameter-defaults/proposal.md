# Change: apply-probe-parameter-defaults

## Why

2026-10-19 的探针参数决策把三个参数定在了文档里，代码却还在用旧值：标签观察窗口的默认值仍是 90 天，按 90 天算 ActiveMQ 有约三分之二的真实缺陷引入提交会被标成 clean；输入上限根本不存在，任何人都可以提交一个需要四小时的全历史解析任务。

参数只写在文档里等于没落地。这次把已经定下来的数值填进代码，并让窗口的来源只剩一处。

## What Changes

- 标签观察窗口的默认值从 90 天改为 180 天，数据集策略、数据源入口、审计脚本和回放策略四处都跟着改，并改成同一个来源。
- 输入上限新增 700 提交的准入边界，超过即拒绝，不再让人提交必然超时的解析任务。
- 标签观察窗口的标定阈值定为 30% 可容忍误标率，写进覆盖率探针的目标参数，作为按仓库标定 W 的入口。
- 保持 `commit_limit` 为空时仍然表示全历史，不改变现有覆盖语义和六项历史特征的启用条件。

## Capabilities

### New Capabilities

- `probe-parameter-defaults`：把探针定下来的标签观察窗口与输入上限落成代码里的显式默认值和准入边界，并保证参数的取值来源唯一。

### Modified Capabilities

无。数据集切分比例、特征口径、模型与接口契约都保持不变。

## Impact

- 受影响的本目录文档：`docs/03-数据与算法规格.md` 的观察窗口定义、`docs/04-API与数据库规格.md` 的解析请求边界、`docs/05-测试与验收计划.md` 的 NFR-03 条目、`docs/07-需求设计测试追踪矩阵.md` 的对应行，以及 `docs/decisions/2026-10-19-探针参数决策.md` 的落地状态。
- 关联追踪：User Story US-02（解析任务的提交范围）、US-06 与 US-07（覆盖率决定历史特征能否启用）、US-08 与 US-09（时间切分与标签成熟度）、非功能需求 NFR-03（性能预算）。
- 非目标：不改变 `commit_limit` 为空表示全历史的语义，也不为全历史任务加任何截断；不在本次实现按仓库标定的自动化流程，标定仍是人工在覆盖率曲线上取点后写入策略快照；不调整特征口径、数据集比例与模型契约。
