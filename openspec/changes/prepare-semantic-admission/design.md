# Design: prepare-semantic-admission

## Context

这次改动接着冻结语义先导的负结果往下做，目标不是再训练一个模型，
而是把下一步能不能评估所需的条件整理成可以复核的材料。范围包括四件事：
为已有训练和验证样本生成上下文 v2、做一次编码资源探针、封存未标注的未来评估人口、
准备独立来源复核材料。

使用的基线是本仓库提交 6f021300e13835cdaca124e641b3344fc7d96f57，
固定的 ActiveMQ 主线提交是 13def043d6f00d7adbfa14b9b083141afc82b82a。
编码复用已经校验过的 CodeBERT（一个预训练的代码语言模型）和独立的 CPU 环境，
不新增权重，也不下载大型数据源。

上下文 v2 只消费 v1 中合格的 488 条训练样本和 172 条验证样本。
原来的 125 条测试样本既不生成新上下文，也不重新编码或评分；
读取 v1 的完整性记录和成员索引，不是为了拿测试集调参。
选择文本时只读取已经绑定的 Git 新旧文件内容并核对 SHA 和长度，
不执行仓库里的任何代码。改动落在新增模块和命令行入口上，
不修改 v1 的绑定源文件，也不改动旧编码器、旧模型和旧资格。

## Goals / Non-Goals

目标：

- 交付一套可以独立执行、可以追溯的上下文 v2，保留旧工件和旧版本，
  任何新结果都能回到源码、策略和 tokenizer（分词器）对齐。
- 在真实训练和验证样本上完成编码资源探针，说明覆盖和遗漏，
  而不是用覆盖数字代替模型效用。
- 封存一批未标注、未评分的未来候选身份，给后续评估留下未暴露的人口。
- 准备可证伪的准入报告和独立复核材料，把还缺的证据逐项写清楚。

非目标：

- 不训练新的分类器，不报告旧测试集上的新效果，也不把工程完成说成模型收益。
- 不建立 gold（人工金标准），不做概率盲抽样的噪声率估计。
- 不交付语义产品任务、产品接口（API）或页面，不改变产品资格，也不做候选发布。
- 不重写 v1 的冻结工件，不修改旧编码器，不修改旧模型和旧资格。
- 如果以后要做 gold 或噪声率，需要另行锁定概率抽样与覆盖、双人判定和一致性、
  仲裁、未知保留以及工作量，本批不涉及。

## Decisions

### 决策 1：只按 Git 的物理行切分，所有输入都来自真实提交内容

Git 在计算差异时只按换行字节 LF 切分物理行，因此 CRLF 里的 CR（回车）字节会原样保留。
CRLF 是 Windows 常见的「回车加换行」两个字节。Unicode 的 U+2028 行分隔符、
单独的 CR 以及换页符（form-feed）都不会被 Git 当作新行。
这一条必须和 Git 自身保持一致，否则行号会和真实差异错位。

上下文只从真实的父提交和当前提交文本中选择。读取已经绑定的 Git 旧文件和新文件内容
（也就是 Git 对象里保存的文件内容，blob）时，先核对 SHA（提交哈希）和长度，
再按原始换行计算精确的新增和删除片段。
不执行仓库里的任何代码，也不联网取新数据。v1 的绑定源文件保持不变，
所有新增逻辑放在独立模块和命令行入口里。

### 决策 2：上下文按半径 3 行选择，在固定 token 预算内装入整行

hunk（代码片段）是 Git 差异里连续的一段改动，包含旧文件和新文件中相互对应的行范围。
token 是 tokenizer（分词器）实际读入的文本单位，一个 token 不一定等于一个字符或一个单词；
这里限制的是 CodeBERT 实际能读到的内容 token 数。

上下文半径固定为 3 行，也就是在改动位置附近取半径 3 行范围内的原始行。
每个角色最多 252 个实际 CodeBERT 内容 token。四个取文本的角色分别是提交消息（message）、
新增行（added）、删除行（deleted）和变更前上下文（base）。
提交消息保持原文；新增行和删除行只从真实变更行里选；
变更前上下文从改动的旧侧以及插入锚点附近选择。

选择时先在各个改动片段之间轮流取行，再按离改动位置的距离排序，
只要整行放得下就贪心加入，放不下就跳过，不把一行拆开。
最后按原文件顺序和行号排序后拼接。整个过程最多考虑 256 个候选改动片段，
每个片段最多 32 个候选行，每个角色最多做 512 次预算检查。
超出上限或长行放不进预算时，明确登记为遗漏，不补造占位内容。

### 决策 3：每个选择结果都要可追溯，遗漏单独登记

每个角色都要登记行号、旧文件和新文件的 blob、改动片段、选中的行，
以及全文 token 数、候选 token 数和选中 token 数，还要记录改动片段的代表率。
代表率回答的是「这个片段有没有被选中至少一行」，不是「整个片段是否完整」。

因此，变更前上下文的代表率只表示至少选中了一个候选上下文行，
不保证覆盖变更行或完整改动片段。选中的上下文没有被截断，
只能说明所选文本被完整编码，不能说明整个提交或全部变更都被覆盖。
如果新上下文在训练和验证分区之间出现摘要完全相同的重复，要另外审计。

### 决策 4：编码复用 v1，但用新的 manifest 形成独立缓存

编码复用 v1 没有改动的窗口和池化代码。池化是把多段 token 向量合成一个表示的过程。
输入 manifest（清单）记录这次运行使用的输入文件、选择策略、源码版本和 tokenizer 版本，
它把新策略和新源码绑定到一起，因此生成的缓存与 v1 缓存不同，恢复和审计也能按清单对齐。

编码使用 4 个 CPU 线程、每批 8 条，并沿用已有的 45 分钟时限、
6 GiB 常驻内存（RSS）和 2.5 GiB 实际输出磁盘上限。
token 预算的实际调用允许使用等价的最近最少使用（LRU）缓存，
最多保存 4096 项，单项字符串不超过 4096 个字符；
不缓存巨大的全文，也不改变选择顺序或预算结果。

这一步只做工程覆盖和资源探针，不训练新分类器，不报告旧测试集上的新效果，
也不拿覆盖数字替代效用。校准支持审计只汇总训练和验证样本以及已有的时间组，
不重新切分旧分区。

### 决策 5：未来评估人口只封存身份和时钟

从同一个固定的 Git HEAD（分支最新提交）出发，遍历主线可达的提交记录，
取提交者时间落在 2025-01-01 至 2025-06-30（UTC）之间的记录，
排除全部原 106674 个规范化成员加 SHA 的成员，再按 SHA 从小到大取至多 64 个。
每个候选都要验证原始提交哈希、作者时间和提交时间这两个时钟，以及是否只有一个父提交。

封存时只保存身份和时钟，不读取候选的代码 blob，不生成标签，也不评分。
公开源里已经存在的 Git 对象，不代表模型在预训练时见过这些提交；
这些身份仍要验证预训练污染和近重复、许可、成熟度与删失、标签以及两类支持，
才能算可用的留出集（holdout）。如果窗口里没有合格候选，就明确失败，
不能用旧测试集替代。

### 决策 6：独立复核只交付材料，不代替审阅者下结论

复核材料针对两条尚未解决的来源规则假设，绑定已有的原生证据和修订摘要，
提供两份空白独立审阅表和一份仲裁协议。原生证据指直接从 Git 祖先关系和时钟得到的证据。

这份材料不是概率盲抽样得到的噪声率估计，也不是 gold 建立。
来源假设里的 bug 与 fix 关系天然可见，材料只对模型预测和评估结果隐藏。
用户可以安排两位独立审阅者，每人约 30 至 60 分钟；本批只交付材料，
不伪造人工结论，也不修改旧状态。

### 决策 7：准入报告逐项可证伪

准入报告分别列出上下文完整性、校准支持、未来留出集未标注、许可元数据、
预训练污染、人工复核、NFR05（原始工件逐字节确定性要求）和产品任务未交付状态。
所有条件都要能证伪，只有拿到证据才关闭。

官方仓库采用 MIT 许可，而固定模型卡没有声明权重许可，这两件事分别登记。
新补充来源的观察时间不会回填到旧的记录里。没有明确证据时继续不批准分发，
也不把「搜索不到」当成「不存在许可」。完整产品 P1 和候选发布标记
（candidate_release）保持 false。

### 决策 8：失败恢复以退出后的检查为准

原生 Git 读取要在进程退出并且文件句柄关闭之后，再检查截止时间、
标准输出和标准错误的上限，确认通过后才读取结果。
退出前的检查不能替代退出后的检查。
分别针对标准输出和标准错误在退出瞬间突发输出的两个独立反例，先复现失败，再修复到通过。

修复前已经登记了三条独立的失败反例，旧 v1 冻结工件不重写。
修复后用新源码重新生成最终的上下文、预留结果和缓存，
同时保留先前已经生成的版本和失败日志，不能只更新 manifest 来冒充重新执行。

### 决策 9：容量不足先停止，不占用 C 盘

基线提交是 6f021300e13835cdaca124e641b3344fc7d96f57，D 盘当时约有 64.71 GiB 可用空间。
预计输入与编码需要 2 GiB、备份需要 3 GiB、验收峰值需要 4 GiB。
D 盘空间不足时先停止并报告，不转到 C 盘。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 只按 LF 切分并保留 CRLF 字节 | 这和编辑器看到的分行不完全一样，U+2028、单独的 CR 和换页符都不算换行；好处是行号与 Git 自身一致，代价是后续解析不能再做额外的行拆分。 |
| 半径 3 行加 252 token 的固定预算 | 选择结果可复现、可比较，但长行或预算不足时只能登记遗漏，无法保证覆盖所有改动。 |
| 旧测试集完全不参与新上下文和评分 | 避免用已经暴露的样本挑选方案，代价是这一批拿不到任何新的测试效果数字。 |
| 未来候选只封存身份，不读取代码 | 避免标签和预测泄漏，但这 64 个身份还远不能直接当作可用留出集，预训练污染、许可、成熟度和两类支持仍要另验。 |
| 独立复核只交付空白材料 | 不伪造人工结论，代价是本批结束时独立审阅仍是零完成，来源假设无法在本批取得独立认证。 |
| 每角色最多 512 次预算检查、最多 256 个改动片段 | 防止组合爆炸和资源失控，代价是极端提交会被明确截断为遗漏。 |
| 编码沿用 45 分钟、6 GiB 常驻内存和 2.5 GiB 输出上限 | 资源可控、失败可恢复，但更大的仓库无法在这一次探针里跑完。 |
| 退出后才检查输出上限 | 能捕获退出瞬间的突发输出，但检查更晚，进程退出前仍可能短暂占用更多内存和磁盘。 |
| 许可缺证时继续不批准分发 | 避免在授权不明时外发，代价是即使工程完成，产品资格和候选发布仍停留在 false。 |

## Validation

- 用独立的 Git 夹具验证 LF、CRLF、U+2028、单独的 CR 和换页符的行边界，
  以及新增、删除和上下文选择的精确行号。
- 用真实训练和验证样本跑上下文 v2，核对每个角色的选中 token、候选 token、全文 token、
  改动片段代表率、遗漏清单和跨分区精确重复。
- 用未改动的 v1 编码代码和新的 manifest 生成缓存，验证缓存与旧缓存不同，恢复后结果一致。
- 验证退出后的输出检查：让标准输出和标准错误在进程退出瞬间突发，确认检查通过后才读取结果；
  保留修复前失败和修复后通过的日志。
- 验证未来候选封存：在同一固定提交上检查时间窗口、单父、两个时钟、
  106674 个成员的排除和最多 64 个上限；没有候选时明确失败。
- 验证独立复核材料：两份空白表、仲裁协议和修订摘要齐全，
  旧 unresolved 状态和取得时间不被改写。
- 验证准入报告：每个条件都有证据字段和完成条件，
  candidate_release 与完整产品 P1 保持 false。
- 验证资源与恢复：D 盘不足时提前停止且不写 C 盘，备份可以隔离恢复，
  活动任务为零时停止服务并保留业务卷。
- 运行 OpenSpec 严格校验。
