# Change: prepare-semantic-admission

## Why

上一轮冻结的语义先导给出了负结果，也暴露出效度上的限制：只靠已有实验，
无法判断上下文覆盖、编码资源和评估人口是否足以支撑下一步。
现在需要一组可以独立执行、可以追溯的准备工作，把这些问题固定成可证伪的证据，
避免继续在旧结论上叠加假设。

如果不做这一步，后续的语义评估会继续缺少确定的输入、明确的资源边界和未暴露的评估人口；
旧测试集也会被反复用来挑选方案，结论无法复核。

## What Changes

- 为 v1 中合格的 488 条训练样本和 172 条验证样本生成可追溯的变更上下文 v2，
  从真实 Git 新旧文件内容计算改动片段，在固定的整行 token 预算内选择上下文，
  并登记所有遗漏，合计形成 660 条训练与验证上下文。
- 复用未改动的 v1 编码代码，对上下文 v2 做一次编码资源和覆盖探针，
  产出新的缓存和审计材料，不训练新的分类器。
- 从同一个固定 Git 提交的历史中封存最多 64 个原数据集之外的未来候选身份，
  只保存身份和时间，不读取候选代码、不生成标签、不评分。
- 为两条尚未解决的来源规则假设准备独立复核材料，包括两份空白审阅表和一份仲裁协议，
  由用户安排两位独立审阅者填写。
- 输出机器可读的准入报告，逐项列出上下文完整性、校准支持、未来留出集未标注、
  许可元数据、预训练污染、人工复核、NFR05（原始工件逐字节确定性要求）和产品任务状态。
- 新增独立模块和命令行入口，不改动 v1 的绑定源文件，也不修改旧编码器、旧模型和旧资格。

## Capabilities

### New Capabilities

- `semantic-admission`：可追溯的变更上下文生成、编码资源探针、未来评估人口封存与独立来源复核材料。

### Modified Capabilities

没有。这次只新增离线研究工件和准入材料，不改变任何已经验收过的能力行为。

## Impact

**数据库**

本次改动没有数据库迁移，也不改变已有表结构。上下文 v2、编码缓存、未来候选身份和准入报告
都以不可变文件工件和清单记录，旧工件的绑定关系保持不动。

**后端**

新增独立的语义准入模块和命令行入口，负责上下文生成、编码探针、未来候选封存和准入报告。
它复用 v1 的编码窗口和池化代码，但不修改 v1 的绑定源文件，也不接入产品接口（API）或页面。

**存储与资源**

基线提交是 6f021300e13835cdaca124e641b3344fc7d96f57，D 盘当时约有 64.71 GiB 可用空间。
预计输入与编码需要 2 GiB、备份需要 3 GiB、验收峰值需要 4 GiB；空间不足时先停止，不转到 C 盘。
编码使用 4 个 CPU 线程、每批 8 条，并沿用 45 分钟、常驻内存 6 GiB、
实际输出磁盘 2.5 GiB 的监督上限。

**不在本次范围内**

本批不交付语义产品任务、产品接口（API）或页面，不产出 gold（人工金标准）、模型收益结论或候选发布。
也不训练新的分类器、不报告旧测试集上的新效果、不下载新权重或大型数据源。
校准与阈值各至少 10 个正例只是工程下限，统计充分性仍需另行论证；
独立审阅结论由用户安排的审阅者给出，本批不伪造人工结论。
