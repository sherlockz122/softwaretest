# Change: add-semantic-pilot

## Why

项目已经验收了逻辑回归（Logistic Regression，LR）和随机森林（Random Forest，RF）两条数值模型研究链，但还没有用提交文本回答语义信息能否带来增益。如果继续停留在数值特征上，后续关于语义模型能否进入产品的判断就没有真实数据可依，研究结论也容易停在架构可扩展这一层。

直接引入预训练模型又会带来新的偏差：文本可能取不到，截断可能被忽略，预训练语料可能已经见过目标仓库，测试集又小到无法支撑显著性结论。如果不先把输入、编码、缓存和对照合同固定下来，任何语义模型更好的结论都不可信。

## What Changes

- 从固定发布的数据集中提取真实提交消息、新增行、删除行和父版本文件，形成不可变、可审计的输入。
- 引入冻结的 CodeBERT（面向代码的预训练语言模型）编码器，在独立的 CPU 环境中按文本角色生成向量和缓存。
- 在同一合格人口和原分区上比较数值模型、纯语义模型和数值加语义模型，并预先固定种子、阈值和收益门槛。
- 为来源、训练输入、编码器缓存和模型建立分层清单，拒绝摘要不符或损坏的工件。
- 以独立的本机研究命令行完成全流程，不向现有 API、Worker 镜像和数据库增加语义发布能力。

## Capabilities

### New Capabilities

- `semantic-research`：从真实提交文本出发的冻结语义编码，以及数值、语义和融合模型的公平对照研究。

### Modified Capabilities

没有。

## Impact

**数据库**

这次改动不新增数据库表，也不写入产品数据库。研究输入、缓存、模型和报告都以本机不可变工件的形式保存在 `runtime` 下的专用目录中。

**后端**

不新增或修改产品接口，也不改动 Worker 的部署镜像。研究流程通过独立的本机命令行工具运行，复用已有的数据集版本、模型工件和研究用途隔离合同。

**存储与资源**

编码阶段固定使用 CPU 四线程和批大小 8。每个重阶段由父进程监督，子进程常驻内存上限为 6 GiB，实际输出盘保留 2.5 GiB 停止线；失败时保留证据，不发布半成品。权重、原始文本和模型副本不提交到仓库。

**不在本次范围内**

完整 P1、目标域发布评估和全规模能力都不在这次范围内；把语义模型接入产品 API、页面、Worker 或候选发布，也不在这次范围内。历史、类型和语言资格不会因为这次研究自动晋升。
