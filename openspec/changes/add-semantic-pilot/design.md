# Design: add-semantic-pilot

## Context

项目已经验收了逻辑回归（Logistic Regression，LR）和随机森林（Random Forest，RF）两条数值模型研究链，数据集发布、模型运行登记和研究用途隔离都有现成合同。这次改动不重复实现这些能力，只在同一套数据分区和评估口径上增加真实提交文本与冻结语义编码，回答语义信息能否带来稳定增益这个研究问题。

研究固定在已经发布的数据集 037a87d0-609e-4822-b2b4-78a49fe73e55 的三个分区上，不重算旧规则，也不改动标签。先导仓库选 apache/activemq；训练集按提交哈希（SHA）取 512 条，验证集 179 条和测试集 138 条全部保留。样本选择不看标签和模型结果；实际文本拿不到时明确拒绝，并报告缺失的人口。

输入只接受完整的单父 Git 对象、纯 UTF-8 文本，以及有界的文件、补丁（patch）和父版本文件（base）。Java 文件以及配置、其它文本都要逐文件记录语言线索，不能确认的记为未知，不冒充已经认证的语言。每个对象保留原始摘要、作者时钟、首次取得时间和许可证信息；修复提交（fix）和未来提交不进入输入。

这次改动以独立的本机研究工具运行，不改产品 API、页面、Worker 镜像或数据库。既有的数据集版本、模型工件和研究用途隔离合同直接复用；完整 P1、目标域发布和全规模能力不在本次范围内。

## Goals / Non-Goals

**Goals:**

- 从固定发布的数据集里提取真实预测侧文本，形成不可变、带来源和覆盖审计的输入。
- 用冻结的 CodeBERT（面向代码的预训练语言模型）编码器把四类文本角色编码成向量，并缓存可复现的结果。
- 在同一合格人口和原分区上，比较数值模型、纯语义模型以及数值加语义模型的表现。
- 把来源、训练输入、编码器缓存和模型分层登记，保留取消、超限和摘要不符等失败证据。

**Non-Goals:**

- 不把语义模型接进产品 API、页面、Worker 镜像或数据库，也不晋升产品、历史、类型或语言资格。
- 不做完整 P1、目标域发布和全规模能力。
- 不重算旧数据集规则，不改动旧标签和已经标记为 false 的结论。
- 不把这次研究当成泛化能力或产品效用的证明，也不依据测试表现更换算法或人口。

## Decisions

### 决策 1：先固定来源和合格人口，再谈模型效果

这次研究只使用已发布数据集 037a87d0-609e-4822-b2b4-78a49fe73e55 的三个分区，先导仓库固定为 apache/activemq。训练集按提交哈希取 512 条，验证集 179 条和测试集 138 条全部保留，不重新划分，也不修补旧标签。

选择样本时只看来源和文本是否可验证，不看标签，也不看任何模型结果。实际文本取不到、摘要对不上、对象不是单父提交、文本不是纯 UTF-8，或者文件、补丁和父版本文件超出上限时，明确拒绝该条输入，并报告缺失的人口。

这样做的理由是：只有所有对照使用同一批合格样本和同一套原分区，语义模型与数值模型的差异才能归因于输入和算法，而不是人群变化。代价是合格样本会减少，缺失原因必须如实暴露。

### 决策 2：用不可变的输入结构记录四类文本角色

新的输入结构（schema）把每条提交拆成消息（message）、新增行（added）、删除行（deleted）和父版本文件（base）四类角色，逐文件记录语言线索、空角色、来源和完整性。每个角色最多保留 128 个词元（token），并取至多两个均匀分布的首尾窗口；总词元数、被覆盖的词元数和截断情况都要保留，不能用一个窗口假装代表完整提交。

编码时，每个角色先去特殊词元后做注意力掩码均值，再按被覆盖的词元数加权窗口均值；四个角色向量与存在掩码拼接，空角色用零向量。所有缓存键都绑定输入、来源文件、权重文件、分词器文件、策略、代码、依赖、CPU 线程数和批大小；摘要不符或输入变化时不得复用旧缓存。

这样做的理由是：提交文本长度差异很大，固定截断会系统性丢掉信息；把覆盖率和截断显式记录，才能区分模型没学到和输入没给够。代价是缓存键更复杂，任何依赖变化都会让旧缓存失效。

### 决策 3：冻结编码器，权重读取和运行环境都按安全边界处理

编码器固定为 CodeBERT 的官方检查点，权重和分词器摘要写入合同。取得权重后先核对大文件存储（LFS）的 SHA256，再在隔离的受监督子进程里用只读张量方式读取，确认张量类型、形状、有限值和键都符合预期，然后转换成 safetensors 格式并逐张量精确比较。safetensors 是一种只保存张量、不执行任意代码的权重格式。

运行阶段只读取本地 safetensors，不启用远程代码（remote-code），不自动联网，也不做微调。遇到未知序列化类型、缺少额外权重或摘要不符时直接拒绝，不能把能加载当成可信。

许可方面有一个明确限制：官方代码仓库采用 MIT 许可证，但本次使用的模型卡没有许可证元数据。因此这一轮只允许本机研究，不能据此打包分发权重或衍生物，也不能进入候选发布。在取得权重适用许可的权威证据，或者换用许可明确的固定检查点之前，这些限制都有效。

### 决策 4：把重型依赖放进独立 CPU 环境，并由父进程限制资源

编码和研究依赖放在 tools/semantic 的独立环境和锁文件里，应用根依赖不变，产品 API 和 Worker 镜像也不安装 Torch。运行固定为 CPU、四线程、批大小 8。

每个重阶段都由父进程监督：取消、期限、常驻内存和实际输出盘余量任一失守，就终止未完成的子进程。子进程常驻内存上限为 6 GiB，实际输出盘保留 2.5 GiB 停止线。失败时保留证据，不发布半成品。

这样做的理由是：语义编码是离线研究，不应该把重型依赖带进产品部署；资源上限能防止一次实验拖垮本机或写满磁盘。代价是吞吐有限，大规模编码需要另做容量设计。

### 决策 5：在同一合格人口上做预声明的公平对照

对照固定为四组：数值逻辑回归、数值随机森林、冻结语义逻辑回归，以及数值加语义的逻辑回归。所有组使用同一批合格样本和原分区。逻辑回归只在训练集上拟合标准化；随机森林使用原值，不做降维、重采样或测试集驱动的参数搜索。

验证集按同一时间组的前后半划分，前半用于校准，后半用于选择 F1 阈值；测试集只做最终评价。固定种子 42 和 17，并额外重复一次 42，用来核对数值状态和概率是否复现。

报告要覆盖 PR-AUC（即平均精度 AP）、马修斯相关系数（Matthews correlation coefficient，MCC）、F1、布里尔分数（Brier score）、可靠性、成本感知指标 effort 和时间块区间，并给出两类支持数，以及按语言线索、时间、缺失和重复摘要的分组结果。交换新增和删除角色、屏蔽消息只作为预先声明的诊断，不能据此选择模型或改变输入。

这样做的理由是：只有把拟合、校准、选阈值和终评严格分开，语义与数值的差异才有解释力。代价是测试集正例很少，区间会很宽，结论必须保守。

### 决策 6：收益门槛在读取新测试预测之前固定

主展示固定使用种子 42，种子 17 作为预先声明的稳定性复验。研究收益门槛必须在读取新的测试预测之前确定：融合模型相对数值逻辑回归的平均精度绝对增量至少 0.02，同时马修斯相关系数和 20% 成本内修复比例（PofB20）不下降、布里尔分数不上升，两个种子都必须满足。

只要任一条不满足，就只报告负结果或不确定结果，不依据测试表现更换算法、人口或阈值。测试集正例很少，即使数值门槛达到，也不构成统计显著性、目标域效用或候选发布的证明。

这样做的理由是：门槛如果看完测试再定，就等于用测试集选模型。代价是可能得到没有收益的结论，但这是研究要回答的问题，不应该被结果好看与否左右。

### 决策 7：工件分层登记，失败不覆盖旧版本

来源和训练输入、编码器缓存、模型三层各自维护独立清单。每层先校验文件和成员索引，再以原子目录登记；损坏的工件拒绝加载，失败的运行不覆盖旧版本，首次失败原样保留。

这样做的理由是：研究结论依赖可追溯的输入和权重，任何一层被悄悄替换，复现就会失效。代价是磁盘上会保留多份失败和旧版本证据，需要按存储预算管理。

旧数据集和特征运行里已经标记为 false 的结论、83 条仍待处理的来源记录、2 条未解决的记录，以及 NFR05 对原始容器字节确定性的要求，都保持原状，不通过这次研究改写；它们的验收安排另行处理。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 测试集正例极少 | 即使达到数值门槛，也不能证明显著性、目标域效用或可发布；结论只能按负结果或不确定结果处理。 |
| 预训练可能污染 | CodeBERT 可能在预训练阶段见过目标仓库，只能通过预先声明的诊断和重复摘要加以限制，不能声称干净泛化。 |
| 文本覆盖有限 | 每个角色最多 128 个词元、两个窗口，无法代表完整提交；覆盖率和截断必须显式报告。 |
| 权重许可证据不足 | 官方代码仓库采用 MIT 许可证，但模型卡没有许可证元数据，本轮只能本机研究，不能打包分发或候选发布。 |
| 独立 CPU 环境吞吐有限 | 四线程、批大小 8 换来资源可控和产品镜像隔离，大规模编码需要另做容量设计。 |
| 失败和旧版本占用磁盘 | 保留首次失败与旧工件提高可追溯性，代价是占用存储并需要按预算清理。 |
| 冻结语义模型可能不如数值基线 | 融合必须同时满足平均精度、马修斯相关系数和布里尔分数门槛，任一不符就如实报告负结果。 |
| 语言线索不是认证 | 按扩展名记录的线索只能用于分组报告，不能当成真实语言标注。 |

## Validation

- 用固定仓库和官方权重跑通取源、文本提取、权重转换、编码和研究的完整链路，首次失败原样保留。
- 在独立 CPU 环境中执行编码用例，验证角色窗口、注意力掩码、池化、安全权重格式和缓存读回。
- 构造摘要不符、工件损坏、未知序列化类型、取消、超限和容量不足等情形，确认不会发布半成品。
- 在同一合格人口上重复种子 42 和 17，并重复一次 42，核对数值状态摘要和逐条概率是否精确一致。
- 在独立新卷上复核泄漏、锁、安全、规格、合同、存储和旧材料守卫，正常卷保持停服且不被清理。
- 用真实探针记录资源峰值和失败路径，不用测试数量或通过数量代替模型效用判断。
