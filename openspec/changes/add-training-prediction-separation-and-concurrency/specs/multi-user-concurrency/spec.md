# Capability: multi-user-concurrency

## ADDED Requirements

### Requirement: 并发幂等去重

同一幂等键的并发重复请求 MUST 只产生一个任务：幂等登记与任务创建在同一事务中完成，其余请求返回同一个任务标识。不同幂等键的并发请求互不影响。

#### Scenario: 同键并发提交只产生一个任务

- **WHEN** 同一用户以相同幂等键并发提交两次构建/训练请求
- **THEN** 只创建一个任务，两个请求返回同一任务 id，不出现重复执行

### Requirement: 并发任务按租约串行消费与恢复

worker SHALL 按任务租约一次只执行一个任务实例；执行中崩溃（租约过期）SHALL 由 reconcile 产生重试任务恢复执行，最终状态与一次成功执行一致。租约内执行与状态更新 MUST 以数据库事务封装，不留下半成品状态。

#### Scenario: 执行中崩溃后恢复

- **WHEN** 任务执行中途进程崩溃（租约过期）
- **THEN** reconcile 生成重试任务，继续执行至成功，数据集/模型状态与一次完成一致

### Requirement: 多用户资源隔离

不同用户并发创建数据集、训练模型 MUST 互不干扰，产物各归其主；用户对他人资源的操作（取消任务、查看管理接口、修改配置）SHALL 返回 403。所有权校验 MUST 在并发下依然成立。

#### Scenario: 两用户并发训练各归各主

- **WHEN** 两个用户同时发起训练
- **THEN** 两个模型运行独立完成，产物、报告与归属各自正确，互不覆盖

#### Scenario: 跨用户操作被拒绝

- **WHEN** 用户 A 尝试取消或操作用户 B 的任务/模型
- **THEN** 返回 403，任务状态不变

### Requirement: 队列排队语义

多个构建/训练任务并发提交时 SHALL 按队列顺序消费，任务状态转移（排队→执行→成功/失败）合法且可查询；任务互不覆盖状态。单 worker 的并发上限与扩展路径（增加 worker 进程数）SHALL 写入文档。

#### Scenario: 连续提交按序执行

- **WHEN** 连续提交多个任务
- **THEN** 队列按序消费，每个任务状态转移合法、结果正确，文档写明并发上限与扩展路径
