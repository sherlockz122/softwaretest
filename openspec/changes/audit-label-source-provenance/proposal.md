# Change: audit-label-source-provenance

## Why

公开 CSV 里的 buggy/clean 标签不能直接证明产品标签资格。AMQ 项目已经暴露出发布修复并不是原始最早链接，其它项目又尚未完成认证，clean 的筛选依据和观察覆盖也缺少独立证据。如果继续直接采信发布标签，下游的 SZZ 标注和训练数据就会建立在一个无法追溯的来源上。

## What Changes

- 固定 ApacheJIT 原始的十四个项目链接和两个筛选 notebook，逐项验证字节大小、Git blob（文件对象）和 SHA256，并记录实际取得时点。整个过程只读，不执行上游代码。
- 独立审计跨项目的发布标签与原始链接，核对时钟、候选重叠、修复选择和原始异常，把差异保留为可复核的证据。
- 输出确定性的分层复核清单，并逐项列出尚未满足的资格条件。事件时间不能代替知识时间，银标也不会被自动升级成金标。
- 保留既有特征、标签合同和规模限制，本批不接入 A17～A19，也不训练模型。来源审计和在线数据集按规划拆成不同批次。

## Capabilities

### New Capabilities

- `label-source-provenance`：固定上游来源、跨项目比较发布标签与原始链接，并发布有界、不可变的审计证据。

### Modified Capabilities

没有。

## Impact

**数据库**

本次变更不新增或修改数据库表、迁移或索引，也不改变任何持久化契约。

**后端**

新增离线来源目录、取得和审计模块，以及相应的脚本、合同测试和指导。没有新增或修改 API，也没有引入新依赖，生产资格判定保持不变。

**存储与资源**

原始材料、取得清单和审计产物只存放在项目的运行目录（runtime），所有可控新增数据都落在 D 盘。审计总输入限制为 100 MiB、合计 500000 行和 120 秒合作式时限，取得清单另有 64 KiB 上限。路径中出现符号链接、目录联接（junction）或其它重解析点时一律拒绝，磁盘不足时停止而不转向 C 盘。

**不在本次范围内**

在线 A17～A19 数据集、模型训练和产品来源认证不在本批。完整单头受控来源核验、筛选重现、完整负例覆盖、金标人工复核和十四维兼容也要另行验收，本批的 AMQ 有限样本不能用来认证全项目的完整负例。
