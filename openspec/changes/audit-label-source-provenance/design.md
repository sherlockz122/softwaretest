# Design: audit-label-source-provenance

## Context

这次改动要回答的是：公开 CSV 里已经发布的 buggy/clean 标签，能不能在来源层面站得住。上游固定到 ApacheJIT 修订 `ddfd547ff8e3d3725f6a1fd0f177c0ebe085a4b5`，包含十四个项目的原始链接和两个筛选 notebook。目录表会保留项目分组（project cohort）与 Git 仓库之间的区别：HDFS 和 MAPREDUCE 的原始仓库都是 apache/hadoop，统计时不合并；额外的 hadoop 发布组没有对应的原始链接，必须明确记为缺证。

这次只做离线审计，复用项目已有的运行目录、脚本入口和合同测试方式，不新增 API、数据库迁移或运行依赖，也不重复实现已有的标签、特征和任务能力。上游代码只读，任何情况下都不执行。真实数据方面，已有的 AMQ 有限 Git 样本只用于只读核对当前能看到的时钟和浅历史边界，不作为全项目完整负例的认证依据。

## Goals / Non-Goals

**Goals:**

- 固定十四个项目的原始链接和筛选来源，用字节大小、Git blob 和 SHA256 证明输入身份，并记录实际取得时点。
- 独立比较发布标签与原始链接，诊断时钟、候选重叠、修复选择和原始异常，输出确定性的分层复核清单。
- 让审计产物有界、可复现、不可覆盖，失败时保留已有证据。
- 逐项记录尚未满足的资格条件，不把研究阶段的比较结果说成产品就绪。

**Non-Goals:**

- 不接入在线 A17～A19 数据集，不训练模型，也不改变产品来源资格。
- 不执行上游代码，不安装上游的 GumTree、Java 或 notebook 依赖。
- 不自动把银标升级成金标，也不用事件时间回填历史知识时间。
- 不用 AMQ 的有限 Git 样本认证全项目的完整负例。完整单头受控来源、抽检、筛选重现和兼容数据集另行验收。

## Decisions

### 决策 1：固定修订与不可变取得清单

上游来源固定到修订 `ddfd547ff8e3d3725f6a1fd0f177c0ebe085a4b5`，十四个项目链接和两个筛选 notebook 逐项校验精确字节大小、Git blob 和 SHA256。取得清单记录带时区的实际取得时间，并限制在 64 KiB 以内。清单完成之后就可以复用，但复用不会重写首次取得时间；损坏的输入会被拒绝，而不是静默重新下载。取得失败时只清除本次的临时文件，已经验证过的源仍然保留。

目录表把项目分组和 Git 仓库映射分开记录。HDFS 和 MAPREDUCE 的真实仓库相同，但不合并统计；hadoop 额外的发布组没有原始链接，明确标为缺证。这样做的目的是让覆盖缺口保持可见，而不是用合并统计把它掩盖掉。

### 决策 2：下载与路径的安全边界

下载器只允许访问固定的 HTTPS raw URL，重定向也只能落在允许的主机范围内。所有材料只存放在项目的运行目录（runtime），路径中出现符号链接、目录联接（junction）或其它重解析点时拒绝读写。审计输出不暴露源码、作者身份或运行配置。上游代码只做静态读取，永远不执行；这样即使原始材料本身带有可执行内容，也不会进入本机的执行链。

### 决策 3：有界审计与输入漂移防护

审计总输入上限为 100 MiB、合计 500000 行和 120 秒合作式时限。内核按字节数和行数逐项监督，并在输入开始和结束时各计算一次哈希；前后哈希不一致就判定输入发生了漂移，拒绝发布。发布表的结构不符合约定、发布键重复或单行结构畸形时也会被拒绝。取消信号会向读取和逐行循环传递，达到时限或资源上限就停止，不留下半份报告。

### 决策 4：异常只诊断，不擅自修正

原始链接重复、时钟倒置，以及同一个 SHA 对上相互冲突的时钟，都作为诊断信息保留，不擅自修正。原始修复和最早链接分别统计，历史可用时间（available_at）保持为空。CSV 里的 bug_date 和 fix_date 是 ISO 文本，raw 日期是 epoch 整数，必须按固定的上游 committer UTC 口径分别解析，不能混用解析器，也不能当成知识时间。

### 决策 5：分层复核配额与资格缺口

复核包按项目分组、标签类别和链接状态分组，每组取 SHA256 排序后的前两行。这个配额是可重复复核的固定抽样，不是概率抽样，也不用来估计噪声率。每个分组保留完整成员摘要和全链接摘要，展示时最多列出八条链接，并明确标注是否截断。资格检查逐项记录完整负例覆盖、筛选重现、原生祖先关系、人工复核和十四维兼容的不足；任何一项缺失都不会被写成已经满足。

### 决策 6：不可变发布与失败恢复

审计报告返回独立副本，内容绑定来源哈希、规则哈希、实际取得时间和内容哈希。命令行入口只在审计完整跑完之后发布报告：先把完整结果写进同目录的一个临时文件，再用排他的硬链接把它变成正式文件，失败时不会留下半份最终报告。报告不得覆盖输入树或已经存在的报告；源在过程中发生变化、监督器取消任务或资源超限时，不发布任何报告，已有证据保持原样。

### 决策 7：真实样本的边界

已有的 AMQ 有限 Git 样本只做只读核对：确认当前能看到的 committer 时间与 raw 一致，并记录两头窗口的浅历史边界。它不能证明所有项目的完整负例，也不能把缺失的祖先关系推断成不存在。后续完整的单头受控来源、抽检和兼容数据集要作为独立验收处理。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 只允许固定 HTTPS raw URL | 部分上游材料无法直接取得，重定向也受限；换来的是下载链路可控、来源可追溯。 |
| 完成清单复用但不重写首次取得时间 | 复用能省去重复下载，代价是复用不会刷新证据时点，过期来源要重新取得才能更新。 |
| 复核包每组只取前两行 | 复核工作量可控、结果可重复，但它不是概率样本，不能用来估计噪声率或推断总体。 |
| 异常只做诊断、不自动修正 | 重复链接和倒置时钟会继续留在数据里，需要人工在复核阶段处理；换来的是不会静默改写原始事实。 |
| hadoop 额外发布组缺少原始链接 | 该组无法在来源层面认证，会留下明确的覆盖缺口；不能用合并统计掩盖。 |
| 100 MiB、500000 行和 120 秒上限 | 更大的输入会被拒绝，需要人工调整参数或另做设计；换来的是资源占用有界。 |
| 不自动把银标升级成金标 | 资格判定偏保守，可能低估一部分可用标签；这是为了防止研究结论越过产品资格。 |
| AMQ 有限样本只能核对所见时钟 | 浅历史下缺失对象的祖先关系仍然未知，不能据此认证全项目完整负例。 |

## Validation

- 用合同测试覆盖来源固定、精确字节大小、Git blob、SHA256、取得清单复用与篡改、安全路径和下载失败清理。
- 覆盖资源上限、期限、取消、输入漂移、结构畸形和发布键重复，确认失败时不发布报告。
- 用固定 fixture 验证候选重叠、非最早修复、缺源、时钟倒置和同 SHA 时钟冲突的诊断结果，以及复核包的确定性和截断标记。
- 跑真实全表审计，核对发布样本与原始链接的数量和匹配关系；用已有 AMQ 只读 Git 样本记录所见时钟和浅历史限制。
- 验证报告返回独立副本、内容哈希绑定来源和规则、已有报告不被覆盖。
- 按项目现有工作流跑静态检查、OpenSpec 严格校验、后端和前端回归，并在独立新卷上用真实浏览器验收。
