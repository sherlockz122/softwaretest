# Change: add-nfr03-load-evidence

## Why

验收计划把性能条目写成"固定硬件、固定数据集、热模型条件下至少 100 次有效请求，候选预测与常用列表查询的 P95 不高于 1 秒，并随结果给出分位数、吞吐、错误率、环境、数据量与模型版本"。仓库里到现在没有任何压测脚本，也没有一次真实请求的分位数。已经入库的解析与特征耗时说明的是后台任务的成本，不能拿来充当在线延迟。

缺的还有页面证据。历史风险列表这一块只有单元测试和组件测试，没有一次真实浏览器里的走查记录；候选预测页要求测的是 `/review`，而这一页在当前代码里还不存在。

## What Changes

- 新增压测脚本，按目标接口重复发请求，把每次请求的接口、序号、耗时、状态码与是否有效逐行写成逗号分隔值（CSV）文件。
- 脚本支持串行与固定并发两组，两组各自统计，不把两组样本混进同一组分位数。
- 有效请求的判定写进脚本：状态码为 200、响应体是 JSON 且包含该接口的关键字段，并且不在预热轮次里。
- 汇总输出 P50、P95、P99、吞吐、错误率、环境、数据量与模型版本，原始记录与汇总一起入库。
- 新增浏览器实测脚本，用真实浏览器打开页面，走一遍历史风险列表的翻页与分区切换，并把截图留档。
- 候选预测页在当前代码里没有对应路由，实测记录里如实写成不可测，不用其他页面顶替。

## Capabilities

### New Capabilities

- `online-latency-evidence`：对已实现接口做可复现的在线延迟压测，按有效请求给出分位数与吞吐，并把环境、数据量与模型版本随结果一同固定下来。

### Modified Capabilities

无。接口行为、数据模型与训练链路都不变，这次改动的产出是脚本与证据。

## Impact

- 受影响的本目录文档：`docs/development/NFR-03性能证据底稿.md` 的"仍缺的证据"与压测方案两节要按实际结果改写；`docs/05-测试与验收计划.md` 的 NFR-03 条目补上证据入口；`docs/07-需求设计测试追踪矩阵.md` 的非功能验证行与 E2E 行更新状态。
- 关联用户故事：NFR-03 性能条目，以及 US-15 的模型运行工件、US-17 的风险评审链路。
- 非目标：不改任何接口实现与响应格式；不做生产容量规划；不测后台解析与训练任务的时长，那部分已有独立实测；不引入负载均衡或多机压测；候选预测接口未合入前不伪造该接口的数据。
