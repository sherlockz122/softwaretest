# Change: add-public-dataset-audit

## Why

现有生产来源合同是按本系统的实际观测和发布时间审核的。
今天去采集历史仓库，并不能自动证明「在历史训练截止那一刻，标签就已经可用」。

另一方面，我们自己手上的验收样本只有三个提交，薄得看不出公开研究数据集到底能不能用。

所以要先把公开数据和历史评估合同验证清楚，
免得一路纵向接入做下去，才发现训练来源根本没法适配。

## What Changes

- 交付固定来源的下载与完整性校验、只读的公开 CSV 审计，以及按项目的历史时间切分可行性报告。
- 明确区分三种来源和用途：实际观测、外部发布标签基准、历史回放。
  本批只交付外部发布标签基准的审计——不伪造在线观测，也不宣布历史回放已经合格。
- 核验发布时间、修复日期、特征语义、缺失与来源关系，报告阻碍和下一批切片的决策依据。
- 同步当前的指导、规划、规格、追踪矩阵与阶段报告。
  模型工程可以并行，但真实效果与发布仍然有数据门槛。
- 一并修复验收过程中发现的问题：Windows 受控 Git 长路径兼容、
  移动端既有特征结果的换行、只读存储统计。
- 不改动 `time-labels-v1` 和 `kamei14-dg-v1`。

## Capabilities

### New Capabilities

- `public-dataset-audit`：对预声明公开数据集的只读、确定性、可复现的可行性审计，
  包含固定来源与完整性校验、研究标签与生产合同的分离，以及按项目的时间切分审计。

### Modified Capabilities

没有。这次改动不改变任何已有能力的行为。

## Impact

- 新增离线审计模块、本机命令行工具和独立测试。
- 不新增依赖、数据库迁移、接口、任务类型或页面功能。
- 数据与原始作者的复现材料留在 D 盘被 Git 忽略的 `runtime/` 下；仓库只保存汇总与来源归属。
- 关联追踪：User Story US-08、US-09；测试 `test_public_dataset` 专项；
  对应数据可行性前置与 NFR 可复现要求。
