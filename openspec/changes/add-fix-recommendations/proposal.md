# Change: add-fix-recommendations

## Why

课程要求系统针对缺陷给出高质量修复建议，而当前产品对缺陷的处理止于指出问题：合入前评审只返回风险概率和影响因素，缺陷追溯只回答缺陷是哪次提交引入的，两条链路都没有回答该怎么修。评审员拿到一个高风险改动，仍然要自己翻历史找先例。系统里已经存着回答这个问题的原料——仓库自己真实发生过的修复提交、修复证据等级、行级追溯证据和十四维特征——只是没有被组织成建议。不做这次改动，课程这条硬指标就没有对应功能，产品也停在预测而不是帮助解决问题。

## What Changes

- 新增修复参考能力：针对一次提交，从同一仓库的历史修复提交中检索与它最相似的修复，按相似度降序返回，每条都说明相似理由并链接到证据。
- 在仓库详情页增加提交的修复参考面板，在候选预测结果页增加高风险改动的同类修复面板，两个入口共用同一个检索实现。
- 新增一个只读查询接口，接入现有登录校验和角色权限。
- 更新产品需求文档，新增用户故事 US-24，并同步需求设计测试追踪矩阵。

## Capabilities

### New Capabilities

- fix-recommendation：针对提交检索并展示历史同类修复参考

### Modified Capabilities

无。

## Impact

- 数据库：不新增表，从已有的提交、修复证据、缺陷追溯和特征数据实时查询，查询带扫描行数和返回条数上限。
- 后端：新增只读查询接口（接口清单编号 A37），走现有认证与权限校验，不触发任何任务或写入。
- 存储资源：无新增存储。
- 不在范围内：不生成修复代码或修复文本，不自动应用修复，不把相似修复描述为当前缺陷的根因，不接入外部模型或网络服务。
- 关联追踪：新增用户故事 US-24；受影响文档包括产品需求文档、需求设计测试追踪矩阵、API 与数据库规格、测试与验收计划、界面与交互规格和开发协作与迭代计划。
