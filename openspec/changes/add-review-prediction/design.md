# Design: add-review-prediction

## Context

这次改动的动机和范围在 proposal 里，这里只讲技术上下文。系统已经具备三块可复用的能力：异步任务基建（任务表、待投递事件、租约、心跳、同根重试和协作式取消）；十四维特征内核，其中修复标记对候选预测按 0 处理；第二十二阶段验收的 LR/RF 研究模型，工件里带校准器、判定阈值和列顺序。模型发布接口目前明确拒绝研究用途，所以预测不能依赖发布链路，只能直接引用已注册的模型运行。产品设计文档给出了 A24 的草稿契约和「超同步时限返回任务编号」的要求，界面规格定了候选预测、风险队列两个页面。

## Goals / Non-Goals

设计层面的目标：用研究模型把合入前评审链路闭合，全部能力搭在既有任务和权限机制上，不新造一套。设计层面的非目标：不实现模型发布和比较、不训练任何新模型、不引入语义输入、不为预测单独建推理服务——单次推理在毫秒级，进程内完成即可。

## Decisions

### 决策 1：新增迁移建立预测任务和预测结果两张表

预测任务表保存一次预测请求的业务上下文，预测结果表保存逐候选的结果。两张表都遵循既有的数据库惯例：标识用定长字符、状态用带检查约束的字符串、外键全部限制删除、时间为协调世界时。预测任务表包含仓库、基准点、模型运行、范围类型（单个引用、单个改动内容或批量）、范围说明、特征版本和根任务引用；任务状态不重复存储，直接复用异步任务表。预测结果表按任务和候选标识唯一，概率、阈值和风险密度用定点小数存储，解释内容用 JSON 存储——定点小数可以稳定排序，解释内容是展示级的，不需要无损精度。批量任务的写入沿用特征轮次的惯例，每批十个结果原子发布，最后一批和成功状态在同一事务里提交。迁移编号接在 0011 之后，降级前检查整条受影响路径非空即拒绝。

### 决策 2：预测资格由模型工件的内容决定，特征按工件列合同重算

预测请求直接携带模型运行标识，资格检查有三条：运行已注册且工件完整；工件声明了校准器和判定阈值；工件声明的特征列合同系统能够重算。当前研究模型的列合同是十二维数值特征，不含改动前文件总行数，特征内核算出全量后按列合同取子集，修复标记按候选的 0 策略处理。放弃的方案有两个：等产品发布链路先落地，那会让这条链路无限期阻塞；或者复刻外部基准数据集的派生口径去算候选特征，那套口径已被明确声明不替代产品口径，复刻出来也无法核验。代价是训练数据与候选特征之间存在口径差异，这个代价写进风险表，在结果和页面口径中如实披露。

### 决策 3：同步时限定为一秒，超时转任务查询

单次候选预测的同步时限定为一秒，超过就返回任务编号，由任务页查询结果，任务类型为单个预测。这样接口的响应时间与非功能需求里「九成五的请求一秒内返回」口径一致，批量预测本来就走任务，两条路径共用一套基建。放弃无限同步等待，那会违反性能需求；也放弃一律异步，小改动明明能即时返回，强制等任务页会让演示和日常使用都变慢。

### 决策 4：风险等级按判定阈值分成三档

概率不低于判定阈值记为高，不低于阈值的一半记为中，其余记为低，阈值来自模型工件的验证集。选三档是因为低保真原型和接口草稿里等级列都出现了中间档，两档表达不了「接近阈值」的中间态；放弃按队列分位数动态分档，那会让同一条结果在不同队列里等级不同，无法稳定解释。

### 决策 5：输入和批量范围声明固定上限

单个候选改动最多两百个文件、累计两万行变更；批量预测一次最多五百个候选，时间窗上限九十天，和已声明的观察窗口一致。超限在入队或计算之前拒绝并说明当前上限。放弃照搬采集侧的仓库限制，采集面向整个仓库，评审面向一次改动，尺度不同；也放弃不设限，那会让执行器的时间和内存不可控。

### 决策 6：逻辑回归用系数贡献，随机森林用树解释器

逻辑回归的逐项贡献是系数乘特征值，方向取系数符号，零额外依赖。随机森林没有系数，用 SHAP 的树解释器计算逐实例贡献，这是树模型逐实例归因的主流方法，代价是新增一个依赖，放进已有的建模依赖组，解释在预测侧按需计算，不影响模型加载。放弃自实现树路径贡献，正确性验证的成本高于接受一个成熟依赖。

### 决策 7：候选引用只解析本地引用，改动在隔离工作区处理

候选引用只允许解析已经克隆下来的仓库里的本地引用，全部是只读的 Git 操作，不发起任何网络请求，从根上避免把预测变成新的网络入口。改动内容的生成在隔离的临时工作区里进行，引用和路径只作为参数传给受控的 Git 命令，不拼接命令行；工作区禁止执行仓库脚本和钩子。放弃从远端拉取候选引用，那会重新引入地址校验和网络边界问题。

### 决策 8：队列排序沿用既有口径，超大改动按固定阈值标识

队列按概率降序、事件时间升序、提交标识升序稳定排序，和评估指标的口径一致。超大改动定义为审查成本超过五百行，独立于风险密度展示，避免一次大改动因为密度低被藏起来。放弃按风险密度排序，产品需求明确禁止这种做法。

### 决策 9：预测请求沿用幂等键和审计惯例

单个预测和批量预测都使用幂等键，同用户同键重放返回原结果或原任务，同键不同载荷返回冲突错误，与仓库采集、特征提取和模型训练的做法一致。每次预测请求和结果生成都写入操作日志，敏感内容脱敏。

## Risks / Trade-offs

| 风险/权衡 | 说明 |
|---|---|
| 训练与候选特征的口径差异 | 研究模型训练于外部基准数据集，候选特征由产品内核重算，两边的派生口径有差异，校准概率的解释力会打折扣。处理方式是在结果、页面和报告口径中如实披露，不冒称跨仓库泛化 |
| 跨项目泛化没有依据 | 模型训练数据来自一个公开 Java 项目，对其它仓库的预测只能算研究用途。这条链路闭合不等于预测效果成立，演示和报告按研究口径表述 |
| 新增树解释器依赖 | 随机森林的解释引入新依赖，体积和维护成本上升，换取逐实例归因的成熟实现 |
| 一秒同步时限可能频繁转异步 | 特征计算涉及历史查询，个别候选会超过一秒转任务。演示数据量下应当同步返回，若实测频繁超时可上调时限并同步改非功能需求口径 |
| 批量五百候选的执行器开销 | 上限以内的批量任务时间和内存可控性依赖分批写入、检查点、取消和超时机制，这些全部复用已验收的基建 |
| 概率存储用定点小数 | 换取稳定排序和无漂移，代价是字段语义比浮点严格，写入时必须在应用层完成舍入 |

## Validation

实现完成后按以下手段验收：单元测试覆盖队列排序的并列口径、风险等级三档边界、逻辑回归贡献计算和幂等重放；集成测试覆盖两种候选输入、无效引用、基准点不可达、超限拒绝、批量范围限制、检查点恢复、协作式取消和同根重试；浏览器测试覆盖预测提交前展示模型和特征版本、结果页的非因果声明、队列排序和超大改动标识；端到端测试走完整合入前评审链路；性能按非功能需求的口径在固定环境压测预测响应；安全测试验证可疑引用不触发命令执行、日志不含敏感信息。
