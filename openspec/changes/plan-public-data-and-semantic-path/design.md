# Design: plan-public-data-and-semantic-path

## Context

当前基线已经完成公开数据的来源审计：公开数据的专项保存与审计、Kamei 特征内核、成熟度内核和可靠任务复用都已经具备。之后，首条公开 CSV 资产、首条用途分离数据集和首条研究 LR/RF 由各自的子 change 交付，但数据集纵向和模型只完成了这些首条切片，真实语义工件、目标域发布和更完整的模型能力还没有实现。

这次改动只更新规划、规格与追踪、遗留问题和衔接指南，不碰业务实现。它依据 [公开数据兼容与预训练语义路线](../../../docs/decisions/2026-10-14-公开数据兼容与预训练语义路线.md)，细化的落点写在 [公开数据与语义模型衔接指南](../../../docs/development/公开数据与语义模型衔接指南.md)。

## Goals / Non-Goals

**Goals:**

- 把公开数据资产、用途能力、标签维度和语义路线写成一份统一的规划，让后续每个功能切片都能明确自己属于哪类用途、需要哪些证据。
- 明确公开原始存档、标准化派生和重新加载的处理方式，以及类型、位置和语言元数据的验收边界。
- 明确预训练语义与融合的公平比较方式、固定分词器、安全工件和资源探针要求。

**Non-Goals:**

- 不修改业务代码、原始数据、依赖、接口、数据库结构或特征运行记录，也不改写既有的 false 资格标记、已有摘要、标签和用户材料。
- 不实现任何功能；每个功能切片开始之前，都要在对应的功能改动里单独设计接口、数据库迁移、权限设计和具体场景。
- 不下载新数据或模型权重，不运行上游代码，也不训练模型。
- 不把研究用途的可用性自动升级为历史回放、目标域发布或产品训练资格。

## Decisions

### 决策 1：公开资产按不可变来源和用途能力分层

PublicAsset（公开资产模块）负责原始清单、合法来源、适配、派生和重新加载。每一层都不可变，并保留与来源的关系；原始字段和原始标签不丢弃，派生映射可以追溯。

能保存不等于能用于训练。用途能力分成原始存档、标准化导出、研究二分类、研究语义、历史回放、目标域候选发布，以及类型和定位任务；硬性不兼容的请求直接拒绝，证据不足的保持隔离或标记为未知，不要求所有来源一次补齐人工金标（人工确认的基准标签）。

版本审计按 M5 能力项的用途与版本审计要求记录资产、来源、适配器、派生、标签、特征和切分的版本；修订生成新的资产或派生数据，旧结果仍然可以重载。权限、任务和原子发布复用已有实现，旧模型和旧轮次保持不变。

### 决策 2：标签维度、粒度与语言能力彼此独立

二分类缺陷标签、缺陷类型、位置、粒度以及语言/领域证据是不同字段，不能互相推导。元数据里拟保留缺陷类型（可以多标签或为空）、类型证据和状态、位置及位置证据，并在实际标注探针之后再确定初始类型集合；M3 能力项中类型和位置保持为可选能力。

原生 14 维特征、外部 12 项数值特征、语义输入，以及函数级、模块级、文件级等粒度不能隐式混用。缺少类型时保留未知，不填入一个推断出来的类别；从二分类标签、SZZ（引入缺陷的提交追溯）行命中或模型解释都不能自动制造类型真值。

### 决策 3：语义路线采用冻结编码器和同人口公平对照

预训练语义路线先用固定预训练编码器的冻结表征加一个简单分类器，再在同一份样本上比较语义特征与专家特征的融合，最后根据证据决定要不要做有限微调，这一步对应 M4 能力项的独立语义工件，以及 M6 能力项的冻结编码器与融合插件。首个候选是 CodeBERT-base，它只是候选，不预先宣称效果最好；选定前要核验语言覆盖、许可、权重来源、预训练污染和资源占用。

语义输入使用真实的提交消息和变更文本，不能从只有数值的 CSV 反推或生成。分词器固定在声明的版本上，不在全量数据上重新学习；语义工件独立存放，输入结构单独定义，不给 14 维向量追加隐藏字段。比较时固定同一份合格人口和同一套分区，缺失文本的子集单独报告，不用较容易的子集结果代表整个数值集。

模型权重、许可、固定版本、哈希、依赖和设备都要记录。默认在本地离线推理，不把代码发到外部服务；优先审查安全格式的权重，不加载来源不明的 pickle（Python 序列化格式）、自定义远程代码或上游容器，也不照搬付费标注接口。

### 决策 4：研究工程与产品发布分开验收

研究阶段允许使用真实、今天已经取得的弱监督标签推进工程，只要声明版本和限制；来源时钟吻合、定向复核和来源比较都不等于完整金标。历史回放和目标域候选发布则各自需要独立证据：历史特征和标签在训练时点已经可用，观察与删失有依据；目标域要证明输入版本、语言、校准、评审效用和资源都兼容。

现有 false 资格标记不回写，新增审计引用只能生成新版本。切片按有限纵向推进：来源复核记录和首条公共 CSV 资产、首条用途分离数据集、首条研究 LR/RF 依次交付，语义和发布在后续批次再做；不要求一次把所有来源都变成金标。每一批都单独设计、测试、迁移和恢复，旧输入、已有摘要、标签和用户材料保持不变。

### 决策 5：失败恢复和发布边界

公开资产先写临时位置，校验后再原子发布；成功之后目录和清单不能被静默覆盖。重复取得保留已有的取得时间，修订另生成资产。重启恢复、摘要漂移拒绝、幂等并发、任务取消和过期写回、导出后再导入以及损坏检测都属于验收项；备份恢复按清单核对原始和派生哈希，重新加载保留原时间，不能用恢复时间替代首次取得时间。

远端取得沿用现有的 SSRF（服务端请求伪造）防护、域名系统（DNS）校验、重定向拒绝和 TLS（传输层安全）校验策略，不提供服务端任意本地路径或任意程序入口。导入按字节、行、列、单字段和时限设限，失败不发布；文件名和解压穿越、链接或重解析点、zip 炸弹等问题如果后续支持压缩包，要专项拒绝。CSV 导出要防公式注入，原始字节仍然封存。

### 决策 6：资源按有界批次推进，不把预算当承诺

当前只读硬件信息显示 Intel Arc 显卡和约 32 GB 内存，还没有做训练探针；D 盘约有 77.9 GiB 可用，但这不能作为全量微调的承诺。后续按用途分别估算：公共适配和复核新增约 0.5～2 GiB，验收峰值另算 2～4 GiB；研究链约 1～4 GiB；首个预训练环境和单模型的有界嵌入约 3～8 GiB，临时峰值另算 2～6 GiB；微调可能需要 8～20 GiB 以上，必须按样本、词元数量、精度、优化器和检查点重新计算。

所有可控增长都落在 D 盘；空间不足时先停下并报告，不自动转用 C 盘。缓存按完整样本数、分块数和嵌入维度估算，只保存预先声明的代表工件，失败证据保留，不做无界实验。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 许可和来源不清 | 公开数据并不等于可以任意使用；许可范围、归属和取得时间必须随资产记录，无法确认时只能隔离或登记待核验。 |
| 噪声和删失 | 弱监督标签和观察窗口会让一部分样本的结论不稳定；因此研究和发布分开评估，不能用研究结果证明产品可用。 |
| 跨来源重叠 | 同一提交或同一内容可能出现在多个来源和版本里；必须按原行记录并防止不同分区之间泄漏。 |
| 粒度不匹配 | 函数级、模块级、文件级和提交级样本单位不同，直接混用会制造伪标签；只能按原粒度保存和报告。 |
| 没有预测侧文本 | 只有数值的来源无法生成语义输入，只能保持语义不可用，不能靠合成缺陷文本补齐。 |
| 预训练污染和捷径 | 预训练权重可能见过目标仓库，模型也可能依赖表面线索；无法排除时要在报告中声明，并用反事实和去重探针检查。 |
| 现代模型未必优于基线 | 编码器更新、参数更多不代表效果更好；如果没有达到收益门槛或资源不足，就保留基线并记录负结果。 |
| 硬件和空间不确定 | 设备只有只读信息，缺少训练探针；D 盘余量不等于显卡和时间足够，因此不承诺全量微调。 |
| 上游材料不可直接复用 | 上游的 pickle、容器和付费标注接口可能带来安全和合规风险；只审查转换后的安全工件，不直接执行。 |

## Validation

- 校验文档链接和 35 个接口编号与 OpenAPI 一致，并运行严格的 OpenSpec 校验。
- 校验改动范围只落在规划文档和这次改动的目录，修改范围检查和来源守卫都不报错。
- 后续真实资产验收：检查清单、许可、哈希、重新加载一致性和摘要漂移拒绝。
- 后续任务验收：检查真实 Worker 执行、权限、取消和恢复。
- 后续模型验收：在同一合格人口和固定分区上比较数值基线、冻结编码器、语义与专家特征融合，并报告缺失覆盖、校准、域适用性和资源占用。
- 新卷浏览器验收：在全新的存储卷上走完导入、数据集、训练和页面的纵向流程。
