# Change: plan-public-data-and-semantic-path

## Why

用户提出公开数据应当可以保存和加载，但现有的 ApacheJIT 专项审计还没有形成通用的产品资产；缺陷类型和按语言划分的验收标准也不够具体，CodeBERT（一种预训练代码理解模型）原先只排在 P2（较低的优先级），不足以支撑现代的语义路线。如果不先把公开数据的来源、许可、用途和资格边界规划清楚，研究上可用的数据就会被当成产品可以直接发布的能力，后续的数据集和模型建设也会缺少统一的判断依据。

## What Changes

- 更新当前规划、规格与追踪、遗留问题和衔接指南，把公开数据资产与数据质量列为 P0（最高优先级），把预训练语义与融合列为 P1（次高优先级）；Kamei 特征基线、LR/RF（逻辑回归与随机森林）研究基线，以及课程中的八个模型都保留。
- 明确公开原始存档、标准化派生和重新加载三类处理，以及按用途划分的能力、类型/位置/语言元数据和后续验收方式。
- 明确真实语义文本、固定权重的分词器、安全格式的模型工件、同一合格人口上的公平比较和资源探针要求。

## Capabilities

### New Capabilities

- `public-data-semantic-roadmap`：公开数据资产的不可变保存与重新加载、用途能力分层、标签维度与粒度、预训练语义和融合路线的规划约束与验收门槛。

### Modified Capabilities

没有。

## Impact

**数据库**

这次改动不新增或修改数据库结构，特征相关的迁移 `schema0008_features` 和现有的 35 个接口编号都保持不变。A17～A19 的新用途和公共导入接口要等到对应的功能改动时再单独设计迁移。

**后端**

这次改动只提交规划文档，不修改业务代码、依赖、接口或特征运行记录。后续功能开发之前，要在对应的功能改动里细化接口、数据库迁移、权限设计和具体场景。

**存储与资源**

这次改动不下载新数据或模型权重，也不运行上游代码和训练任务。后续批次会先测本机的处理器、内存、显卡和 D 盘余量，再按有界切片估算空间；空间不足时先停下并报告，不自动改用 C 盘。当前只读硬件信息显示 Intel Arc 显卡和约 32 GB 内存，还没有做训练探针，D 盘约有 77.9 GiB 可用也不等于可以承诺全量微调。

**不在本次范围内**

这次改动本身只做规划与文档同步，不实现公开数据导入、用途分离数据集、LR/RF 训练、语义工件、目标域发布和模型扩展，也不改写既有的 false（未就绪）资格标记。首条公开 CSV 资产、首条公开研究用的 12 项数值用途分离数据集和首条研究 LR/RF 已经由各自的子 change 交付；其中首条公开 CSV 资产只覆盖 ApacheJIT 的首条 CSV 和本机复核，不是通用的应用导入、RBAC（基于角色的访问控制）、数据集或模型能力。原生 14 维特征、历史回放用途、通用格式和备份恢复并没有随着这些切片完成；独立的冻结语义先导也只完成了限定范围内的先导验证，完整的产品语义 P1、目标域发布、八个模型以及类型、定位和非 Java 语言扩展仍未完成。
