# Design: add-historical-risk-list

## Context

训练进程在发布阶段已经写出 `probabilities.csv`，列为分区、仓库、提交编号、事件时间、标签、概率，随模型工件一起登记大小与摘要，并把摘要写进运行的输出清单。也就是说逐提交概率早就存在，只是没有任何接口把它读出来。

目前模型运行详情只给聚合指标与工件下载，页面看不到"哪些提交被排在前面"。E2E-01 要的历史风险列表缺的就是这一步。

## Goals / Non-Goals

**Goals:**

- 用一个只读接口把已有工件里的逐提交概率按风险排出来，分页可翻。
- 排序稳定、结果可复现，同一次运行两次请求顺序一致。
- 默认不展示样本内分数，也不泄漏真实标签。

**Non-Goals:**

- 不新建预测结果表，不写库。
- 不做候选改动预测、批量扫描与导出。
- 不重算概率，不改模型、特征与阈值口径。
- 不提供按标签筛选。

## Decisions

### 决策 1：直接读 `probabilities.csv`，不落库

概率已经在工件里，且工件有摘要与不可变发布语义。另建一张预测表等于把同一份分数存两遍，立刻要面对"工件改了表没改"的一致性问题。

代价是每次请求要解析一份 CSV。所以接口必须有界读取并在页面侧按页请求，而不是一次把全量塞进前端。

### 决策 2：默认只列验证与测试分区

训练分区的分数是样本内的，直接展示会让模型看起来比实际强。默认排除训练分区，只有调用方显式指定时才返回，并在响应里带上分区清单与阈值，让页面能说明"这不是全量样本"。

### 决策 3：不返回标签

工件里带 `label`，但风险列表不返回它。理由很直接：这是给历史评估看的列表，把真实标签摆在旁边等于把答案和预测一起展示。评测要看标签请走报告与指标，不要走这个列表。

### 决策 4：风险等级按该次运行的阈值划分

同一批概率在不同运行里阈值不同，写死一条通用阈值会让两次运行不可比。等级取该次运行报告里的阈值：不低于阈值算高，不低于阈值一半算中，其余算低。等级只是展示分档，不参与任何评估。

### 决策 5：有界读取并显式失败

单次解析设行数与字节上限，超过就报错而不是截断。静默截断会让人以为已经看到了全部高风险提交，这比接口报错危险得多。

## Risks / Trade-offs

每次请求重新解析 CSV，翻页是 O(全量) 的解析开销。当前演示规模（数百到一千余条提交）可以接受；如果将来单次运行包含上万条，就需要把解析结果缓存或落库，那时再按实测决定，而不是现在提前加复杂度。

## Test Strategy

- 单元：给定一份构造的工件，验证降序排序、概率并列时按提交编号升序、分页不重不漏。
- 边界：首尾页、页大小上限、空分区、只有训练分区时的默认结果为空。
- 非法：运行不存在、未发布、工件摘要不一致、分区取值非法、超过行数上限。
- 不覆盖并发与冷缓存，本次是只读解析，不涉及写路径。
