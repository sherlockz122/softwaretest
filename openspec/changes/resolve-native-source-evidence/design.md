## Every parent and scoped uncertainty

Read and verify the original commit object, ordered parents and both clocks. For each actual parent, read the complete bounded parent-to-result file changes, using the established raw/numstat/patch and line-content checks. Keep raw merge metadata separate from the explicit one-parent edge view supplied to baseline tracing. Never change the original parent list to pretend a merge was a single-parent commit. Combined diffs may omit files modified relative to only some parents; an empty combined diff is not completeness evidence. See [Git diff-tree](https://git-scm.com/docs/git-diff-tree) and [Git show](https://git-scm.com/docs/git-show).

Evaluate the existing message Fix predicate with the union of actually observed parent-edge file records; only evidence of genuine exclusions (for example all edges documentation-only) may refine the old unverified classification. Export every edge's full trace, file disposition and source hashes. Verify each parent belongs to the original ordered parent list, all required edges occur exactly once, and every eligible target has actual compatible parse evidence, clocks and strict ancestry.

For a single parent, the projection is the existing supported line policy, with explicitly recorded new target evidence if reparsing resolves a prior failure. For multiple parents, provisional positives require the same eligible origin identity to be witnessed on every parent edge. The union of concrete origins not supported by all parents, and any ineligible in-frame origin, remains target-specific uncertainty; it is not relabelled negative. Unknown files/unmapped lines or unverified outside-frame identities remain global gaps. Verified outside-frame identities cannot be confused with unreadable lines. Existing valid provisional positives remain evidence, not causal proof or Gold.

Every original target receives a full W90/L7 horizon result, using all1971 observations and the fixed roles. A negative requires no compatible positive and no applicable unresolved global/target gap. Retain actual_label_available_at=null and distinguish counterfactual availability. The new projection is a new purpose/version, not a rewrite or assertion of equivalence to v1 merge semantics. Support, maturity/purge, native14/representation, independent review, contamination and utility remain distinct gates; this batch grants no training/release readiness even if support improves.

## Owned runtime and caches

The new reader uses a separately bound runtime: bounded stdout/stderr, cooperative check/deadline during waits and after exit, and cleanup of only its owned process group/tree. On Windows retain the actual Popen handle and PID/creation identities; a denied/failed taskkill must not skip root cleanup or other owned descendants. Cleanup failures cannot be reported as success. Validate actual nested children, cancellation, timeout, terminal bursts and normal allowed exit statuses. Sampling/cooperation is not a universal OS-crash or hard-quota guarantee. Legacy `semantic.control`/`repositories.clone` and their artifacts remain unchanged; only the new path obtains this behavior.

Caches live only within a verified source execution: at most8MiB/512 ordinary blob entries and4096 `(origin_sha,parent_sha)` ancestry results, with bounded eviction and checks on every hit. Bind immutable content identities, retain object hashes and final source inventory verification. Do not cache errors or turn cancellation/time/ancestry failures into success. Source/mode/version changes must not reuse incompatible entries. Preserve every original line and missing reason; changing target eligibility after a real reparse is evidence refinement, not a cache-equivalence claim.

Benchmark the two fixed completed units in stage33's pre-execution plan, including the1798-link unit with its genuine target gaps. Use the original immutable target eligibility for both reference and candidate, fresh attempts and3 alternating cached/uncached pairs. Compare complete observations/line facts byte-for-byte, not only aggregate counts. Keep per-run wall/RSS/commands/cache/cleanup and median/range; do not call uncontrolled OS caches cold. Adopt caches only if matched-batch median wall improves at least20% (internal engineering criterion), reference equality and resource/cleanup tests pass; otherwise use uncached new runtime and retain the negative result. Reparse/refinement is measured separately.

### v3 nested budget isolation, declared before implementation

V2's independent empty-cache replay differs on two observations and six `gap_fix_ids` lists; identical labels do not satisfy the complete-payload requirement. A nested fresh target metadata/record parse currently mutates the same reader's deadline used by its enclosing trace, so a child's timeout can exhaust unrelated subsequent line reads, and a child's success can replace the parent's remaining budget with a fresh30 seconds. The v3 correction saves that parent deadline and charges the fresh independently bounded target suboperation to its own budget, restoring the parent deadline plus exactly the suboperation's elapsed time on success or failure. Thus the parent's remaining active budget is preserved; cached target lookup/deep-copy work remains inside the parent budget. Target metadata and record reads retain their existing30-second bounds; every native read and terminal acceptance still checks its deadline. Whole source2700-second wall, parent identity/cancellation,6GiB RSS and output supervision remain active during nested work, so this is no universal30-second total-wall promise or unbounded pause.

Use the new source version and fresh declaration/cache namespace; retain old artifacts, failed strict replay and frozen v2 copied ROOT. Add actual two-file cold/warm timeout equivalence, deterministic remaining-budget success/fatal counterexamples, and require them in formal safety. Fatal ownership/cleanup failures must still abort without publishing an observation; restoring clock bookkeeping cannot suppress them. Regenerate current safety, unchanged original-eligibility three-pair benchmark, pilot/full projection and a fresh copied-root empty-cache comparison of every payload and target-attempt unit. No new eligibility memo/cache is adopted: measured43 target calls/0.594 seconds do not support that additional change. Publication lock/attempt suffix `v2` remains the storage protocol name, distinct from source-policy versionv3.

Use exclusive persistent OS publication locks and immutable unit hashes. Revalidate completed units before resume; cache/inputs/source drift refuses rather than overwrites. Preserve failed attempts and original drafts, account for temporary publication peaks, and reconcile before publication. Independently restore the old+new evidence closure under another local root, replay all new cases from an empty cache, and independently rederive horizon results. This is a local installed-dependency closure, not clean-machine/full-product disaster recovery.

The output namespace budget includes published artifacts, failed attempts and residual temporary files. Count at most4096 filesystem entries (directories included conservatively) and1GiB of logical file bytes, reject links/special files/unreadable trees, reserve atomic publication/native temporary peaks before writes, and hold the output OS lock from attempt creation through publication. Refusal preserves prior evidence; it never deletes failures to make room. This is a per-output namespace bound, not a lifetime whole-project quota. Logs remain individually bounded and the project storage wrapper budgets each new phase/retry.
