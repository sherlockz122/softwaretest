# Design

The operator explicitly supplies a local runtime source directory and its expected64hex manifest identity. This is a trusted deployment operation, not an HTTP upload capability. The importer verifies the v5 source, copies only embeddings.npy/rows.json/coverage.json and the original manifest, and publishes a deterministic sealed consumer receipt into runtime/semantic-assets/<receipt-hash>. It excludes paths/text from public API projections. Failed attempts remain hidden and preserved; identical imports are idempotent; conflicts and mid-operation changes reject without replacing a published directory. Independent restore must work without the old directory, weights, producer executable source or Torch. The receipt preserves provenance assertions without claiming their truth or re-certifying source/labels/license.

v1 only admits frozen-codebert-population-v5 with660 rows,3076little-endian float32 columns,488train/172validation and its fixed CPU protocol. Manifest≤64KiB, rows≤512KiB, coverage≤1MiB, NPY header≤4096bytes and exact660×3076×4body; receipt≤32KiB. Read from an opened regular non-link runtime path with exact declared size, bounded reads and before/after identity checks. Duplicate JSON keys/nonfinite values/nesting/schema surprises reject. NPY is parsed using a bounded literal header and streamed finite/mask/empty-role checks, never pickle or unbounded NumPy load. Caps are version-specific support limits, not an admission increase for old research contracts. A failed artifact is not silently omitted from catalog results. Max64 published assets; deterministic hash ordering; API page_size/limit≤100, stable index and optional train/validation filter. Listing verifies receipts and original manifests, detail verifies all files and exact row/coverage projection before responding. A list item does not claim current matrix verification.

All existing authenticated Viewer/Member/Admin users can read the research catalog under the existing shared deployment policy; anonymous/disabled/stale sessions are rejected by current_user. No HTTP mutation or model publication permission is added. API errors contain safe codes/request IDs, not paths, input text or dependency details. No cross-request mutable validation cache in v1. New APIs are A36 GET /semantic-assets and A37 GET /semantic-assets/{asset_id}; database stays0011. API sees a read-only D bind; the operator creates directories. Missing catalog is an empty state. Restore/import output remains under configured local runtime with reparse checks and no C fallback.

This is the first application read/display slice, not complete semantic creation/training/serving. Follow-up adds qualified inputs and reliable semantic tasks, then same-population baseline/semantic/fusion evaluation and licensed/independent target-domain publication. Eight-model, historical/candidate chains, governance and100request hotP95 remain in the whole-product plan. Allocation measurement is Python allocation, sampled processRSS separate, not serviceP95 evidence.

Full-page reload retains the existing in-memory access/CSRF contract: re-login is required, followed by an allowlisted internal return to the original semantic asset identity. Add semantic-assets to that existing list and reject external, lookalike and array return values; never persist tokens or weaken authentication to satisfy a browser assertion. Local filter/page state resets on full reload. The first18/19 browser attempt and its successful cleanup remain evidence; re-run the complete19 against the corrected UI.
