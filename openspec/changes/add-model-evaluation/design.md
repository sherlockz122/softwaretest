# Design: add-model-evaluation

## Context

这次改动要在已有的固定公开研究数据集之上，建立第一条逻辑回归（LR）和随机森林（RF）的训练、评估与模型工件应用链路。数据集版本是已发布的 published_binary_12_v1，包含两个类别和十二个数值列。训练直接消费它已经发布的 manifest、固化成员和 CSV，不重新运行当前的数据集构建规则去重算旧版本。

训练依赖使用独立的 modeling 依赖组，核心是 scikit-learn 1.7.2；模型工件用 skops 序列化。运行环境只使用 CPU，不使用 GPU，也不下载模型权重。

这次改动不重复实现已有的数据集发布能力，也不改动 0001 到 0010 的迁移，数据集只作为固定输入读取。训练放在受监督的本地子进程里，父进程负责取消、租约、时限、内存和容量的控制。研究结果与候选发布资格保持隔离：A22 只检查当前用途并拒绝不兼容的产品发布，研究模型不会自动上线。

## Goals / Non-Goals

目标：

- 为 US-09、US-11～US-15 建立第一条逻辑回归和随机森林的训练、评估和工件应用链路。
- 固定数据、参数、代码和依赖，让同一组输入能够复现结果。
- 只让训练集参与拟合，验证集负责校准和阈值选择，测试集只做最终评价，避免信息泄漏。
- 把研究结论与候选发布资格隔离开，研究模型不会自动进入产品用途。

非目标：

- 不把旧标签、旧历史或候选资格晋升为生产用途。
- 不实现语义模型、其余六个模型、未知格式导入或 main 分支维护。
- 质量线未决的部分继续保留，不在这次改动里决定。

## Decisions

### 决策 1：只消费已发布数据集版本，并冻结全部训练输入

这次改动仅支持已发布的两类、十二列研究数据集版本 published_binary_12_v1。训练消费已经发布的 manifest，以及固化的成员和 CSV，不调用当前的数据集构建规则去重算旧版本。创建训练任务时冻结数据集摘要、十二列、目标列、插件、参数、种子、代码和依赖摘要；Worker 重新核验完整的数据库成员、分区和工件。数字文本按无损方式保存，CSV 逐项精确核对，不放宽容差。合法的浮点参数经 MySQL 任务持久化、认领和幂等重放后要保持逐位一致；超出范围的整数返回 422，不发生浮点转换溢出。

### 决策 2：运行根记录与工件登记一次完成

model_run 的根编号对应第一次任务；重试时保留同一个根任务和最新任务栅栏，每次尝试使用独立的目录。model_artifact 记录固定的名称、大小和哈希，不接受用户提供的 URI。完整工件和成功状态在同一个事务里登记，不发布半成品。A22 会检查当前用途并拒绝不兼容的产品发布，研究模型不会自动上线。

### 决策 3：训练、校准和阈值都按固定子集与规则执行

训练使用 scikit-learn 1.7.2。逻辑回归（LR）先做标准化再训练，标准化只在训练区上拟合（train-only，即只用训练区拟合）；随机森林（RF）直接使用原始数值特征。默认既不重采样，也不设置类别权重。验证集按时间顺序分成前后两半：前半部分在同一时间组内拟合 sigmoid 校准，后半部分在同一时间组内选择 F1 阈值。阈值候选固定为 0.05 到 0.95、步长 0.01，平局时取较高的阈值。如果验证集分不出两类，或者凑不出同时间组的子集，就直接拒绝，不向测试集借样本。训练、校准和阈值选择所用的子集与规则都固定下来，测试集只做最终评价。

### 决策 4：指标口径固定，区间只做描述

基准模型使用训练集的先验常数。指标覆盖两个类别，包括 PR-AUC（定义为 average precision，即精确率-召回率曲线下的平均精度）、ROC-AUC、MCC（马修斯相关系数）、F1、Brier 分数和可靠性，以及 PofB20、IFA、Popt 这三个与工作量（effort）相关的指标。并列概率按事件、提交 SHA 和规范顺序（canonical）依次排列；这些指标以完整提交为单位，跨过 20% 的边界；零工作量导致密度无穷时，把它放在最优和最差参考的最前面；曲线面积用梯形积分计算，分母为 0 时返回 null。测试集按连续时间块做 bootstrap，固定 seed，重复 100 次，只报告描述性的条件区间，不用来选择模型。

### 决策 5：训练在受监督子进程中执行，失败后从固定输入重训

训练在一个独立的本地子进程里执行。父进程每 0.5 秒检查一次取消、租约、900 秒时限、2 GiB 的常驻内存（RSS）上限和物理盘 2.5 GiB 的余量；每 2 秒做一次容量监测，并在阶段边界写检查点、续租。进程的线程数上限为 1；随机森林的并行任务数（n_jobs）为 1，最多 256 棵树、深度 32；逻辑回归最多训练 1000 轮。子进程一旦发现父进程身份消失就退出。fit 不能从中间接续，所以故障重试时从固定输入重新训练，不能声称恢复了模型的内部状态。

### 决策 6：模型工件只信任可核验的序列化结果

模型工件用 skops 保存，不加载外来的 pickle，也不自动信任未知类型。序列化之后重新载入并核对预测是否逐项一致；训练报告用 JSON 保存，逐行概率也保留下来。

### 决策 7：0011 的降级先做整路径预检

schema 0011 的降级会先对整个请求的目标路径做预检：模型运行、模型工件、训练任务，以及将受影响的旧表和引用都必须为空，任何 DDL 执行之前就拒绝。0001 到 0010 的迁移不改。模型目录对 Worker 可写、对 API 只读，数据集目录只读；现有的初始化器不得递归改动正常数据卷。

### 决策 8：并列概率排序按事件、SHA、规范顺序

验收时发现初始 v1 的并列概率排序把规范顺序（canonical）排在 SHA 之前，这与 03 号数据与算法规格不一致。用两个样本构造反例确认之后，改成 research-lr-rf-v2 的事件、SHA、规范顺序，并补了一个独立的对照实现（oracle）来核对。旧模型、失败和中断的回归都保留，参数、校准和阈值不变；新版本重新训练和验收，不根据测试结果反过来优化排序。

## Risks / Trade-offs

| 风险 / 权衡 | 说明 |
|---|---|
| 只支持 published_binary_12_v1 | 其它数据集版本和其余六个模型都不可用；换取的是输入、摘要和验收口径完全固定。 |
| 默认不重采样、不设置类别权重 | 在不平衡数据上不会主动调整样本或类别权重；换取的是训练规则简单、可复现。 |
| 阈值候选固定为 0.05 到 0.95、步长 0.01 | 阈值只能落在固定网格上；换取的是校准和阈值规则可复现、可审计。 |
| 测试集 bootstrap 只报告描述性区间 | 区间不用于选择模型；换来的是避免用测试集挑选模型。 |
| fit 无法中途接续，失败后从固定输入重训 | 重试会重复消耗训练时间；换来的是不伪装恢复模型内部状态，重试结果可解释。 |
| 训练子进程受 900 秒、2 GiB 内存和磁盘余量约束 | 超出预算的训练会直接失败，需要调整预算或另做设计；换来的是单机资源可控。 |
| 工件只信任 skops 已知类型 | 外来的 pickle 或未知类型会被拒绝；换来的是不加载不可信的序列化对象。 |
| 0011 降级要求目标路径为空 | 非空时必须先人工清理，降级不能直接执行；换来的是不会在 DDL 阶段破坏已有模型数据。 |

## Validation

- 用手算结果核对指标和阈值。
- 扰动测试集，确认模型、校准和阈值都不受影响。
- 覆盖两类、同时间组、精度和 schema 漂移这些边界，并验证 skops 会拒绝未知类型。
- 在真实 MySQL 上验证幂等、RBAC、取消、过期令牌、原子回滚和降级。
- 用真实 Worker 验证进程终止和重试。
- 在固定的 106674 研究数据上，用 LR 和 RF 各跑两个 seed，核对重复复现结果并实测资源占用。
- 在独立的新卷上用浏览器验收，并核对备份恢复摘要。
- 复跑完整的旧回归、锁检查、安全检查、严格校验、合同校验和精确 SHA 校验。
- 用两个样本的反例验证并列概率排序，并用独立对照实现（oracle）核对 research-lr-rf-v2 的顺序。
