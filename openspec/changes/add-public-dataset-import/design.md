## Context

资产层的现状是按 ApacheJIT 这一种来源写死的：文件清单是固定的六个名字，适配器版本是 `apachejit-asset-12-v1`，导入函数在封装前会调 `audit_paths` 对两份表做联合审计，数据集准备阶段会再读一次许可常量。数据集的准备阶段要求每行十七个字段齐备，其中十二个数值特征不能为空。

导入要接进来，最小的改动点是把「来源种类」变成资产的一个属性，而不是模块里的常量。

## 决策 1：上传走显式列映射，服务端不猜列

上传方在表单里为十六个必填字段各选一列，服务端只按映射取值。列名相近、大小写不同、中英文混排都不做自动识别。

自动猜列看起来省一步，但猜错的后果是把另一列的数字当成改动行数，训练会安静地错到底；显式映射错至少会在体检阶段暴露成类型或范围错误。

备选路径是按列名相似度匹配并给候选建议。可以做，但必须仍然要求用户确认，等于多一层交互换不到少一步操作。

## 决策 2：上传作为独立来源种类，与下载来源分开版本与文件清单

资产清单里增加来源种类与对应的适配器版本，上传来源用自己的版本号与文件清单（上传原文、来源声明、归一化文件、质量文件、清单）。读取旧资产时按旧版本校验，行为不变。

这样 ApacheJIT 的六文件清单与许可常量不会被套到上传来源上，也不会为了共用一份校验而给上传来源伪造 `zenodo-record.json` 这类文件。

备选路径是让上传来源也凑齐六个文件名。文件是齐了，清单里会出现与来源无关的文件，读的人无法分辨哪个是真实来源记录。

## 决策 3：十六列必填，缺特征就拒绝，不补零

必填十六列是提交编号、项目、标签、作者时间与十二个数值特征。缺任何一列返回明确错误并列出缺的列名。

补零会把「没提供」变成「零改动」，训练与评估都会当真值用；标成「未提供」需要数据管线支持缺失值，那是另一批改动。这一批选择明确拒绝，让缺特征的数据进不来，而不是进来后悄悄变味。

备选路径是允许缺特征并记 `features_unavailable`。方向对，但准备阶段现在要求十二个数值齐备，改了会牵动训练与指标，不适合与表单一起做。

## 决策 4：请求体用 JSON 携带 CSV 文本，不引入 multipart 依赖

接口接收 `{"source_name", "license", "content", "mapping"}` 四个字段，`content` 是整份 CSV 的文本。服务端限制文本长度与行数，超限直接拒绝。

这样不需要新增 multipart 解析依赖，也沿用现有「JSON 请求体 + 来源头校验」的约定；代价是文件体积上限比二进制上传小，按目前的演示规模足够。

备选路径是 multipart 文件上传。适合大文件与流式处理，但要新增依赖、另做临时文件与中断清理，收益要等到导入真的跑几百万行时才显现。

## 决策 5：导入在请求内同步完成，先体检后封装

一次导入最多两万行、四兆字节文本，服务端在请求内解析、体检、写资产并返回。体检五项全部通过才落盘，任一项失败不留资产目录。

备选路径是把导入做成异步任务。任务体系现成，但导入的耗时在一秒量级，异步只会让页面多一个轮询状态。

## 决策 6：表单只做最小交互

表单包含文件名、许可、十六个映射选择、提交按钮，以及结果区（资产标识、行数、标签分布）与错误区（错误码与缺失列）。不做进度条、不做断点续传、不做预览表。

备选路径是做导入预览：先上传解析出前几行让人确认映射。这个体验最好，但需要两次往返与临时解析状态，等到表单被真实使用过一轮再加。

## Risks / Trade-offs

- 许可责任：上传方声明许可，系统只校验字段存在与取值在允许集合内，不能替上传方判断数据真的可以再用。
- 数值口径：上传数据填进的是产品侧的十二个数值列，来源方原始定义可能与产品口径不同，质量文件里记录「按上传方声明」并保留原始字段。
- 与下载来源的对比：两类资产的能力位与限制清单分开记录，不能拿上传资产的结果去证明公开数据的效果。
- 重复上传：同一份内容重复上传应得到同一资产标识；若上传方改了声明，标识随之改变，两个资产并存并各自可追溯。

## Migration Plan

这次不改数据库，只新增接口与表单。已存在的资产按旧版本读取；接口清单与 OpenAPI 基线需要同步。实现分三步：资产层按种类泛化并保持旧资产不变，接口与体检，表单与浏览器实测。

## Validation

文档层面跑严格 OpenSpec 校验与契约检查。实现层面按下面的任务逐条验证：旧资产读取与导入幂等、缺列与标签非法被拒、行数与体积上限、权限拒绝、表单提交与错误显示。细则见 [导入方案与格式口径](../../../docs/development/公开数据集导入方案与格式口径.md)。
