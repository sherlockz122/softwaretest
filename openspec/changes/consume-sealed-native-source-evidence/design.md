## Bounds and result

Initial limits:64 total files/entries across the full supplied closure,128MiB payload bytes,64MiB individual file,16MiB JSON/JSONL record,2MiB manifest,1200 targets/2048 observations under these known producer policies,60-second operation wall and1GiB sampled process RSS. These are new-consumer engineering limits, not changes to generator limits or hard OS quotas. Check actual and declared sizes before allocation, strict JSON duplicate/nonfinite values, XML entity rejection, plain files and safe root-relative paths. Reject unknown extras, directories/links/reparse/special files and unsafe recorded filenames. Supervise hashing/record loops, revalidate all bound files/catalog at terminal acceptance, preserve originals on refusal. Test the limits before accepting them as sufficient; if evidence requires a change, amend this design before a fresh run and retain failure evidence.

Return a small versioned sealed result binding the technical approval, both manifest identities where required, current consumer code/runtime descriptors, fully rederived summary/outcome digest and explicit capabilities. Historical verification and recorded producer cache use are separate from current cache adoption, source authenticity claims, Gold, professional review, training/readiness and release. All existing qualification fields stay false. CLI errors are safe codes; metadata/payloads, absolute paths, commands and raw producer logs are not emitted. Normal verification is read-only; no runtime approval update or implicit output publication is offered.
