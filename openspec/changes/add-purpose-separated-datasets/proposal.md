# Change: add-purpose-separated-datasets

## Why

此前系统只把公开数据保存成离线资产，应用里还没有用途明确的数据集，也没有配套的任务恢复、权限和页面。这样一来，公开的后验银标（由已发布信息推导出的弱监督标签）进不了生产用的十四维特征，也进不了要求标签在事件发生时可知的那套合同；文件保存得再完整，同样不能证明模型可以发布。

这次把离线资产接成一条应用内可创建、可查询、可追溯的数据集链路，先把研究用途、来源和标签口径固定下来。

## What Changes

- 交付 US-08、US-09 与 US-24、US-25 的首条应用纵向：从 0009 的持久化，到 dataset.build（数据集构建任务）、A17～A19 三个数据集接口和页面，再到研究用 12 个数值的 CSV（逗号分隔值）导出。
- 固定数据集的资产、政策、成员和分区摘要。时间切分按同一时间组留出，或者按 canonical（规范化的仓库标识）做仓库留出；重复和冲突有明确处置，每个分区都要检查是否包含两类样本，最终以原子事务发布。
- 只允许 published_binary_12_v1（基于已发布标签的 12 数值研究用途）这一种研究用途。历史用途和候选用途的资格不足时明确拒绝，不修改旧的 FeatureRun（特征轮次）记录、原资产和 review（复核）记录。

## Capabilities

### New Capabilities

- `purpose-separated-datasets`：用途分离的数据集持久化、可复现分区、可靠构建与原子发布，以及 A17～A19 的应用入口和受控导出。

### Modified Capabilities

没有。这次改动不改变任何已经验收过的能力行为。

## Impact

**数据库**

新增 0009 迁移，建立 dataset_version（数据集版本）和 dataset_member（数据集成员）两张表；0001～0008 的旧迁移不改。再追加 0010 迁移，把成员的数值列改成无损的规范化 JSON 文本。降级必须在任何 DDL（建表、改表这类数据定义语句）执行之前完成预检，受影响数据非空时直接拒绝。

**后端**

新增数据集创建、分页列表、详情和已发布 CSV 下载接口，对应 A17～A19；构建任务复用已有的异步任务框架和 outbox（事务外投递表），新增 dataset.build 这一业务类型；权限沿用现有角色，Viewer（只读角色）只能读取，Member（成员）可以创建，任务由 Owner（所有者）或 Admin（管理员）管理。

**存储与资源**

API 与 Worker 以只读方式挂载 public-assets（公开资产目录），Worker 另外写入专用的数据集工件目录，路径由专用初始化创建，不向请求暴露本机路径。整轮构建限时 900 秒，每 2 秒检查实际输出挂载至少保留 2.5 GiB；磁盘空间不足时直接失败，不回退到 C 盘。

**不在本次范围内**

模型训练、其它数据格式、多语言与类型资格，以及 main 分支的维护，都不在这一批；历史用途和候选用途的资格接入也留到后续批次。
