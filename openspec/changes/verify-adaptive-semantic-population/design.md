## Population and immutable lineage
All existing660 v2 rows, in their exact recorded order. Validate canonical repository, nonzero40lowercasehexSHA, unique canonical+SHA, partitions488train/172validation and existing hunk/file bounds. Identity alone selects membership; never inspect labels or scores to substitute rows. Freeze seven slices [0,96),[96,192),[192,288),[288,384),[384,480),[480,576),[576,660). A84-row tail is real data, never padded or repartitioned. Bind v2, prior96 v3/v4, safe weights, current source hashes and all members at declaration entry, and recheck before every accepted publication. Old modules/manifests stay immutable.

## Context chunks
For every row read original old/new blobs once under existing native Git30s/byte/file limits, reconstruct LF hunks and old v2 text/selection audits exactly. Apply unchanged v4 classify_groups/select_lines from old v2 floor. Preserve4032contenttokens/32contiguouscodewindows,2messagewindows and original32linecandidates/256hunks. Required content class comes from full eligible ranges, with old changed base before alphanumeric/nonblank, no arbitrary fill. Budget/cap/message failures remain explicit unsupported, not a proof of infeasibility and not a reason to drop a member. Oversized serialized rows fail the chunk before publication under existing record limits, retaining attempts.

For the original96, independently construct the complete v3 record from the same groups and compare it to sealed v3; compare v4 selected text, coordinates, per-role audits, message audit, support and parent hashes to sealed v4. These are checks after recomputation, not cached result substitution. Do not claim prior v3/v4 reconstruction for remaining564. Record population_index and exact original identity, separate structure/content-class/eligible/changed-base/cap metrics. Hash and retain every member. Context chunks and merged660 payloads deterministic, with publication dedup only after complete computation; two complete passes have distinct supervision/log paths.

## Encoding and merge
Only a merged660 context with all660 supported can encode. Revalidate the whole population and immutable declaration before tokenizer/model loading, including while processing any slice. New validator supports actual slice counts and declared identities; do not call or monkeypatch the old fixed96 validator. Reuse the old pure bounded aggregation with records<=96, new complete32-window function and existing masked inference. Safe local CodeBERT CPUfloat32, threads4/batch8,128tokens, no gradients/downloads; all selected tokens must enter jobs. Each slice stores explicit global indices/members, coverage and float32 values shape(count,3076).

Merge exactly seven distinct indices with exact declared identities/order/ranges/checkpoint/execution/dependencies/sources and all-new-forward/frozen/first-batch-repeat evidence; reject missing/duplicate/reordered/foreign/drifted chunks. Concatenate all660 genuine vectors without placeholders. Two full passes must have disjoint operationIDs and byte-identical embeddings.npy/rows.json/coverage.json; volatile manifests/operation IDs and arbitrary serving or cross-population numerical invariance are not claimed. Old96 vector equality is not required because batch composition changes; actual96 selected text/audits must remain exact. New version is not old-model compatible.

## Resources, failures and workflow
Every child phase retains2700s/6GiB sampledRSS, original Git30s and caps. Sequential chunks only; a full pass is at most7 children per context or encoding phase, all bounded, and sources remain frozen across passes. D measured before stages/checkpoints; estimate contexts2GiB, encoding2GiB, backup3GiB and engineering4GiB peak; no C fallback, no large scan/backup with timed computation/fault tests. No weight duplication/download merely for a new version. Preserve failed attempts and raw original manifests. Unsupported population stops encoding and leads to documented bounded follow-up; no classifier fit, oldtest score, label/split/readiness rewrite or product release.

Require independent counterexamples for exact seven-slice mapping/tail, identity/split drift, all-input/source drift, v2/v3/v4 mismatch, unsupported retention/preload rejection, loss/duplicate/reorder/foreign chunk, nonfinite/shape/token omission, file-level repeat drift and safe supervision. Tiny CPU tests cover real84-tail aggregation/protocol separately from scientific validation. Complete full old/affected engineering, fresh-browser, material/restoration/storage guards under proper permission contexts, stop-preserve-normal, ordinary wang delivery and both exact-SHA CIs. Git file lists use-z/--name-only NUL rather than quoted human display; post-commit helper errors require inspecting the actual commit, not blind re-commit/amend.
