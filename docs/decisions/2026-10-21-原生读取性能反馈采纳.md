## 采纳和不采纳

| 项目 | 处置 | 理由和边界 |
|---|---|---|
| 优先量测原生Git读取和监督成本 | 采纳为后续工程切片 | 扩大真实原生输入前建立同口径基线；不假定所有成本都来自进程创建 |
| 常驻`cat-file --batch`对象读取 | 采纳为待验证候选 | 量测证实热点后设计有界管道/输出、取消清理和跨平台协议；不是本轮已选定或已实现的替换 |
| 改善等待与容量检查开销 | 采纳优化目标 | 保留取消、心跳、租约、截止时间、输出及D容量保护，具体等待方式/检查周期由预算与故障验证决定 |
| v2在大规模下收益非单调 | 登记待复测现象 | 核验输入、精确等价和重复测量；分析DAG祖先、作者衰减、dense回退和路径事件，不以7.7MiB差值锁定字典/GC原因 |
| 每提交固定26命令、52ms均属创建进程 | 不作为事实采纳 | 漏计diff/patch/tree且受文件状态/缓存影响；普通非合并双侧有效文本修改示意为3+5F，还不含冻结树读取，不代替实际计数 |
| 28倍/96.6%精确归因、全仓4.7小时 | 仅保留对方报告/外推属性 | 100条探针与12600条内核不是同人口同阶段对照，缺原始证据和重复运行 |
| 200条以上必然超时 | 不采纳推论，保留失败线索 | 按1.34秒线性估算200条约268秒，小于300秒；窗口文件量、全可达枚举、树核验及负载需另查 |
| 每提交只剩一次命令、降至0.1秒 | 不作验收承诺 | batch不会自动消除diff/patch/tree，实际收益须测量 |
| 直接阻塞wait、固定64次容量检查 | 不直接采纳实现 | 可能失去监督或形成无界检查间隔；20ms sleep是完成感知粒度，不是CPU忙等，也非每命令固定罚时 |
| 全部大仓库不可行、撤销已有内核优化 | 不采纳 | 有界单库实测不支持普遍结论，已有等价和用途约束继续有效 |

## 与旧决策及当前路线的衔接

第十八阶段为控制管道、跨平台进程和取消清理风险而暂不使用常驻cat-file，仍是该阶段事实。本决策只将后续量测及受控batch候选纳入规划；没有回写已验收设计，也不授权直接替换旧v1解析器。未来若通过验证，应在实施子change中说明替代范围、失败回退及规则版本/源码摘要兼容方案。

保留1000提交/10000文件/32MiB/数值30秒等现有限额，以及Git探针300秒与产品配置；纯内核绕过上层的12600条压测不构成产品容量认证。解析内容、模式、排序、rename/merge、缺失原因或身份语义变化须新版本和审计重算；纯性能改造也须核对规则摘要及未完成轮次的漂移拒绝，旧已完成结果不可覆盖。

该切片是扩大原生采集/在线核验人口前的条件，不暂停所有基于冻结资产的合格研究工作。第二十四阶段覆盖/支持/许可/独立复核与新人口准入优先级保留；不改旧test、标签资格、Gold或candidate门槛，不预设模型必有增益。索引退化与存储遍历维护分别记录，不混作同一热点。

## 执行责任和外部依赖澄清

用户确认临时答复已转交且自行删除目录，不恢复该目录；长期开发依据是本决策、总规划、问题账、测试计划及OpenSpec，不依赖临时答复或外部回信。

已明确采纳的是原生读取/监督热点量测、优先验证批量对象读取、按实测改善等待和容量调度，以及必要的数值热点复核。尚待确定的是具体实现参数、适用路径、实际收益和跨平台故障边界，属于开发方负责的工程任务，不是需用户补充信息才能开工的事项。

外部存疑与内部待验证须分开：前者是对方版本、26命令/28倍/96.6%等测量或推论的证据不足；后者是本项目候选实现是否安全有效，仍须由开发方实测。对方即使不回复，也可使用本项目已固定来源和真实Git夹具独立建立基线、设计子change、实施及验收；其补充材料仅用于复现其具体结果，不作为本项目继续开发或性能切片开工的前置条件。

执行顺序为：按第二十四阶段readiness继续覆盖/支持/来源及新人口准入；在任何扩大原生输入前执行本性能计划；开发方自行完成预算、量测、实施规格、候选比较、故障/等价验证和回退，并按结果更新任务账。不因外部材料未到而暂停合格冻结资产研究，也不因发现热点而默认扩大人口或提前发布。

本性能切片没有新增必须由用户处理的事项。已有人工来源复核仍需用户协调两名独立审阅者分别填写、必要时仲裁，不能由开发助手代替独立判断。权重适用范围核验/许可明确替代选择及其它工程准入继续由开发方调查和提出方案，不因证据缺失默认转交用户解决；如确实需要用户专属权限、资源/费用或外部联系决定，再说明具体事项、方案和影响。已知人工复核未完成只阻塞其依赖的来源认证/发布，不阻塞所有受限开发。

## 实施前量测和停止条件

1. 固定项目SHA/dirty状态、锁与解释器/Git版本、系统/硬件、源HEAD/取得时间/成员hash、覆盖及文件状态。取得对方脚本/计时日志后另认证其结果，当前代码事实无需等待才能登记。
2. 分别测初次解析、在线v1/v2原生核验与冻结、离线causal探针、同冻结输入纯数值内核；单独记录plan、record/blob/diff/patch、ls-tree、监督、计算及DB阶段，完整任务另测。计数命令类型、tick/容量检查、缓存命中、锁时间、wall与进程树峰值RSS；tracemalloc须注明仅Python分配峰值，单独测量避免扰动计时。
3. 先确定性真实Git夹具和既有本地源的小窗口，例如20/50/100，预算通过再至200，覆盖修改/新增删除/rename/merge/二进制/gitlink/超限；核对不同窗口文件量。明确应用缓存开关及OS缓存状态，至少3次可比重复、交错先后顺序，报告每次值与中位/范围；未控制OS缓存不得称冷缓存。预声明单次/整批上限、最小可接受收益和回退，未执行实验不填结果。
4. 不靠放宽限制、跳过accepted HEAD/模式/原生DB逐字段比较、把Git移入持锁事务、拆开原子冻结或改写历史来提速。batch须覆盖缺对象/错误类型/超限长度/截断或错位响应、stderr洪泛、管道阻塞、取消/租约失效/超时/父进程终止及Windows/Linux清理。输入不可信时拒绝，不运行仓库代码或启用网络获取。
5. 文件和内存缓存继续有界，命中仍监督；若降低容量查询频率，先声明时间/增长上界与检查点，不能将64次调用当作安全证明。保留进程退出后最终输出/时间复核的验收要求。
6. 每个读取器分别证实收益和等价；比较完整record、native digest、冻结输入、向量值/原因/质量及版本摘要规则。现有缺陷边界不因追求字节一致而豁免，修复语义变化另版本验收。无收益或故障清理不合格则保留原实现并记录负结果。
7. 新增下载、构建、探针或训练前实测D余量并预估临时峰值，传ExpectedGrowthGiB；长任务复测，不足保存进度停止，不转C。故障回归/编码/计时期间不并发全树存储扫描。
