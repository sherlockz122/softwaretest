## 2 任务状态和重试

原失败任务保留终态、错误和执行记录；重试创建新任务并通过 `retry_of` 关联。默认自动重试上限沿用架构基线。

`stale` 是心跳/租约派生的健康标记。协调器确认租约失效后将原执行标记失败，再按策略创建 successor。使用原子领取及执行令牌，防止消息重复投递和过期 Worker 写回破坏新执行。

取消采用协作式检查点；取消请求已接受与实际 cancelled 区分。取消和完成竞态通过条件更新裁决，不允许同时出现两个终态。

## 3 入队失败补偿

采用事务 outbox：在同一 MySQL 事务内创建业务任务和待投递事件，提交后由投递器发送至 Celery。失败事件持久保存并按退避策略补投，超限时产生可查询错误，不让任务永久静默停留 queued。

队列投递采用至少一次语义，不能宣称恰好一次。投递成功后、标记已发送前发生中断可能产生重复消息，因此 Worker 幂等领取和业务唯一约束必须一起实现。

验收至少覆盖重复请求、数据库提交后 Redis 不可用、发送后写回失败、重复投递、Worker 中断、旧 Worker 恢复、重试关联和取消竞态。
