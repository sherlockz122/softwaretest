# v2 文件历史索引决策

依据第十六阶段规划“扩大采集前先验证数值/原生读取/锁规模”，第十七阶段拆为受控文件历史索引批次。先消除重复扫描无关文件的开销，逐项与未改动的 v1 内核严格等价；不因空间充足提高1000提交/10000文件/32MiB/30秒限额。

v1 两个源码文件与原规则摘要保留。v2 数值部分复用旧当前内容公式并按路径事件索引计算历史六维；DAG祖先交集、committer/SHA排序、文件循环次序、改名/复制/删除生命周期和浮点 fsum 次序必须一致。新模块加入 v2 rule hash，老已完成轮次保持可读且不可变，旧未完成轮次规则漂移按原冲突处理，不跨实现恢复。

祖先求解、作者衰减及高频同路径仍可能二次复杂度。原生逐条 Git 与冻结数据库事务暂未优化，必须在下一批容量/锁探针后决定采集方案。性能等价不认证负例、知识可用时间或训练资格；来源认证、新数据集用途与A17～19、LR/RF仍按顺序推进。

实施探针发现密集路径索引退化，最终策略补充：完整事件排序单链复用祖先前缀；最大路径事件数超过提交数/4时复用旧vector扫描。策略仅由冻结输入确定且精确等价，阈值不是正确性/覆盖声明；四组最终probe保留调整前后证据。
