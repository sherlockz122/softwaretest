# 增量同步与验收

第八阶段实现 US-03 / A10。先完成安全克隆和初次解析，再同步默认分支；只在 wang 个人分支交付。Fix、SZZ、模型和历史分叉复核决策界面仍待后续。迁移 head 为 `0005_repository_sync`。

## 使用与状态

1. 按 [工程启动](工程启动与验收.md) 构建共用应用/页面镜像，先执行 maintenance migrate 的 upgrade head，再启动 full；已有认证、提交和首次窗口保留。版本不符时启动/readiness 拒绝，不能 stamp 绕过。
2. 仓库详情在首次解析完成后提供“同步默认分支”。Member/Admin 可启动，Viewer 只读；任务的取消/重试仍遵循归属权限。POST `/repositories/{id}/sync` 要求 Idempotency-Key 和空对象 `{}`，拒绝 URL、ref、limit 或路径输入。
3. 同用户/仓库/键重放原任务，不联网或新建窗口。正在同步、失败/取消等待重试或 requires_review 时，另键返回 409；失败/取消继续当前 task 链，不创建新窗口改变基线。
4. `repository.sync_status` 为 pending/queued/syncing/synced/requires_review/failed/cancelled；既有 clone 状态、首次 parse 状态不混用。解析后总数据可查询，但未完成同步的已提交批次不是已批准的新 HEAD。
5. 页面展示最新任务、首期历史覆盖度和分页同步窗口。任务成功且 result.disposition=requires_review 表示检查结束并暂停，**不是 HEAD 已推进**；仓库详情有醒目的复核提示。无复核批准/重置按钮。

## 不可变快照与进度

每个根任务有独立 sync_window：基线 HEAD/默认分支/存储引用、候选 HEAD/默认分支/存储引用、解析版本、关系、plan_hash、total/processed/last_sha。候选首次发布到窗口之后，重试直接读同一快照，不重新联网选 HEAD；上游之后继续变更也不改变当前计划。初次 parse_checkpoint 和每个历史 sync_window 永久保留，不放开旧 repository UNIQUE 约束来原地覆盖首次窗口。

候选由既有公开 HTTPS 安全克隆执行器完整 clone 到新 UUID 目录；不对任何已发布 bare 做 fetch/update-ref、alternates、hardlink、gc 或 prune。复用 DNS 全地址/连接 pinning、TLS、重定向拒绝、无凭据/钩子/子模块、输出/时间/大小约束。完整独立 clone 的成本明确：每轮可能多一个仓库副本，暂不以不安全共享来省空间。

原 HEAD 不存在于新快照、不再为新 HEAD 祖先、从非空变空或已有默认分支改变均 requires_review；保存候选供后续复核，不导入候选提交、不删旧行、不推进 HEAD。空历史变为非空是 initial；同 HEAD 且分支未变为 unchanged；正常 fast_forward 用 `rev-list new ^base` 算新可达集合，按 committer time/SHA 排序，不能用时间戳筛掉较旧的新提交。

复用第七阶段每10提交原子 upsert/checkpoint、唯一 SHA/文件序号、有效 token/status/lease/latest/root 检查。最后一批连同仓库 HEAD/默认分支/存储引用、100%/成功/审计同事务更新；期间旧 HEAD 仍为正式基线。取消、空间不足、崩溃、数据库失败保留已提交批次和候选；提交回执未知保留发布目录。解析临时目录与候选分开，清理只触及本次临时 UUID。

A09 增加 sync_status、sync_window 和 history_coverage；A10只读子资源 GET `/repositories/{id}/sync-windows?page=1&page_size=20`，最大100，created_at desc/root_task_id asc。只返回安全元数据/计数/版本，不导出 storage_key、token、邮箱和原始 Git 输出。A11可读取持久化批次的并集；数据集必须额外固定接受的 HEAD/窗口，不能把中断批次并集当不可变数据集。

## 资源与复验

受理与尚未建立候选的重试需要 `2*repository_max_bytes + 512MiB` 预计峰值，加2GiB紧急余量；旧快照本身已计入当前可用空间。克隆期间复用大小/超时/容量周期保护；解析前/命令/批次继续512MiB预算。预计容量不足提前拒绝/停止，保持进度，绝不转C。不自动删旧快照或用户文件；长期归档/受控清理须另有明确数据引用与回滚策略。

- `tests/test_sync.py`：真实 TLS smart HTTP Git、MySQL，含增量/无变化/时钟倒序、强推对象缺失及仍在其它 ref、分支变化/空库、幂等/RBAC、取消/租约/空间、最后批次回滚、未知快照/完成回执、旧数据升迁与整路径降级、最近N覆盖度。
- `tests/test_sync_runtime.py`：实际 Linux Worker 在提交部分批次后 SIGKILL，实际协调器过期/创建 successor；验证旧token拒绝、同一候选/旧HEAD保留、最终唯一记录及原子HEAD推进。夹具候选在同事务创建的测试窗口中预置，不设置生产安全绕过开关。
- 私有快照物理存在性由Worker应用身份验证；Linux根目录为UID10001/0700，宿主机及其它UID不可遍历。跨平台测试不能依赖Windows绑定目录的宿主访问表现，也不能放宽权限来使断言通过。
- 浏览器公开 GitHub clone→parse→sync（HEAD未变化）→文件查询/重登录；丢失sync响应后同键重放且页面继续跟踪，Viewer无同步按钮。独立新库/卷清理前保留本机服务日志，禁止用mock或skip取代网络接入。

本机结果保留 `runtime/acceptance/stage8`，日志脱敏及SHA-256清单；不上传Actions artifact。准确提交的远程 CI 结果另在本机 ci-status/聊天核对，不能用本机通过代替。

## 下一批注意点

优先 Fix 证据规则/版本与复核状态，随后独立 baseline SZZ change。requires_review 仍需未来设计显式批准、拒绝或重新基线流程，不能静默解除状态或覆盖原历史。新增规则、父策略、身份归并和窗口重算需要新版本及可审计方案。最近N的初次窗口经同步仍为 recent_window；不补全旧历史，不得用于宣称完整EXP/NDEV等特征。merge/二进制/编码/超限不是clean或零统计。数据集必须绑定接受快照、成熟标签和时间边界；磁盘足够不替代CPU/内存/时间探针。
