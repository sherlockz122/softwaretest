## 公开资产与用途

原始取得 → 资产清单/许可 → 有界解析 → 标准化派生 → 质量和能力审计 → 固定切分 → 数据集/模型工件 → 指定用途发布。每层不可变且保留来源关系。raw 能加载/保存与 ready 必须分开；可保存尚不兼容训练的合法数据。

首批只承诺 CSV/JSONL 显式适配；普通 JSON 元数据用于清单。CSV 按原编码/schema/单位和缺失值规则核验，不推测列义。任意 URL、zip、pickle、notebook、模型或脚本不作为可信数据直接执行；未知格式拒绝/登记待适配，不能承诺所有公开数据都即插即用。模块级/文件级/函数级数据可以存档/做其本身研究，不默认转换提交级标签。

拟定义 asset/source ID、dataset 名及固定修订/URL/许可/归属、各文件大小/SHA256、schema/adapter/quality 版本、取得时间、canonical 仓库/原 project、语言（可 unknown/多语言）、样本粒度、原事件时间/来源口径、标签/类型/位置的来源和置信度、可用特征组、未知字段和异常计数。样本身份用 source+row/commit+granularity，避免不同仓库同 SHA 或多函数/多语言变更混淆。原始字段和原始标签不丢弃；派生映射可追溯。

安全要求：当前 SSRF/DNS/redirect/TLS 策略用于远端取得；不得提供服务端任意本地路径/任意程序入口。导入限字节/行/列/单字段、限时、取消、失败不发布；文件名/解压穿越、链接/重解析、zip bomb 如后续支持须专项拒绝。CSV 导出防公式注入，原始字节仍封存。Member 可发起/管理自身可见资产，Viewer 只读，发布/共享按显式授权与审计，不扩大旧角色权限。

先做有界离线资产纵切和重新加载，再接应用任务、RBAC、迁移及页面。工件临时写入、校验后原子发布，成功之后目录/清单不能静默覆盖；重复取得保留已有 acquired_at，修订另生成资产。重启恢复、摘要漂移拒绝、幂等并发、任务取消/过期写回、导出再导入和损坏检测是验收项。备份/恢复按清单检查原始及派生哈希；存档重新加载要保留原时间，不能用恢复时间替代首次取得。

| ReDef C/C++ | 函数级变更与语义压力测试候选 | revert/人工与模型辅助筛选偏差、粒度/标签定义、仓库及版本、发布时间、许可、重叠和反事实；不把函数标签随意聚合成提交标签 |

原始修复文本/Issue 只用于事后标签审计；产品语义输入只用预测时可得的引入提交 message/diff/base，不引入未来 fix、Issue 结论或测试目标。仅数值来源的样本保持 semantic_available=false，不能自动生成源码或用合成缺陷扩充真实测试集。

## 数据质量与标签

| 维度 | 必须保留的报告/处置 |
|---|---|
| 完整性 | 必要字段/原对象/父关系/全文/时间/观察范围/截断缺失；按用途拒绝或 Unknown，不填零掩盖 |
| 准确性 | 标签链、选择过滤及 bug/fix 身份证据、独立审阅、分歧与未决；来源比较不等于 gold |
| 一致性/有效性 | 单位、时钟/UTC、schema、布尔/SHA、数值范围、特征定义、行与文件摘要；硬冲突不静默修正 |
| 唯一性 | 同仓库/同提交/同内容、cherry-pick/fork、同源不同版本/数据集重叠；记录原行，split 防跨组泄漏 |
| 代表性 | 按语言/项目/时间/大小/类别/缺陷来源及过滤的分布；缺类/删失不重采样 validation/test 来掩盖 |
| 时效与可用性 | event、acquired、label_available、review 时间分别存；今天取得不冒充历史当时可见 |
| 可追溯/可复现 | 原始/派生/规则/代码/切分/模型摘要、实际拒绝原因、许可范围、不可变和重新加载校验 |

定向85条包用于定位问题，不能估计总体噪声率。噪声研究另设计预声明的分层概率抽样、样本量/置信区间、两人独立盲审和分歧裁决；模型辅助标注只能是弱监督或建议，不能由同一模型同时产训练真值和测试 gold。保留未知/银标/金标与 review revision，允许在明确限制下进行弱监督研究，发布评估集至少有独立核验的子集及代表性说明。

缺陷有无、类型、粒度、位置、严重性是不同字段。拟引入 taxonomy_version、defect_types（可多标签/null）、type_evidence/status、location 与 location_evidence，初始类型集合在实际标注探针后预声明。未知类型不作为“无缺陷类型”训练。bug 的 Issue 分类、SZZ 指向某行、某词命中或解释贡献均不能独立证明类型/根因。先导入可选类型，后根据每类支持数/一致性/质量决定能否训练类型头；类型指标包含 per-class precision/recall、macro/micro-F1、未知覆盖和置信度。定位指标与二分类/类型指标分别验收。

## 训练资格分层

| 能力 | 准入含义 |
|---|---|
| raw_archived / normalized | 合法取得、清单/摘要/解析可验证，不等于标签正确 |
| research_binary | 明确原发布/弱监督目标；正确身份、两类可行性、独立固定分区、train-only 处理及噪声限制 |
| research_semantic | 上项加真实预测侧文本、合法权重/固定 tokenizer、文本可用时间和长度/缺失/重复控制 |
| historical_replay | 历史特征/标签证据在各训练时点已可用，观察与删失、purge/embargo、窗口及完整负例有依据 |
| candidate_release | 目标仓库/语言/输入版本兼容，独立评估、校准/阈值、评审效用/成本、冷/热性能、异常回退与可追溯发布 |
| type / localization | 对应粒度及独立类型/位置标注合格；二分类不能继承此能力 |

上述为后续设计，现有 product_training_ready=false 不改写。新增审计引用生成新版本，不凭文件下载或通过测试把原报告改成 ready。历史回放缺证不阻塞后验研究；当前训练允许真实“今天已取得”的标签用于今天训练/以后评价，但不能假称模型当年已经知道。固定时间边界不保证所有派生标签早已可见。

## 语义模型与公平验收

先 LR/RF + 数值基线，固定同一 eligible population/splits 再比较冻结编码器+分类器、语义/专家特征融合及有限微调。缺文本群体单独报告，不能把较容易子集的语义结果与整个数值集直接比较。课程六经典+MLP/TextCNN 矩阵保留；新增语义实验不会把 MLP 14 数值算成语义或未复现模型改名。预训练 tokenizer 固定 revision，不在全数据重学；任务拟合/降维/分类器/重采样/校准与微调遵守 train/validation/test 隔离。

message、added/deleted/base 块的角色和顺序版本化，保留语言/路径、分段窗口/mask/token 限制、截断/不可解码/空输入的显式原因；长提交按预声明规则聚合，不以“第一个512 token”代表完整提交。缓存键绑定原 blob/diff/输入 schema/checkpoint/tokenizer/池化/长度策略；训练随机增强与模型适配的缓存按 split/run 隔离。旧原生输入保存不足文本，须新受控语义工件，不更改已有 FeatureRun。

预训练可能见过目标开源仓库，核查权重发布时间/数据声明、项目/内容重叠，无法排除就报告可能污染；按新时间/仓库留出、重复内容去重、反事实 added/deleted 极性/非语义标记探针检测捷径。不要据权重早于某时间就宣称完全没有预训练泄漏。

主指标/成功门槛在看 test 前确定。报告 PR-AUC/MCC、effort-aware、校准/Brier/可靠性、时间块/仓库级区间、多 seed；按语言/项目报告支持数，不只整体微平均。验证阈值及回退，test 不择优，不把重采样测试分布或单类指标置零。语义/Fusion 没有收益或资源不达标时保留可用基线并报告负结果；代码可扩展不等于跨语言效果已验证。解释/注意力不是因果根因或类型真值。

模型权重/许可证/固定 revision/hash/依赖/设备均记录。默认本地离线推理，不把代码发外部 LLM。优先审查安全权重格式，不让服务加载未知 pickle/自定义 remote code；只有可信源老格式时先隔离审查/转换再发布安全工件，禁止 trust_remote_code 无审查开启。重任务使用独立依赖组/镜像与限额 Worker，不把 GPU/Transformer 依赖强装现有 API 镜像。

## 有限批次、空间和用户协助

第二十阶段已完成首条公开CSV离线保存/重载/能力及来源绑定review；第二十一阶段首条研究dataset/权限/任务/API已接入，直接下一批研究LR/RF工程，质量线受控核验选定小样本、缺对象Unknown继续保留。不要求一次补齐所有14项目完整历史/金标/类型。随后独立研究数据集及 LR/RF 任务/工件，再语义文本及冻结编码器 pilot；上线、八模型/类型/定位/多语言扩展按验收拆批。

此段空间范围是总体规划；第二十阶段只做CSV资产/复核，无训练或权重下载。实施前测 CPU/RAM/GPU、D 余量和源大小，使用 ExpectedGrowthGiB。暂估公共适配+复核新增0.5～2GiB、验收峰值另2～4GiB；研究链1～4GiB；首个预训练环境/单模型/有界嵌入新增3～8GiB、临时峰值另2～6GiB；微调可能8～20GiB以上，必须按样本/token/精度/optimizer/检查点重新算，不能将范围当安全承诺或重复累加。先有界分批表征，按完整样本数×分块数×embedding维度×字节数估缓存；只保存预声明代表工件，失败证据保留，不无界实验。

所有可控增长 D；不足先停并报告，不自动转 C。D 足够不证明 GPU/时间足够，不为资源困难降低质量或冒称语义任务完成。无需用户先找全量数据；如需要领域专家独立复核或经探针确认需要云 GPU，开发提交具体样本/工作量/预算/代码处理方案后再请求，届时不自动付费或上传。

设备实施参考 [PyTorch Intel GPU 官方说明](https://docs.pytorch.org/docs/stable/notes/get_start_xpu.html)：存在Windows/XPU路线，但当前设备/驱动/锁定版本/算子与实际性能未验证，不能把Intel Arc视为CUDA设备或把文档支持视为本机已可训练；本轮不安装或改驱动。
