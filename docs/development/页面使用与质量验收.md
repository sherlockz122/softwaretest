# 页面使用与质量验收

第五阶段实现框架登录/任务页面，依据 [界面规格](../08-界面与交互规格.md)、[API契约](../04-API与数据库规格.md) 和框架OpenSpec。专用loopback部署现已增加安全克隆及提交解析/文件列表，见 [解析指导](提交解析与验收.md)；增量同步已接入，见 [同步指导](增量同步与验收.md)；生产HTTPS、Fix/SZZ/预测待后续。

## 页面和会话

完整环境按 [工程说明](工程启动与验收.md) 启动，在 `http://127.0.0.1:18080` 登录。路由为 `/login`、`/tasks`、`/tasks/:id`、`/health`；未登录访问任务地址跳转登录，成功后返回原任务地址。用户名/密码使用显式初始化账号，不提供默认密码。刷新整个页面后重新登录是当前协议，不保存 access/CSRF 到 localStorage/sessionStorage。刷新不会删除数据库任务。

任务中心支持状态筛选、每页 10 项、分页和自动刷新。Member/Admin 可创建 0～30 秒诊断任务，Viewer 只读。详情展示任务 UUID、阶段、进度、心跳、起止时间、安全错误/request ID、执行结果和 retry_of 链。Member 取消/重试仍由后端校验创建者，Admin 可以操作其他任务；页面提示权限原因，无法越过服务器鉴权。运行取消需等待检查点，重试创建新任务。

查询按最新请求版本更新，并在页面离开取消请求和轮询；切换任务/筛选先清空旧对象，避免误操作旧任务。access 401 触发一次合并 refresh，失效会话转登录。退出等待可能进行中的 refresh 后撤销当前会话并清空内存，迟到响应不恢复任务数据。如果网络/CSRF 导致服务器未确认撤销，页面说明这一结果，不宣称已撤销。

创建/重试响应丢失时，同一页面、相同输入的再次操作保持原 Idempotency-Key。已确认成功后再次创建是新请求。刷新整个页面会丢失内存中的操作键；出现不确定结果时应先查询任务列表，再决定新建，不能通过刷新反复提交。

## 本机复验

从项目根目录运行，所有可控缓存仍位于 D 盘：

```powershell
$projectNode = 'C:\nvm4w\nodejs\node.exe'
$projectNpm = 'C:\nvm4w\nodejs\node_modules\npm\bin\npm-cli.js'
$projectPython = (Resolve-Path .venv/Scripts/python.exe).Path
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectNode -ArgumentList @($projectNpm,'--prefix','apps/web','ci')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectNode -ArgumentList @($projectNpm,'--prefix','apps/web','run','lint')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectNode -ArgumentList @($projectNpm,'--prefix','apps/web','run','format:check')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectNode -ArgumentList @($projectNpm,'--prefix','apps/web','test')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectNode -ArgumentList @($projectNpm,'--prefix','apps/web','run','build')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectPython -ArgumentList @('-m','scripts.check_contracts')
```

OpenAPI 基线为 `docs/contracts/bootstrap-openapi.json`；修改真实 API 后用 `python -m scripts.check_contracts --export` 导出并评审差异，不直接覆盖来隐藏漂移。依赖保持 npm/uv 锁一致。

浏览器端到端验收使用新随机配置/新数据库卷，不停止正常开发部署：

```powershell
$env:DG_BROWSER_CHANNEL = 'msedge'
try {
  ./scripts/Test-FreshEnvironment.ps1 -Browser -NodePath $projectNode -EvidenceDirectory "$PWD/runtime/acceptance/my-browser-run"
} finally { Remove-Item Env:DG_BROWSER_CHANNEL }
```

本机复用已安装 Edge，不另下载浏览器；其他环境可在 `PLAYWRIGHT_BROWSERS_PATH` 指向项目 runtime/cache 后安装 Playwright Chromium headless shell。`-Rebuild` 可显式执行无缓存镜像构建。故障场景只暂停脚本临时项目的 Worker，并只修改测试新建任务的截止时间；finally 恢复组件后清理该唯一临时项目。正常开发卷不删除。

完整后端回归仍按 [可靠任务说明](可靠任务与运行验收.md) 显式启用真实组件故障测试，不在团队或生产部署执行。

## 测试结果留存

本机结果在 Git 忽略的 `runtime/acceptance/`，按运行批次分别保存，不覆盖首次失败证据。内容包括后端/前端 JUnit、运行日志、浏览器 HTML 报告、错误上下文及桌面/窄屏截图。当前不保存 trace、HAR、storageState、cookie 或网络响应令牌。

```powershell
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectPython -ArgumentList @('-m','scripts.retain_evidence','--directory',"$PWD/runtime/acceptance/my-browser-run",'--label','local-browser')
```

索引 `manifest.json` 记录时间、验收起始提交、文件大小和 SHA-256；交付提交号由阶段报告/聊天记录关联。归档前自动去除本机配置实际 secret 和 JWT，截图由测试遮罩密码字段。只保存可诊断的证据，配置仍单独位于本机忽略的 runtime/fresh，勿将它与报告打包发送。

## CI 范围

`.github/workflows/wang-quality.yml` 仅对 `wang` push、目标 `wang` 的 PR 和手动运行生效；不合并、不部署、不推送其他分支。GitHub Actions 使用固定 action SHA、Python 3.11、Node 24.13.0、uv/OpenSpec 固定工具版本和项目依赖锁，在新 runner/new volumes 验证静态、前端测试/构建、迁移、OpenAPI、规格和真实 Worker 浏览器链路。

自动审批未批准向 GitHub Actions artifact 上传测试数据，因此当前不配置 upload-artifact；本机测试证据持续保留。CI 使用其自身生成的随机配置、诊断及公开仓库克隆任务，结果由 workflow 状态查看；配置存在不等于远程运行通过，实际远程结果在阶段报告单独登记。

后端步骤在 runner 内生成 JUnit 与完整日志，对外输出仅包含用例名称、失败类别及数量，断言内容和日志正文不输出；步骤保留 pytest 的原始退出码，摘要或环境清理不能将失败改成成功。

实现参考：[Vue Router](https://router.vuejs.org/guide/)、[Vue 请求清理](https://vuejs.org/guide/essentials/watchers.html)、[Vitest](https://vitest.dev/guide/)、[Playwright 报告](https://playwright.dev/docs/test-reporters)、[GitHub workflow 触发](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)。
