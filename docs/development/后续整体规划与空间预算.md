## 磁盘安排与容量决策

第二批结束附近：D 可用约 **9.46 GiB**，C 约 **48.17 GiB**；相对开始，D 空间减少约 **2.66 GiB**，包含依赖、镜像/构建缓存和数据库。全盘差值会受到其他程序影响，不能当作严格的本项目独占计量。现有第一轮新增预算 4 GiB 尚余约 1.3 GiB，D 保留 6 GiB 后约有 3.46 GiB 实际可分配余量；更严格的预算先到上限时就停止扩大范围。

代码、`.venv`、node_modules、下载缓存、临时文件、Git 样本、数据库/Redis 卷、模型和验收工件均使用 D。Docker/WSL 虚拟磁盘已在 `D:\Develop\DockerData`；API/Worker 共用镜像，不复制两份模型依赖。Node 可执行文件使用既有 C 盘安装，不新增 C 盘大体积安装。Windows/Docker 元数据、系统活动仍可能写 C，不能保证零写入，也不把 C 盘剩余 48 GiB 作为自动备用空间。

当前空间可继续认证与可靠任务的小批开发。采集和 LR/RF 阶段每次核查真实增长，始终保持小仓库、一个实验窗口和显式保留工件；不能凭上表估算越过 4 GiB 初始预算。

为了完整项目、少量重复实验及构建峰值，建议模型阶段前让 **D 盘或另一个用于开发的非 C 盘具备 20～30 GiB 可用空间**。这是基于当前实测与上表的小数据 CPU 路线预算，并非库厂商给出的最低要求；不能保证覆盖大仓库/大语义权重。当前 9.46 GiB 不足以稳妥承诺所有后续阶段。需扩容或另选数据盘时，单独规划配置和回滚，不自动迁移或删除现有文件。

八模型先采用 CPU 与受限语义输入，不默认安装 CUDA/大型预训练权重；PyTorch 允许选择 CPU 构建，具体版本、文件大小和兼容性在实施时重新核查，[依据官方安装选择器](https://pytorch.org/get-started/locally/)。若之后选择 CUDA、CodeBERT、大仓库或大量参数搜索，应另预留数十 GiB，并重新评估训练时间和内存；此范围不在本次安装计划。

每次安装或 build 前通过包装器检查 `D 剩余 >= 6 GiB + 预计增量`，并核查阶段累计预算；长任务在执行中也需容量检查。预算到限就缩小/暂停增长，不转移 C、不全局 prune。依赖锁文件和阶段报告上传仓库，大文件和 secrets 不上传。
