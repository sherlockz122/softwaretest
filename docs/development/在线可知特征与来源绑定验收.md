## 运行与版本

使用项目 .venv Python 3.11、D 盘 Docker/数据/缓存，开工核对 Engine 和 schema0008_features。启动 scripts/Start-Environment.ps1 -Mode full；修改本批服务代码后重建 api/web 并刷新部署，不能仅运行旧镜像验收。A15 feature_version 可指定 kamei14-dg-message-v2，purpose 为 historical 或 candidate；v2 禁止 fix_run_id。未指定版本的旧客户端仍为 v1，页面明确提供版本选择且默认 v2；v1 的 historical 冻结 Fix、candidate 默认 FIX=0 合同不变。

## 输入与质量边界

feature_versions.py 逐条核验已接受原生 Git 与 DB 投影，freeze_native_record 获取真实模式/前像；冻结信号仅保留消息摘要和判定，读取原消息不执行仓库代码。无法证明解码的 merge_skipped 继续 FIX=null/message_unverified。v2 both-purpose 同规则，后来人工复核不会改变冻结输入/结果。原有 feature_service 租约 token、最新任务、规则/HEAD/storage/版本栅栏、批次原子 checkpoint 和最后质量发布继续生效。

质量含 source_validation：accepted_head/native_records_digest、feature_population_complete、label_coverage_complete=false/product_training_ready=false。页面展示特征窗口完整与标签未认证，Viewer 只读。十四维缺失/原因/分位数仍保留；full 不等于每项非空，不补零，不构造训练标签。

## 验收与证据

tests/test_feature_v2.py 覆盖原生 DB 消息/计数/时钟/身份篡改、完整解析缺口、规则漂移、后来复核隔离、幂等版本冲突/Viewer、recent_window 和冻结摘要；取消/租约/容量失败后恢复保留同一冻结输入。tests/test_feature_runtime.py 对 v1 400 与 v2 120 提交执行真实 Worker SIGKILL，在已落库部分批次后修改 Fix、过期旧租约并恢复，拒绝旧 token，不能只测试 mock。完整后端与独立 UUID 新卷浏览器包括响应丢失幂等、Viewer、质量缺失和390px布局。实际结果以报告和本机 JUnit 为准。

本批保留 runtime/acceptance/stage16 及安全 evidence 子目录：首轮失败/最终 JUnit、日志、源/镜像摘要、独立浏览器截图、分支头、关闭状态及确切 SHA CI。不上传 trace/HAR/storageState/凭据，也不遍历复制 pytest 全目录；安全清单经 retain_evidence 脱敏/哈希。验收后停止普通项目容器，保留正常业务卷和私有仓库，下次启动恢复；仅临时新卷可删除。
