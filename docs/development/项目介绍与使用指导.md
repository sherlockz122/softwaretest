# 项目介绍与使用指导

这份文档给「第一次接触这个项目的人」用：项目是什么、环境怎么起、每个页面干什么、完整演示链路怎么走、测试怎么跑。需求与规格的权威口径以 [docs/README.md](../README.md) 的基线文档和 [openspec/](../../openspec/) 为准，这里只做导航与操作说明。

## 1. 项目是什么

DefectGuard 是一个面向代码评审场景的提交级即时缺陷预测系统：从 Git 仓库构建可追溯的缺陷标签、变更特征和数据集，对历史提交与尚未合入的候选变更给出风险概率、解释和评审排序。

一句话定位：**先"体检"（仓库分析），再"训练"（数据集与模型），最后"开处方"（预测与评审排序）——三件事分开，中间靠时间因果这条纪律连接。**

| 环节 | 输入 | 产出 | 页面入口 |
|---|---|---|---|
| 添加仓库 | 公开仓库 HTTPS 地址 | 受控克隆（内网/本机地址被拒） | 仓库目录 |
| 整理提交 | 克隆结果 | 按提交窗口解析的提交记录 | 仓库详情第 1 步 |
| 找出疑似修复 | 提交记录 | Fix 轮次（证据 + 把握等级，可人工复核） | 仓库详情第 2 步 |
| 追查缺陷引入 | Fix 轮次 | SZZ 标签（candidate_buggy / unknown + 行级线索） | 仓库详情第 3 步 |
| 计算统计指标 | 冻结提交快照 | 14 维特征向量（12 数值 + fix/lt） | 仓库详情第 4 步 |
| 研究数据集 | 公开数据资产（内置/导入） | 按时间切分的训练/验证/测试样本 | 数据集页 |
| 训练模型 | 数据集 + 插件与参数 | LR/RF 模型 + 评估报告 + 风险概率 | 训练页 |
| 历史风险列表 | 已注册模型运行 | 逐提交风险排序 | 风险页 |
| 合入前预测 | 候选变更 + 已注册模型 | 风险概率 + 解释（排序用，不是结论） | 预测页 |

技术栈：FastAPI + Vue 3 前端 + MySQL 8.4 + Redis 7.4 + Celery（Linux 容器内）+ scikit-learn（模型），全部依赖锁定在 `uv.lock` 与 `apps/web/package-lock.json`。服务端口固定绑 loopback：

| 端口 | 服务 | 说明 |
|---|---|---|
| 18080 | Web（Nginx 同源代理） | 浏览器入口 |
| 18000 | API | 健康检查 `/api/v1/health/ready` |
| 13306 | MySQL | 独立密码 |
| 16379 | Redis | 独立密码 |

## 2. 环境准备（一次性）

**Python**：项目要求 Python 3.11，依赖装在根目录 `.venv`。用默认 Python 3.13 直接 `python -m venv .venv` 会建成 3.13 环境，必须指定 3.11 解释器。日常使用不激活也可以直接调用：

```powershell
.\.venv\Scripts\python.exe --version   # 应显示 3.11.x
.\.venv\Scripts\python.exe -m pip --version
```

编辑器为当前项目选择 `.venv\Scripts\python.exe` 即可，不改系统默认 Python。

**Docker Desktop**：先启动（本机在 `D:\Develop\DockerDesktop`），确认 `docker info` 正常。所有服务跑在 Linux 容器里（Celery 不支持原生 Windows，以容器方式运行，不是 solo 绕过）。

**磁盘空间**：仓库/存储组件对运行盘剩余空间有预检（至少留 6 GiB）。C 盘吃紧时，把测试临时目录指到 D 盘（见第 8 节），不要靠删数据硬挤。

**前端**：Node 22+，依赖在 `apps/web` 用 `npm ci` 安装（锁文件为准，不跑裸 `npm install`）。

**配置**：`.env` 由 `scripts/New-LocalConfig.ps1` 首次生成（四个 256-bit 随机秘密，不显示、不上传、不入库）；已有 `.env` 不会被覆盖。秘密值只在本机，任何聊天、截图、提交里都不出现。

## 3. 启动与停止

**一键起全套**（构建镜像 + 六组件 + 初始化容器，数据留在卷里）：

```powershell
docker compose --profile full up -d --build
```

**迁移升级**：改过 `migrations/` 之后、启动 API 之前，必须显式执行（不 stamp、不手工建表）：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

**健康确认**：浏览器开 `http://127.0.0.1:18080`；`GET http://127.0.0.1:18000/api/v1/health/ready` 返回 200 表示 MySQL 迁移版本与当前代码一致且 Redis 可达。API ready 不等于 Worker 正常——任务真正被消费还要看任务页进度。

**停止**：`docker compose --profile full stop`（保留卷与镜像，下次再起即可）；`down -v` 会删数据卷，属于重来操作，别顺手执行。

**预置基线模型**：`DG_PRESET_REGISTRATION_MODE=startup`（compose 默认）时，API 启动会检查模型池，缺失就用内置公开资产训练并注册 LR/RF 预置基线（按代码版本幂等，重复启动不重训）；内置资产还没导入时注册自动推迟、不阻塞启动，之后跑一次 `python -m scripts.register_presets` 即可补上。

## 4. 账号与权限

注册默认关闭，账号由管理员用 `python -m packages.auth.bootstrap`（带 `DG_BOOTSTRAP_USERNAME` / `DG_BOOTSTRAP_PASSWORD`）显式创建。三种角色能力对比：

| 能力 | Viewer | Member | Admin |
|---|---|---|---|
| 查看仓库/任务/数据集/模型/风险 | 是 | 是 | 是 |
| 添加仓库、跑四步分析、导入数据、建数据集、训练 | 否 | 是 | 是 |
| 把运行加入模型池 / 移除自己的池条目 | 否 | 是 | 是 |
| 移除预置池条目、发布候选产品、创建账号、操作他人任务 | 否 | 否 | 是 |

登录失败有限速；access/CSRF 只放内存，整页刷新后重新登录（会跳回原页面），不写 localStorage。

## 6. 完整演示链路（当前版本）

演示顺序建议：**导入数据 → 建数据集 → 训练（带模型池复用）→ 评估 → 风险列表 → 合入前预测**。仓库分析线（添加仓库 → 四步）可另行演示，两半链路的关系见第 7.4 节的口径。

### 6.1 公开数据集导入（数据集页，Member/Admin）

数据集页折叠区「导入外部数据」：选许可声明 → 选文件（CSV/JSONL，UTF-8）→ 系统读表头按列名自动匹配（身份列兼容 repo/sha/time/bug 等常见别名）→ 核对映射下拉 → 提交。必须映射：仓库名、提交编号、事件时间（整数秒）、标签（0/1 或 True/False）、12 个数值特征（la～asexp）；修复标志列可选，不映射按「未提供」展示。Admin 还能填服务器本地路径，点「读取文件列」走同一套映射确认。

- 数字例子：一份 60 行 CSV 导入成功 → 资产编号 64 位哈希 → 建两分区数据集 46 条样本 → 训练报告 `calibration_partition="train"`。
- 幂等保证：同文件同映射同许可重复导入返回同一资产编号，不产生副本；换映射/许可则是新资产。上限 20,000 行 / 32 MB。
- 数据诚实：导入标签只是「文件里声明的」，摘要写 `user_declared_import_label`；系统不承诺来源数据的质量认证。

### 6.2 建数据集（比例自选）

选资产 → 填训练/验证/测试三个百分比（总和 100、训练/测试非 0、验证可为 0）→ 生成。切分按事件时间先后（防泄漏：后面的提交不许影响前面的特征）。验证比例填 0 时不切验证分区，训练会用训练区前后两段校准定门槛并如实标注「样本内」。

### 6.3 训练与模型池复用（训练页）

选数据集、插件（LR/RF）、参数、随机种子，勾选指标与形式（默认全选、LR 标准化 / RF 原始值）。「模型参数从哪里来」三选一：

| 选项 | 行为 | 适用 |
|---|---|---|
| 从零训练 | 每次重新拟合参数 | 默认，最直白 |
| 复用池中模型 | 按当前插件/参数/指标/形式实时过滤池条目，显式挑一个 | 契约不符会报错而不是硬套 |
| 自动匹配 | 按同一四元组规则找池条目，找不到就自动从零训练并在报告注明 | 能省则省，不用先查池 |

比喻：复用相当于**借了"做题经验"（模型参数），但考试题目（标准化、校准、门槛）还是每次用新数据自己做**——经验可以借，考试不能替考，所以复用的评估口径与从零训练完全一致、可对比。复用来源会写进报告（`reused_from`），详情页能看到并跳回来源运行。

预置基线（LR/RF 默认配置，第 3 节已说明注册方式）与「把某次成功运行加入池」并存；池条目是密封工件（哈希校验），被篡改或移除后训练会失败而不是静默复用。

### 6.4 评估与风险列表

训练结果页看：判定门槛（概率超过就算"可能引入缺陷"）、各分区指标表（类别不平衡下看 PR-AUC 与 PofB20，不用准确率）、校准方式（有验证区用验证区，没有用训练区后段并标样本内）。下载 probabilities.csv 展示产物。风险页对已注册运行做逐提交排序，三档等级（高 ≥ 门槛，中 ≥ 一半）。

### 6.5 同类修复参考（仓库详情与预测结果两处入口）

仓库详情页选中某条提交时，文件列表下方出现「同类修复参考」面板：同一仓库真实存在过的修复提交按「触及文件重叠、改动特征距离、证据把握」排序，点参考编号可以跳到那条修复提交。合入前预测的结果下方也有同一面板，检索对象与这次预测的候选改动完全一致。面板声明这些参考「是同类缺陷的修法示例，不是对当前缺陷的根因结论」，检索范围包括时间上晚于目标提交的修复（参考是检索材料，不参与训练）。没有修复历史时明确显示空状态，不会拿别的仓库数据顶替。

### 6.6 合入前预测

选仓库、base、candidate 提交 → 用已注册模型出概率与解释。定位一句话：**用于安排审查顺序，不是自动合并或拒绝的结论**。

### 6.6 演示口径红线

不能说：仓库提交已接进训练数据集；模型效果代表真实缺陷预测能力；预测结果等于根因结论；缺陷类型已经能区分。被问数据来源就讲清楚「仓库分析线真实跑通，模型线用公开研究基准训练，纵向接入是后续工作」。

## 7. 关键机制问答（评审追问）

### 7.1 打标签怎么做的

对每个候选修复提交，取父版本里被删掉的代码行，对父版本跑逐行 `git blame` 找出最早引入该行的提交（blamed_sha），校验行内容哈希防 blame 错位，把 blamed_sha 标为 candidate_buggy。四道门槛过不了的标 unknown 并写原因：被 blame 提交在解析窗口外、时间晚于修复提交（时间倒置）、不是父版本祖先、文件不可追。SZZ 只产 candidate_buggy 或 unknown，**从不产 clean**——追查不到不等于没有缺陷。

### 7.2 14 维特征防泄漏

特征 = 本次改动（7 个：LA/LD/NF/ND/NS/LT/Entropy）+ 历史经验（6 个：EXP/REXP/SEXP/NDEV/AGE/NUC）+ FIX。铁律是时间因果：任何晚于提交时间才知道的信息不许用到该提交上——历史特征只由严格更早的祖先计算；v1 的 FIX 因修复判定天然晚于提交而恒缺失，v2 改从提交说明文本判定（提交那一刻就存在，天然合规）。算不出的指标留空写原因，绝不填 0、绝不插补。

### 7.3 标签成熟度

每张标签带可知时间（label_available_at），训练只用某个时刻之前已经成熟的标签，晚到的不许回填——数据集按时间切分时靠它过滤，保证"当时能知道的才进当时"。

### 7.4 两半链路

仓库分析线（添加仓库 → 四步）从头到尾真实跑通；模型线（数据集 → 训练 → 预测）也真实跑通，但数据起点是公开研究基准（内置 ApacheJIT 或用户导入），不是你自己仓库的提交。把仓库样本纵向接入数据集是后续工作。

## 8. 测试与验收命令

从项目根目录执行。**C 盘空间不足时先设临时目录到 D 盘**（仓库存储预检要 6 GiB 空闲）：

```powershell
# 前端单元测试
Push-Location apps/web; npm run test -- --run; Pop-Location
# 后端内核测试（不需 MySQL）
.\.venv\Scripts\python.exe -m pytest -m 'not integration and not runtime' -q
# 后端应用测试（真实 MySQL/Redis，需先起 compose 栈）
$env:TMP = 'D:\temp-dg'; $env:TEMP = 'D:\temp-dg'
.\.venv\Scripts\python.exe -m pytest -q
Remove-Item Env:TMP, Env:TEMP
# 规格与契约（改 API 后必须先 --export 重导出再检查）
.\.venv\Scripts\python.exe -m scripts.check_contracts --export
openspec validate --all --strict
# 代码风格
.\.venv\Scripts\ruff.exe check .
```

测试证据保存在 Git 忽略的 `runtime/acceptance/`：后端 JUnit（backend-integration.xml）、前端 JUnit（web-unit.xml）、浏览器报告等；按运行批次留存，不覆盖首次失败证据。runtime 测试（`DG_RUN_RUNTIME_TESTS=1`）会停止/恢复 Redis、Worker 并强杀进程，只对本项目专用开发环境执行。

## 9. 常见错误码速查

| 错误码 | 一句话含义 |
|---|---|
| `REPOSITORY_STORAGE_LOW` | 磁盘剩余低于预检下限（6 GiB），清空间或把临时目录指到 D 盘 |
| `SYSTEM_DEPENDENCY_UNAVAILABLE` | MySQL/Redis 不可达或迁移版本不符（先 `alembic upgrade head`） |
| `DATASET_IMPORT_COLUMNS_INVALID` | 导入列映射缺身份列或 12 个数值特征，或缺口列名在错误信息里 |
| `MODEL_POOL_CONTRACT_MISMATCH` | 显式复用的池条目与当前训练配置不一致（不回退，需重新选择） |
| `MODEL_POOL_VERSION_CONFLICT` | 池条目是旧代码版本训练的，不能用于本次训练 |
| `MODEL_DATA_DRIFT` | 训练用的数据/分区摘要与记录不一致，重新创建数据集 |
| `TASK_IDEMPOTENCY_CONFLICT` | 同一幂等键下的请求内容不一致，换键或核对请求 |
