# 可靠任务与运行验收

第二十七阶段临时环境增加清卷前安全`task-summary.json`，见[指南](语义残留诊断与验收.md)。独立正常/失败验收均最多采1000个有序任务的ID/根ID/类型/状态/error_code并显式标截断，不采payload/result/message/actor/凭据或原始stderr；父进程15秒/256KiB，原浏览器/任务超时保持。采集/日志失败仍进入自身项目down，并令验收失败；正常wang卷不受影响。摘要仅支持故障定位，具体原因仍须证据，不因最终重跑通过把首轮未知根因记为已解决。

## 代理与TUN环境

项目没有全面禁用TUN。公网仓库的应用解析必须返回真实全球可路由地址，Docker/WSL内部及本机回环通信也须可用；DNS返回198.18等Fake-IP映射时，现有公网校验会正确拒绝。不能为代理兼容放行这类非公网地址，也不能仅凭宿主浏览器可访问就宣称Worker克隆可用。

以Mihomo为例，[官方DNS配置](https://wiki.metacubex.one/config/dns/)把fake-ip/redir-host作为DNS模式，并支持对指定域名不下发Fake-IP；[TUN配置](https://wiki.metacubex.one/config/inbound/tun/)另行控制入站/路由和DNS劫持。因此可保留TUN并采用真实IP的DNS模式或适当过滤规则，最终以应用容器自身解析和真实克隆验收为准，不能推断所有代理客户端/配置均已认证。开发方不自动修改用户的代理、系统DNS、hosts或全局网络。

第二十五阶段首轮应用与指定1.1.1.1查询均返回198.18.0.50；用户调整后应用返回真实公网地址，独立新卷18/18通过，旧失败证据保留。这证明调整后的当次环境可用，未读取用户代理配置，不能据此声称独立验证了TUN开关或某种具体配置。无需为纯离线覆盖/编码探针关闭TUN；后续联网验收仍在运行前核验实际DNS和连接。

可靠任务0002基础与repository.clone/parse/sync/fix/szz/feature保留；第二十一阶段head0010，dataset.build复用outbox/租约/最新尝试/令牌/Owner-Admin，并用500行成员/进度原子批次及最终发布，见 [数据集指南](用途分离数据集与验收.md)。解析/SZZ原细则和历史报告保留；训练/预测仍后续。

## 启动与升级

使用项目 Python 3.11 和已有 `.env`，先启动 MySQL/Redis，再显式迁移；首次使用空库时显式初始化管理员，最后启动完整六组件：

```powershell
$projectPython = (Resolve-Path ./.venv/Scripts/python.exe).Path
$projectDocker = 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
./scripts/Start-Environment.ps1 -Mode services -DockerPath $projectDocker
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectPython -ArgumentList @('-m','alembic','upgrade','head')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectPython -ArgumentList @('-m','packages.auth.bootstrap')
./scripts/Start-Environment.ps1 -Mode full -DockerPath $projectDocker
```

具体启动参数以 [工程说明](工程启动与验收.md) 为准。完整组件为 MySQL、Redis、API、Web、Celery Worker 和独立 scheduler。已有认证数据升级时保留，不删除原开发卷。迁移及初始化也可使用 Compose 的 `maintenance` profile 中的 `migrate`、`bootstrap` 服务；初始化密码只传入初始化服务。

`0002_tasks` 新增 `async_task`、`task_outbox`。任务、outbox、审计同事务提交，数据库约束包含幂等唯一键、单个直接 successor、外键、状态/进度/计数及 JSON 大小限制。迁移 SQL 固定于迁移文件，不依赖未来 ORM 的变化。非空任务或 outbox 拒绝回退至 `0001_auth`；回退至 base 会先检查认证/审计数据，避免 MySQL DDL 隐式提交导致先删任务表再拒绝认证回滚。开发库已有审计，不用于执行破坏性回滚，回滚验收使用测试独立库。

## 接口与权限

| API | 行为 | 权限 |
|---|---|---|
| A35 `POST /api/v1/tasks/diagnostic` | body 为 `duration_seconds`，严格整数 0～30，默认 1；返回 202 | Member/Admin；仅 development/test 注册 |
| A29 `GET /api/v1/tasks/{id}` | 任务详情与安全错误、健康状态 | 已认证的 Viewer/Member/Admin |
| A30 `GET /api/v1/tasks` | 分页、状态过滤、稳定排序 | 已认证的 Viewer/Member/Admin |
| A31 `POST /api/v1/tasks/{id}/cancel` | queued 取消 204，running 请求协作取消 202；重复 cancelled 返回 204 | 创建者或 Admin，Viewer 拒绝 |
| A32 `POST /api/v1/tasks/{id}/retry` | failed/cancelled 创建唯一直接 successor，返回 202 | 创建者或 Admin，Viewer 拒绝 |

创建及重试必须带 `Idempotency-Key`（1～128 个可见 ASCII 字符，无空格）。同作用域、同键同载荷复用已有任务，返回其**当前状态**；同键异载荷返回 409。并发不同键重试同一个父任务只允许一个 successor，其他请求 409。诊断任务不接受 URL、仓库地址、代码或任意命令。详情不返回执行令牌、投递令牌、内部载荷和载荷哈希。production 不提供诊断创建路由，使用已有 UUID 查询/取消路由不会使该入口返回 405。

状态为 queued → running → succeeded/failed，取消可经过 cancel_requested → cancelled。取消与成功并发时由数据库锁、有效执行令牌决定先提交的合法状态，不覆盖终态。用户权限在写事务中重新检查，审计记录真实操作人；重试保留 root/retry_of 链。

## 投递、执行与恢复

- scheduler 每秒轮询 outbox，短事务使用 `FOR UPDATE SKIP LOCKED` 领取投递令牌/租约，释放事务后联系 Redis，再以有效令牌写回。消息只含任务 UUID，队列为 `defectguard`。
- 默认投递租约 30 秒、最多 8 次；失败退避为 5 秒起指数增长、封顶 60 秒。超限标记 dead，仍 queued 的任务变为 `TASK_DISPATCH_FAILED`。发后写回失败允许补投，依靠 Worker 的数据库领取消除重复执行。
- Worker 默认执行租约 45 秒，每 10 秒心跳；领取、进度、成功、取消均检查数据库 UTC 时间、状态、令牌和未过期租约。重复消息、已终结任务和旧令牌不获得执行权。
- scheduler 的协调器默认每 15 秒检查过期任务。queued 默认 600 秒未被领取则 `TASK_QUEUE_TIMEOUT`；running 租约过期则 `TASK_LEASE_EXPIRED` 并最多自动生成 3 个后继；cancel_requested 租约过期直接 cancelled。队列超时和投递失败不自动创建后继，用户可手动重试。
- Redis 故障保留数据库已接受任务；投递失败后本轮停止联系 broker，使恢复协调仍可执行。Worker 数据库故障不写入成功状态，由租约到期恢复。日志使用安全错误，不输出凭据或驱动明文。

所有时间参数可通过对应 `DG_*` 配置调整，心跳必须小于执行租约。当前是本机单 Worker 并发、单 scheduler 部署；空间增长不等于内存增加，暂不提高并发。锁和租约参考 [MySQL SELECT](https://dev.mysql.com/doc/refman/8.4/en/select.html)，消息确认配置参考 [Celery 配置](https://docs.celeryq.dev/en/stable/userguide/configuration.html)。

## 可复现验收

日常单元/独立 MySQL 集成测试：

```powershell
$projectPython = (Resolve-Path ./.venv/Scripts/python.exe).Path
./scripts/Invoke-ProjectCommand.ps1 -FilePath $projectPython -ArgumentList @('-m','pytest','-q')
```

真实组件故障测试需要完整本机开发环境、管理员初始化及空闲服务，设置进程级 `DG_RUN_RUNTIME_TESTS=1`、`DG_DOCKER_EXE` 为本机 Docker 路径后运行 `tests/test_tasks_runtime.py`。测试会停止/重启本项目 Redis/Worker/scheduler，并强制退出 Worker；只在专用本机开发环境执行，不对团队或生产环境运行。测试创建独有诊断任务，保留审计，不清空开发数据库。普通 pytest 默认跳过这些显式选择的破坏组件测试。

完整独立新环境检查：

```powershell
./scripts/Test-FreshEnvironment.ps1 -Rebuild
```

该脚本生成独立随机配置、不同端口、唯一 Compose 项目、新 MySQL/Redis 卷；`-Rebuild` 执行无缓存 API/Web 构建。验证升级、重复初始化、六组件健康、真实 HTTP 登录/任务创建/幂等/执行/refresh/logout。结束时仅删除脚本自己创建的临时项目卷，保留 `wang` 开发卷；结果和忽略的本机配置在 `runtime/fresh/`。重复验收可不带 `-Rebuild` 复用已构建镜像，每次仍使用新配置和新卷。
