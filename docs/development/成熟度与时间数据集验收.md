## 标签与时间

默认观察窗 W=90天，可预声明1～3650天；它是工程政策，不是已完成真实项目缺陷延迟分布分析的结论。不得观察测试结果后调窗或调整切分边界以凑齐类别。

正例须来自人工确认且复核 revision/证据仍匹配的完整 SZZ 轮次，blame 指向严格祖先，时间一致。候选分数不能直接变成确定标签。clean 必须有完整历史轮次覆盖提交后的整个 W，且没有未解决候选、复核冲突、Issue 不可用、内容不完整或不完整追溯。近期窗口、未来事件、merge、解析或文件不支持等保守保持 Unknown；Unknown 不进入训练，缺失值不置零。

观察覆盖以与接受 HEAD/private snapshot 匹配的真实 clone/sync 成功任务 `started_at` 为保守的新鲜度下界，不能使用今天 SZZ 的完成时间代替旧快照观测时间。证据可用时间至少为完整 Fix/SZZ 成功发布和相关证据时间的最大值。事后执行完整历史分析不能证明当年的 clean 已经可知；历史数据须保留当时实际发布的多轮完整观察，禁止补造时间。

内核按提交事件时间分组，以 SHA 稳定排序，预先确定约70/15/15切分。同一事件时间组不跨集合，先确定边界再剔除晚到标签：train 的可用时间严格早于 validation 首个事件，validation 严格早于 test 首个事件，test 不晚于快照 T。保留剔除 SHA 和原因，不因缺类重新移动边界。

每个集合均需 buggy/clean 两类；少于三个事件组、任一集合缺类、train 任一特征全缺失都会拒绝构建。原始14维值及缺失原因保留；类权重 N/(2*Nclass) 仅取 train。median/标准化和类权重的训练约束写入不可变合同，当前 `fitted=false`，尚未实际填充、缩放或训练。合成成功用例只能验证算法合同，不能证明真实数据或模型精度合格。

## 只读核验

先启动环境，用项目 Python；本机 CLI 不新增在线权限接口。轮次 ID 可重复传参以选取不同历史轮次，不能选同一 ID 两次。T 默认数据库 UTC 当前时间，指定值须带 UTC offset，未来 T 拒绝。

```powershell
& scripts/Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ExpectedGrowthGiB 0.25 -ArgumentList @('-m','scripts.audit_dataset','--repository-id','仓库UUID','--feature-run-id','完整特征轮次UUID','--szz-run-id','完整SZZ轮次UUID','--window-days','90')
```

CLI 仅输出汇总，不输出凭据、private storage、代码正文或完整逐提交标签。退出0代表可构建，2代表样本不足，3代表输入/来源/依赖拒绝。汇总和 JUnit 重定向到 D 盘忽略的 runtime/acceptance，不提交仓库。

来源必须是当前接受快照上的完整 historical 特征轮次，以及兼容算法/解析版本的完整 SZZ/Fix 轮次。读取使用当前共享 locking read；验证冻结输入、证据、质量摘要、实际成功任务和链接序号，不改任何来源表或旧结果。MySQL JSON 的浮点质量统计允许1e-12相对/绝对舍入误差，计数、键和缺失原因精确核对。复核变化保留 Unknown 冲突，而非重写旧 SZZ。

冻结合同绑定源摘要、实际原始向量、完整轮次输出、版本和源码摘要、窗口、T、边界、未知及剔除原因。canonical JSON 的访问器返回副本；改变输入或政策产生新内容摘要，不修改旧对象。原有 Kamei/SZZ 计算源码与摘要保持。

适配器每次最多32轮、32MiB序列化输入，读取及内核分别有30秒监督；每次容量检查预计256MiB增长另保留2GiB紧急余量。保护线不等于无限规模保证，扩大真实样本前要测 CPU/内存/数据库耗时。所有可控新增使用 D；不足停止告知，不转 C，不自动 prune。
