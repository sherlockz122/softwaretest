# 认证与数据库迁移

第三阶段在个人 `wang` 实现 A01～A04 和认证基础；任务、用户管理接口和登录页面仍按后续计划开发。部署前必须先运行迁移。API 启动与 readiness 要求数据库版本恰为 `0001_auth`，Worker 健康检查也验证此版本。不要用手工建表或 `alembic stamp` 绕过迁移。

## 初始化与日常启动

以下命令从项目根目录运行。本机 Python、Docker、缓存和数据位置沿用 [工程启动与验收](工程启动与验收.md)。

```powershell
# 新环境：必须自行指定应用管理员用户名；生成随机密码但不显示。
# 已有 .env 时此命令拒绝覆盖。
& .\scripts\New-LocalConfig.ps1 -BootstrapUsername 'your_admin_name'
& .\scripts\Start-Environment.ps1 -DockerPath 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ArgumentList @('-m','alembic','upgrade','head')
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ArgumentList @('-m','packages.auth.bootstrap')
& .\scripts\Start-Environment.ps1 -Mode full -Build -DockerPath 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
```

已有 `.env` 需要在本地编辑器中显式填写 `DG_BOOTSTRAP_USERNAME` 和 `DG_BOOTSTRAP_PASSWORD`，不要覆盖已有数据库、Redis 或签名秘密。用户名为 1～64 个 ASCII 字母、数字、下划线、点、短横线，统一小写；密码 12～1024 字符且不隐式去空白。seed 命令创建活动 Admin 并留审计；相同活动 Admin 已存在时不修改密码或再次留初始化审计，账号禁用/角色冲突时拒绝。常规 API 启动不执行 seed，也不需要初始化密码。修改 `.env` 密码不会重置已经保存的密码哈希。

本机本阶段已明确创建应用账号 `wang-admin`，随机密码只位于 Git 忽略的根目录 `.env`；不在聊天、报告或日志中输出。它与 Windows 账号无关。生产初始化需另行提供受控秘密与 HTTPS 部署，不使用本机配置。

迁移按批次拆分：`0001_auth` 创建 `user`、`auth_session`、`operation_log`；`async_task/task_outbox` 在下一阶段创建。UUID、哈希、UTC 微秒时间、索引、唯一键、角色/布尔/generation CHECK 和 RESTRICT 外键由真实 MySQL 验收。密码为 Argon2id，参数 memory=19456 KiB、time=2、parallelism=1；refresh/CSRF 只保存 SHA-256。

## 接口使用

开发 OpenAPI 为 `http://127.0.0.1:18000/api/docs`。前端完整模式通过 `http://127.0.0.1:18080/api` 同源代理；原生 Vite 为 `http://127.0.0.1:5173`。完整 Compose 明确采用前者 Origin，原生 API 使用 `.env` 中后者 Origin，禁止通配符或任意 Origin。

| 操作 | 请求 | 响应与约束 |
|---|---|---|
| 登录 | `POST /api/v1/auth/login`，JSON username/password | 201，access/CSRF/user；refresh 仅 HttpOnly cookie |
| 当前用户 | `GET /api/v1/users/me`，Bearer access | 200，id/username/role；每次查 DB 中会话、活动状态与最新角色 |
| 刷新 | `POST /api/v1/auth/refresh`，cookie + X-CSRF-Token | 200，轮转 refresh 与 CSRF；旧 refresh 401；并发只有一次成功 |
| 退出 | `POST /api/v1/auth/logout`，cookie + X-CSRF-Token | 204，撤销会话并清 cookie；现有 access 随即失效 |

access 默认最长 900 秒，cookie Max-Age 和 access 到期均不超出 session 剩余绝对寿命；session 默认 7 天，刷新不延长。JWT 固定 HS256、issuer=defectguard、audience=defectguard-web，必须包含 sub/sid/iat/exp/iss/aud。开发/test 的 loopback HTTP 可不带 Secure，HTTPS 必带 Secure，production HTTP 拒绝签发；尚未验收生产代理/证书部署。

cookie 路径 `/api/v1/auth`、SameSite=Strict。刷新/退出即使无 Origin 也要求 CSRF；存在 Origin 时必须精确匹配。客户端把 access/CSRF 留在内存，页面刷新后先重新登录；不把 refresh 写入 localStorage。当前仅 API 可用，登录页面待开发。

错误用户/密码/禁用统一 401；缺少/无效 access 401，角色不足 403，CSRF/Origin 403，登录媒体类型不符 415、其他输入不符 422，production HTTP 400。Redis Lua 对用户名和 IP 分别执行默认 5 次/60 秒限制；超限 429（Retry-After: 60），Redis 不可用返回 503，不退回进程内计数。代理部署前须评审真实客户端 IP 获取方式；目前依据直接连接来源，不信任任意转发头。

成功初始化/登录/刷新/退出与对应 DB 写入同事务留审计；审计失败不签发 cookie、不提交会话变更。错误响应不回显密码、令牌或驱动细节。角色/归属 helper 已验收，实际任务接口的 Viewer/Member/Admin 权限将在下一阶段接入；当前不能宣称完整 SEC-RBAC 或业务 E2E 已完成。

## 验收与回滚

`tests/test_auth.py` 在本机 MySQL 新建随机前缀 `dg_stage3_test_*` 临时库，限制只在本地 development/test 执行，给专用应用账号授予该库权限，结束撤销此库授权并删除该临时库。当前开发库与已有表不用于破坏性回滚。共享 Redis 测试键独立随机命名，60 秒 TTL，不执行全局 flush。完整 HTTP 测试显式设置 `DG_RUN_RUNTIME_TESTS=1`，使用本地显式 Admin，保留正常审计和已撤销会话。

`alembic downgrade base` 只允许三张认证表均为空；任何认证/审计数据存在时拒绝删除。本机已 seed，不能用 downgrade 删除本机账号；需要回退代码时先评审备份和兼容迁移。MySQL DDL 有隐式提交，数据库版本检查不能替代备份或修复中断迁移的审阅。
