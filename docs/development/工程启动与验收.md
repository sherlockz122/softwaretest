# 工程启动与验收

第二批已实现 `bootstrap-application` 第 1 组工程基础；第三批完成第 2 组认证迁移、A01～A04 和显式账号初始化，详见 [认证与数据库迁移](认证与数据库迁移.md)。第四阶段实现第 3 组可靠任务和任务权限，并增加独立新环境验收，详见 [可靠任务与运行验收](可靠任务与运行验收.md)。操作页面和完整浏览器 E2E 仍待第 4 组，Worker ping 不替代业务执行验收。

## 1 依赖与本机位置

需要 Python 3.11、uv、Node 22.12+（本机 24.13.0）、PowerShell 7.2+ 和运行中的 Docker Desktop。`uv.lock` 锁定 Python 依赖与哈希，`apps/web/package-lock.json` 锁定前端依赖。Compose 和 Dockerfile 中基础镜像固定 digest；API 和 Worker 共用同一应用镜像。仓库不保存依赖目录、镜像、缓存或密钥。

本机 uv 位于 `D:\Develop\uv\bin\uv.exe`，Python 安装和 `.venv` 见 [Python说明](Python环境使用.md)，Docker CLI 为 `D:\Develop\DockerDesktop\resources\bin\docker.exe`，Node/npm 位于既有 `C:\nvm4w\nodejs`。不重装或迁移 Node；新增 node_modules/npm 缓存仍在 D 盘。本机 Docker/WSL 数据已在 D 盘，其他机器必须先确认自己的 Docker 数据盘。

先测量并满足 [存储预算](存储预算与命令使用.md)。新机器选择有空间的项目所在盘；虚拟环境生成在项目根目录，而非复制本机 `.venv`。

```powershell
& .\scripts\Measure-ProjectStorage.ps1
# 仅首次执行；存在 .env 会拒绝覆盖。生成的密钥不显示、不上传。
& .\scripts\New-LocalConfig.ps1
# 本机设置仅在当前 PowerShell 进程生效，保留系统默认 Python 3.13。
$env:UV_PYTHON_INSTALL_DIR = 'D:\Develop\Python'
$env:UV_PYTHON_DOWNLOADS = 'never'
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath 'D:\Develop\uv\bin\uv.exe' -ExpectedGrowthGiB 0.5 -ArgumentList @('sync','--frozen','--python','D:\Develop\Python\cpython-3.11.16-windows-x86_64-none\python.exe')
Push-Location apps/web
try {
  & ..\..\scripts\Invoke-ProjectCommand.ps1 -FilePath 'C:\nvm4w\nodejs\npm.cmd' -ExpectedGrowthGiB 0.6 -ArgumentList @('ci','--no-fund')
} finally { Pop-Location }
```

`.env.example` 中秘密为空，不能直接启动。生成器写入四个独立 256-bit 随机秘密；已有 `.env` 由使用者审阅，不自动覆盖。不要在聊天、截图、提交或 `docker compose config` 完整输出中暴露秘密，检查 Compose 时使用 `config --quiet`。这只是本地开发配置，生产部署需要单独的密钥管理流程。

## 2 日常开发与完整演示

所有命令从项目根目录执行，端口固定绑定 loopback，冲突时退出，不接管已有进程。容器/卷使用 `defectguard-wang` 项目命名，不共用其他项目数据。

```powershell
# 首轮/日常：只启 MySQL、Redis（首次自动下载固定镜像）
& .\scripts\Start-Environment.ps1 -DockerPath 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
# 首次/迁移变更后，API 启动前执行；管理员按认证说明显式初始化
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ArgumentList @('-m','alembic','upgrade','head')
# 当前窗口运行 API；先启动上述基础服务
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ArgumentList @('-m','uvicorn','apps.api.main:app','--host','127.0.0.1','--port','18000','--no-access-log')
```

另一个 PowerShell 窗口进入 `apps/web`，用包装器执行 `npm run dev`；浏览器访问 `http://127.0.0.1:5173`。Vite 将 `/api` 代理到 API。

Celery 官方不支持原生 Windows，因此本机 Worker 使用 Linux 容器（不是以 solo 模式绕过此限制）。需要 Worker 时：

```powershell
& .\scripts\Start-Environment.ps1 -Mode worker -Build -DockerPath 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
```

完整六组件路径（需先停止本项目原生 API，以释放 18000）：

```powershell
& .\scripts\Start-Environment.ps1 -Mode full -Build -DockerPath 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
```

浏览器访问 `http://127.0.0.1:18080`；API 地址 `http://127.0.0.1:18000`。Nginx 同源代理 `/api`，开发 OpenAPI 为 `/api/openapi.json`。MySQL 使用 13306，Redis 使用 16379，均带独立密码。完整路径不需要在宿主机安装 nginx 或第二套 Python。

Docker token 请求偶发超时时，可先用包装器 `docker pull` 同一固定 digest 的官方镜像后重试；不修改系统 DNS、关闭主机校验或换未知镜像。日常只启动基础服务，后续 Worker 可按需启用；完整模式不需一直运行。

## 3 当前健康与错误契约

- `GET /api/v1/health`：进程存活，200 `{"status":"ok"}`，无需登录。
- `GET /api/v1/health/ready`：MySQL `SELECT 1`、迁移版本恰为 `0002_tasks` 与 Redis PING 均成功则 200；不可用时 503、`SYSTEM_DEPENDENCY_UNAVAILABLE`。API 初次启动版本不符即失败；运行中版本改变则 readiness 503。任务实际执行另验收 Worker、scheduler 和任务状态；API ready 不代表任务立即被消费。
- 响应含 UUID `X-Request-ID`；输入是合法 UUID 时沿用，否则生成。统一错误 `{code,message,request_id}`；404/405/422/500 不回传输入值、驱动异常、SQL、路径或 secret。
- 缺失/空/过短数据库或 Redis 密码、签名密钥，进程初始化即失败，配置错误仅列字段名。签名密钥至少 32 字符，服务密码至少 12；名称和端口可有无秘密默认值。
- API 就绪不代表 Worker 工作正常。Worker 容器健康检查另要求自己的 Celery ping 加 MySQL/Redis 连接；已注册受限诊断任务，单独的 scheduler 投递 outbox 并协调租约恢复。应用容器使用非 root 用户。
- CORS 使用单个显式前端 Origin，生产关闭 OpenAPI 文档；认证安全接口已验收，任务权限已接入，实际生产 HTTPS 部署待实施。当前只用于 loopback 开发。

## 4 可重复验收和关闭

```powershell
& .venv\Scripts\ruff.exe check .
& .venv\Scripts\ruff.exe format --check apps packages migrations tests
# 单元检查（基础服务可不启动）
& .venv\Scripts\python.exe -m pytest -m 'not integration and not runtime' -q
# 完整环境已启动后：包含真实基础服务、HTTP、Worker、故障及卷持久化
$env:DG_RUN_RUNTIME_TESTS = '1'
$env:DG_DOCKER_EXE = 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
& .venv\Scripts\python.exe -m pytest -q
Remove-Item Env:DG_RUN_RUNTIME_TESTS, Env:DG_DOCKER_EXE
& .\scripts\Test-StorageGuard.ps1
```

runtime 测试显式启用，只对本项目专用开发环境执行，会停止/恢复 Redis、Worker、scheduler，重启数据库、强杀 Worker，并创建诊断任务、审计和少量平台标记。运行前确保无其他待运行任务；不对团队/生产库执行。测试分别记录基础平台与可靠任务证据，不把 ping 当作任务恢复通过。

在 `apps/web` 运行包装器 `npm ci` 和 `npm run build` 复验锁文件重装/构建。验收后可停止本项目完整环境：

```powershell
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath 'D:\Develop\DockerDesktop\resources\bin\docker.exe' -ArgumentList @('compose','--profile','full','stop')
```

stop 保留卷、镜像和缓存，之后再次 `Start-Environment` 即可恢复。不自动执行 `down -v` 或全局 prune；更改数据库密码不会自动更新已初始化卷内账号，必要时须单独评审迁移，不能直接删卷重建。

实现依据：[FastAPI errors](https://fastapi.tiangolo.com/tutorial/handling-errors/)、[Docker startup order](https://docs.docker.com/compose/how-tos/startup-order/)、[uv Docker](https://docs.astral.sh/uv/guides/integration/docker/)、[Celery Windows FAQ](https://docs.celeryq.dev/en/stable/faq.html#does-celery-support-windows)。
