# 安全仓库克隆与验收

第六阶段交付 A07～A09 与 `/repositories` 页面：公开 HTTPS 仓库接入、真实 bare 克隆、默认分支/HEAD/大小及任务状态。提交解析、作者身份、checkpoint、同步和 Fix 尚未交付；“已克隆”只代表保存了 Git 数据。

## 启动与存储

复用现有 `.env`，不要重新生成或覆盖凭据。先确认 Docker 正在运行、项目和 Docker/WSL 数据在 D，预计构建/测试可用空间充足。命令包装器的 ExpectedGrowthGiB 为本次操作的峰值估算；预计增长+2GiB 无法容纳即拒绝，不改用其他盘。

```powershell
# 项目根目录，既有工具路径
$dockerPath = 'D:\Develop\DockerDesktop\resources\bin\docker.exe'
./scripts/Invoke-ProjectCommand.ps1 -FilePath $dockerPath -ExpectedGrowthGiB 2 -ArgumentList @('compose','--profile','full','build','api','web')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $dockerPath -ExpectedGrowthGiB 1 -ArgumentList @('compose','up','-d','--wait','mysql','redis')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $dockerPath -ArgumentList @('compose','--profile','maintenance','run','--rm','migrate')
./scripts/Invoke-ProjectCommand.ps1 -FilePath $dockerPath -ArgumentList @('compose','--profile','full','up','-d','--wait','--wait-timeout','180')
```

普通启动共享 `runtime/repositories` bind mount，位于项目 D 盘；API/Worker 容器路径 `/app/runtime/repositories`。`repository-init` 只初始化专用根和 objects 两层、赋给 UID 10001，不递归修改仓库。不要将 DG_REPOSITORY_DATA_DIR 改到 C。fresh 验收脚本为每次运行配置独立的 `runtime/fresh/<uuid>/repositories`，不得共享开发克隆目录。

默认单仓库上限 2GiB、整体克隆900秒；接收/执行前要求 4GiB预计峰值+2GiB余量。运行检查当前目录和剩余空间，资源超限即终止本次进程树、任务失败并清理本次未发布 UUID 目录。此限制用于保护单项任务，可以在明确容量后配置 DG_REPOSITORY_MAX_BYTES / DG_REPOSITORY_TIMEOUT_SECONDS（Compose 传入）；不是旧项目总空间上限。当前 Worker 并发1，扩大并发前重新估算同时峰值。

Windows Docker bind 的 `disk_usage` 已与宿主 D 盘实测核对；迁移 Docker/挂载方式后必须重新核对，不能用虚拟磁盘的理论空闲替代宿主实际余量。数据、缓存、临时目录、镜像层在 D；现有 C 盘 Node 等工具继续使用，操作系统后台占用不属于项目可控制的写入。

## 使用与排障

访问 `http://127.0.0.1:18080`，登录后打开“仓库目录”。Member/Admin 填最终公开 HTTPS URL，无 token/账号/查询参数；当前只接受 ASCII DNS/IPv4、443，DNS AAAA 可用，IPv6 字面 URL 不支持。GitHub owner/repo 大小写归一，其余服务路径大小写保留。

添加前验证 DNS、TLS、smart HTTP，不跟随任何重定向。接收后返回同事务创建的仓库与任务，页面轮询最新任务。网络未返回时再次提交保留同键；同键改 URL 明确冲突，不同键添加已有 URL 提示已有仓库。Viewer 可以读取目录和详情；任务取消/重试仍要求本人 Member 或 Admin。

克隆不执行 hook、脚本、工作区检出、LFS 或子模块。每次 CONNECT 复核所有 A/AAAA，并直接连接批准 IP，核对实际 peer；TLS 验证原域名。未知 Git 外部 URI 不能改用其它协议/主机。DNS/证书/连接失败拒绝，不能通过关闭 TLS、SSRF 或改成 SSH 绕过。终态失败通过任务页重试，租约失效由协调器创建 successor。

常见码：STORAGE_LOW 先补 D 空间；STORAGE_UNAVAILABLE/UNSAFE 检查专用挂载与 symlink/junction；NOT_PUBLIC_GIT/REDIRECT_REJECTED 检查最终公开地址；DNS/NETWORK_UNAVAILABLE 检查域名与网络/证书；SIZE/TRANSFER/OUTPUT_LIMIT 或 CLONE_TIMEOUT 先评估仓库与预算。均带 REPOSITORY_ 前缀；用 request_id/task_id 排障，错误不回显凭据、Git 输出或本机路径。

数据库事务提交结果不确定时保留尝试目录，避免删除可能已发布的数据。不要手工清理正在运行的尝试；先核对 repository.storage_key 与任务 token/终态，再单独批准孤立数据回收。停止服务保留数据可用 `compose --profile full stop`，日常不要 `down --volumes`。

## 验收与本地证据

`tests/test_repository_safety.py` 验 URL/IP、DNS变化、CONNECT authority/peer、TLS/重定向、容量和进程限制；`tests/test_repositories.py` 在真实独立 MySQL 库中验幂等事务、DDL/降级保护、原生 Git 克隆、取消/恢复及提交不确定性。HTTPS fixture 使用单日测试 CA 和构造器注入，生产没有关闭安全策略的配置；fixture 私钥只在 ignored runtime 临时目录，不提交/导出。

Playwright 包含真实登录→公开 `octocat/Hello-World`→API/outbox/Worker→元数据→重新登录持久读取，并验证响应丢失的幂等重放、私网拒绝、Viewer 和移动端。公开仓库 E2E 需要实际 GitHub HTTPS；网络不可达时必须报告失败，不将模拟结果记为真实 Worker 验收。确定性的本地 HTTPS fixture 不依赖外部网络。

完整本机结果在 `runtime/acceptance/stage6`，保留 JUnit、脱敏日志、截图和 SHA-256 manifest，不上传 Git/CI artifact。运行 `scripts.retain_evidence` 重新建立清单；证据注明验收工作树和最终提交关系。验收 fresh 项目只清理其自身服务/卷，目录留作定位；日常开发数据保留。
