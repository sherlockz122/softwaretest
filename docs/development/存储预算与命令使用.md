# 存储预算与命令使用

2026-10-09 本机实测：C 盘剩余约 47.48 GiB，D 盘约 12.12 GiB。GiB 按 1024³ 字节计算。该快照会随其他软件使用变化，操作前重新检查。

当前容量可以开始框架和小样本开发。框架阶段将**新增占用目标控制在 4 GiB 内、D 盘至少保留 6 GiB**；这些是预算和开工门槛，不是已测出的安装大小，也不是文件系统硬配额。现有 Python、Docker 和 WSL 安装不计入新增预算。安装或镜像实际超过预算时暂停扩大范围，再调整存储，不自动切到 C 盘。

| 新增内容 | 预算目标 |
|---|---:|
| Python/Web 依赖及前端依赖 | 1.5 GiB |
| MySQL/Redis 镜像和框架构建 | 1.5 GiB |
| 小样本、数据库和运行日志 | 0.5 GiB |
| 下载缓存、临时文件和余量 | 0.5 GiB |

本批只增加文本和脚本，不安装应用依赖、不拉取镜像、不克隆实验仓库。下一批先让 API/Worker 共享 Python 依赖，在宿主机运行应用，仅以容器运行 MySQL/Redis；完整 Compose 演示再使用共用应用镜像。暂不下载 PyTorch/Transformer 权重或大数据集。后续八模型、全量历史和模型工件可能明显超过现有余量，开始前必须重新估算或扩容 D 盘。

项目 `.venv`、数据、运行工件位于项目所在 D 盘，Docker/WSL 数据已位于 `D:\Develop\DockerData`。Docker 虚拟磁盘文件长度不等于实际分配空间或最大容量；其所在卷仍可能被其他 Docker 工作负载填满。Windows、Docker Desktop 的配置和少量系统临时活动仍可能写 C 盘，不能承诺 C 盘零写入。这里控制的是项目大文件和常用下载缓存，不迁移用户配置或修改系统目录。

## 执行方式

从项目根目录使用 PowerShell。先读取只读容量报告：

```powershell
& .\scripts\Measure-ProjectStorage.ps1
```

`project_logical_bytes` 包括 `.git`、`.venv` 和项目运行文件，跳过重解析点；不是磁盘分配量，不包含项目外的 Docker 数据或 uv 安装。报告只扫描项目，不扫描或删除其他文件。

通过包装脚本运行项目命令，例如验证解释器或预留 1 GiB 安装预算：

```powershell
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ArgumentList @('--version')
& .\scripts\Invoke-ProjectCommand.ps1 -FilePath "$PWD\.venv\Scripts\python.exe" -ExpectedGrowthGiB 1 -ArgumentList @('-m','pip','install','-r','requirements.txt')
```

第二条是未来有依赖文件时的使用示例，本批没有 requirements.txt，不能现在执行。uv/Node/npm 同样传已验证的绝对可执行文件路径，参数传数组，不拼接 shell 命令。

包装脚本在启动前要求 `剩余空间 >= ReserveGiB + ExpectedGrowthGiB`，ReserveGiB 默认且最低为 6；不满足即拒绝执行。它在当前进程临时设置 TEMP/TMP、pip/uv/npm 缓存和 HF_HOME/TORCH_HOME 为 `runtime/` 下的目录，命令成功、非零退出或异常时均恢复原值。全局 PATH、用户/系统环境变量保持原状。直接绕开包装脚本执行命令不具有这些保护；第三方工具也可能不遵守缓存变量。

它只做启动前检查，不在下载中强制限额、不限制其他程序，不会删除缓存或 Docker 资源，也不会自动迁移到 C 盘。下一批任务 4.2 将把同样的门槛接入具体 pull/build/采集入口；长任务还需执行过程中的容量检查。

## 小规模运行限制（下一批接入）

- 首轮只运行一个实验仓库，解析上限 1000 个提交；克隆工作目录先以 250 MiB 为上限，超过即终止并提供安全错误。提交数不能约束 Git 克隆体积，两者必须分别检查。
- 容器日志使用 json-file 的 `max-size=10m`、`max-file=3`；宿主机日志也需轮转，避免无限增长。
- 实验工件只保留显式选择的运行，不默认保留所有重跑副本；删除由用户或已明确授权的管理流程执行。
- 每次安装、pull/build 和采集之前检查余量、预计增量及 Docker 用量。若实际增长逼近 4 GiB 预算或 D 盘余量低于 6 GiB，停止增加负载并重新规划。

缓存配置依据：[uv cache](https://docs.astral.sh/uv/concepts/cache/)、[npm environment variables](https://docs.npmjs.com/cli/v11/using-npm/config#environment-variables)。Docker 数据位置及设置依据：[Docker WSL](https://docs.docker.com/desktop/features/wsl/)、[Docker settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/)。
