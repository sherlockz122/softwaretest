# 语义覆盖窗口探针与验收

第二十六阶段实施`probe-semantic-hunk-coverage`，承接第二十五阶段原生读取基线。当前为离线工程探针，不拟合分类器、预测旧test或提升产品资格；实际结果见[阶段报告](../reports/2026-10-28-第二十六阶段语义覆盖窗口报告.md)。

## 固定人口与策略

复用旧v2的660条train/validation上下文、固定AMQ13def043及既有安全CodeBERT。按hunk数1/2～8/9～32/33～128/129～256分层，train配额10/24/20/9/1，validation6/14/8/3/1；层内SHA升序、总计64/32。只依身份/分区/hunk数选样，先封存声明，不读标签或模型结果作选择，不替换难例。声明保留全部660身份/分层与旧覆盖影响；这是诊断样本，不是代表性Gold或噪声率抽样。

新模块从绑定Git blob核验身份/长度，精确重建所选v2的hunk、文本和坐标。独立反例已证明直接扩大贪心预算可能挤掉旧已选行；候选先保留所有v2整行，再按原hunk轮转消费新增预算，每代码角色固定1008个实际token。基线与扩展各最多512次预算检查，半径3、最多256hunk及每hunk32候选行保持；旧版252-token实现及工件不改。

只选真实整行，不碎片化长行冒充覆盖。分别报告至少一个候选整行的hunk代表、全部eligible行、32行截断、完整eligible-hunk以及未代表部分；共享base行的分母是hunk-行关联数，不是去重物理行。base可为未变上下文，以上均不等于全文、完整变更或模型效用。

冻结编码使用CPU4线程、batch8、float32、128-token窗口，代码角色最多8窗口、message保持旧2端点窗口；排除结构和padding，以实际内容token数加权短尾窗口，附4个角色掩码得到3076维。新版本/源码/权重/依赖/人口均绑定；同维度不表示与旧模型兼容。使用独立进程完整重复96条编码，核对所有向量和NPY、成员/覆盖文件；不把时长/元数据字节或本次局部重复当全产品NFR05认证。

## 命令与资源

新增CLI为`python -m scripts.semantic_coverage_probe`，按`select → contexts → encode → encode → compare`执行。每阶段显式给`--inputs --output --result --log`，另给相应`--checkpoint`、`--declaration`、`--source`或`--other`；结果文件必须新建，旧证据不覆盖。选择/比较用项目解释器，需tokenizer/模型的阶段自动进入现有`tools/semantic/.venv`；不安装新权重、不联网执行远端代码。先用`--help`核对参数，冻结源码后才启动正式运行。

输入/上下文和编码预计各2GiB、备份3GiB、验收4GiB临时峰值，均通过项目包装器显式声明。单阶段2700秒、6GiB采样进程树RSS；Git读取共享30秒及原双流上限；父进程身份、容量、日志和退出后总时限均核对。D不足先停，不改用C；2.5GiB是子进程检查的磁盘余量，不是输出大小配额。采样与协作检查不冒充OS硬限额。编码或有时限故障验收期间不并行构建、全树扫描或大备份。

上下文、声明、编码和比较分别封存；保留父目录/许可继承及源码和权重绑定。失败、取消、漂移、非有限值、旧行丢失或重复不精确时保留attempt与日志，禁止记为成功。成功也只支持所选96条局部结论，不关闭全660覆盖、支持/来源/许可、Gold、污染或产品任务门槛；后续须根据真实结果另行预声明全人口验证或修订方案。

## 工作流

独立根回归和隔离CPU反例先通过，再做真实封存探针；之后必要全量后端/真实故障、CPU/前端/全新卷浏览器、锁/审计/静态/规格/合同、镜像源码及无Torch、正常数据模型/旧材料与A/B守卫、备份独立恢复及8项存储守卫。零活动停正常项目保两业务卷；仅wang普通交付，实现CI与最终文档自身SHA CI分别核验。保留6原模型/18工件/3导出、旧test/标签、正式review和readiness。

代理/TUN的验收要求见[运行验收](可靠任务与运行验收.md)：允许可用的TUN配置，应用容器DNS必须返回真实公网地址，实际克隆和本机/容器通信须通过；不为Fake-IP放宽SSRF，也不自动修改用户全局网络。
