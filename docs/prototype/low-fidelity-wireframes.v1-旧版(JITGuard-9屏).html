屏 01 / 09 · 登录
本屏标注
角色：
代码评审员 / 研发团队负责人 / 算法工程师（三类角色共用同一登录入口，登录后按角色进入各自首页）
进入条件：
未持有有效登录态（从未登录或会话已过期），访问任意受保护页面时被拦截并跳转至本屏
本屏主任务：
完成身份认证并建立会话，随后回跳到用户原本想访问的页面
关键控件：
用户名输入框、密码输入框（掩码显示）、「记住我」复选框、登录按钮、统一错误提示区
交互跳转：
登录成功 → 代码评审员进入「屏 07 风险提交列表」；研发团队负责人进入「屏 09 缺陷引入趋势看板」；算法工程师进入「屏 02 仓库接入与管理」。若由拦截跳转而来，则回跳原路径
异常态：
① 用户名或密码错误 → 给出统一提示「用户名或密码错误」，不区分「用户不存在」与「密码错误」，避免账号枚举；两类失败在提示文案与响应耗时上保持一致 ② 连续失败 5 次 → 锁定该账号 10 分钟，提示「账号已锁定，请于 10 分钟后重试」，锁定期间登录按钮与输入框置灰 ③ 未登录直接访问业务页面 → 跳转登录页，并在登录成功后回跳原路径（原查询参数一并保留）

屏 02 / 09 · 仓库接入与管理
本屏标注
角色：
算法工程师（负责仓库接入、采集配置与数据同步）
进入条件：
以算法工程师身份登录后从主导航进入；或从「屏 03 采集任务监控」返回
本屏主任务：
接入待分析的代码仓库（Git 地址 + 缺陷跟踪系统 + 采集时间窗口），并维护已接入仓库的可用状态
关键控件：
仓库名称、仓库地址、平台下拉（GitHub / GitLab / Gitee / 本地路径）、访问凭据（Token）、缺陷跟踪系统下拉（JIRA / GitHub Issues / 无）、缺陷单项目键、采集时间窗口（起始日期 / 结束日期）、排除路径规则、校验连通性按钮、保存并接入按钮；下方仓库列表表格及其行内操作（触发采集 / 编辑配置 / 停用）
交互跳转：
点击「保存并接入」成功 → 提示接入成功并提供「前往采集任务」入口，跳转「屏 03 采集任务监控」；列表行「触发采集」→ 同样跳转屏 03；「编辑配置」→ 就地展开表单或进入本屏编辑态
异常态：
① 地址格式非法（非 Git 协议地址 / 本地路径不存在 / 填写了网页地址）→ 字段级报错且不发起任何网络请求，提交按钮保持禁用 ② Token 失效或无权限 → 返回可读错误（含 HTTP 状态码，如「凭据校验失败：HTTP 401」），数据库不留半成品记录，表单内容保留以便修改后重试 ③ 重复接入同一仓库 → 拒绝保存，并提示已存在仓库的名称与接入时间，提供「查看已有配置」入口

屏 03 / 09 · 采集任务监控
本屏标注
角色：
算法工程师
进入条件：
从「屏 02 仓库接入与管理」点击「触发采集」或「前往采集任务」进入；也可直接进入查看历史任务
本屏主任务：
观察 Git 历史采集与 SZZ 标注任务的运行状态与进度，处理失败任务与被跳过条目
关键控件：
任务列表表格（任务类型 / 目标仓库 / 状态 / 当前阶段 / 进度 / 已处理-总数 / 耗时 / 触发人 / 操作）、四阶段进度条、阶段日志表格（阶段 / 状态 / 消息 / 计数指标）、行内操作：重试、取消、查看跳过清单
交互跳转：
任务完成后 → 提供「查看提交数据」入口跳转「屏 04 提交浏览与数据质量」；「查看跳过清单」→ 弹出或就地展开被跳过/失败的提交明细；「取消」→ 二次确认后终止任务
异常态：
① 同一仓库已有任务运行中 → 拒绝创建新任务，并提示正在运行的任务 ID 与启动时间，提供「查看该任务」入口 ② 任务中断后重试 → 从断点继续（已完成的阶段与已处理的提交范围直接复用），不重复抓取，耗时字段区分本次耗时与累计耗时 ③ 单个提交解析失败 → 不终止整个任务，该提交进入错误清单并计入失败计数，任务继续执行，结束后汇总「成功 / 跳过 / 失败」三项数量

屏 04 / 09 · 提交浏览与数据质量
本屏标注
角色：
算法工程师（研发团队负责人可只读查看，不显示任何写入类按钮）
进入条件：
从「屏 03 采集任务监控」任务完成后的「查看提交数据」入口进入；或从本屏筛选器直接浏览已采集数据
本屏主任务：
浏览采集到的提交明细，核对数据质量（是否修复提交、关联缺陷单、是否被标注为缺陷引入提交 BIC），确认数据可用于建模
关键控件：
筛选器（仓库 / 时间范围 / 作者 / 是否修复提交 / 是否 merge 提交）、提交主表格、右侧「选中提交的文件变更列表」面板、导出按钮
交互跳转：
点击表格行 → 右侧面板加载该提交的文件变更明细（选中行高亮）；点击文件行 → 展示该文件的 diff 摘要占位；「进入样本构建」→ 跳转「屏 05 特征与样本集构建」
异常态：
① 二进制文件与单文件超 5000 行的变更 → 被标记为「已排除」并在数据质量报告中单独计数，不参与特征计算，界面上以灰底 + 排除标签呈现 ② merge 提交（父提交数 ≥ 2）→ 标记为「不参与建模」，但仍保留在提交表中可被检索与查看，导出时该列一并输出标记 ③ 筛选条件无命中 → 表格区显示空状态提示与「清除筛选条件」按钮，右侧面板同步清空并提示未选中提交 ④ 缺陷单关联为空 → 「关联缺陷单」列显示「—」而非空白，避免与「未采集到」混淆
