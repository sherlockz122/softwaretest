一、文档分工说明

低保真原型被拆成两份配套文件，原因是单文件同时承载「界面长什么样」与「什么条件下会出现什么状态」， 会让矩形框过多、读者分不清正常态与条件触发态。分工原则是： 线框图只画正常态，凡是描述「在某种情况下会发生什么」的内容（报错、告警、空态、降级、失败态、其他步骤形态）全部归本文档； 而静态的字段约束与输入提示（无论什么条件都显示给用户的说明）仍留在线框图中。

文件放什么读图顺序
low-fidelity-wireframes.html 10 屏正常态线框：面板 / 表格 / 图表 / 统计卡 / 控件形态；每屏 4 行标注（角色 / 本屏主任务 / 关键控件 / 主要跳转）；静态字段约束与输入提示 先读它，建立信息架构与页面骨架的认知
screen-states.html（本文档） 全部条件触发态、异常、错误码、空态、降级与口径说明；每屏三张内容：前提与归属 / 状态与异常 / 口径说明 再读本文档，逐屏核对每一条状态在什么条件下出现、界面变成什么样
读图约定（线框图中）：实线框 + 白底 → 正常态，这一屏正常呈现的界面；无边框浅底 + 左竖线 → 说明文字（角色 / 主任务 / 关键控件 / 主要跳转），不是界面的一部分。 本文档中：每屏「状态与异常」表的编号 ①②③… 与该屏源标注块「异常态」的编号严格对应；编号后带「补」的行来自该屏的条件报错、告警、空态、条件态块或面板脚注，源标注块中没有对应编号。
