本屏标注
角色：
全部四类角色（代码评审员/开发负责人、算法工程师、团队/质量负责人、平台管理员）共用同一入口；注册与登录匿名可访问（A01/A02），登录后按 role 进入各自可达功能

本屏主任务：
完成注册或身份认证并建立会话，随后回跳到用户原本想访问的页面
关键控件：
登录/注册双 Tab；登录 Tab：用户名、密码、「登录」按钮、行内错误提示区；注册 Tab：用户名、密码、邮箱、「注册」按钮；页脚提示文案
交互跳转：
登录成功 → 按角色回跳原目标页（默认 /repos）；点「注册」Tab → 本屏切换；登出 → token 进 Redis 黑名单后回到本屏
关联用户故事：
US-22 用户与权限管理（P1，3 点，Sprint 2）；接口 A01 注册 / A02 登录 / A03 当前用户信息；数据表 user、operation_log
异常态：
① 用户名或邮箱重复 → HTTP 409 / 错误码 1004，注册 Tab 对应字段标红并提示「用户名或邮箱已存在」； ② 同一 IP 1 分钟内失败登录超过 5 次 → HTTP 429 / 错误码 1003，行内提示「请求过于频繁，请稍后重试」，持续触发则封禁窗口顺延； ③ 未登录访问受保护页面 → 跳转本屏，登录成功后回跳原目标页； ④ 账号被禁用（user.status=0）→ 登录被拒绝，提示「账号已禁用，请联系管理员」。
线框要点｜会话与安全口径： JWT access_token 有效期 2 小时（A02 返回，前端存入 Pinia）；登出后该 token 写入 Redis 黑名单，再用返回 1001；密码 bcrypt 散列存储；RBAC 仅 admin 可删仓库/删模型/管理用户。

屏 02 / 10 · 仓库管理路由 /repos ｜ 模块 M2 ｜ US-01/02/03 ｜ Sprint 1（US-03 为 Sprint 2）
本屏标注

/repos

已登录（JWT）；列表来自 A04，可按 clone_status 过滤

关键控件：

交互跳转：
行点击 → /repos/:id/data（屏 03 数据与特征）；「同步」→ A08 增量同步；「删除」→ A07（仅 admin，普通用户返回 1002）

异常态：
① 非 https / 内网 IP / localhost → 2001（SSRF 拦截），不创建 repository 记录、不发起任何网络请求； ② 同一 URL 已存在（repository.url 唯一约束）→ 2003，提示已存在并回显既有 repo_id； ③ 仓库正在克隆或同参数同步任务已在运行 → 2004，被幂等键 (repo_id, kind, params_hash) 拦截； ④ 克隆超时或认证失败 → 指数退避自动重试 3 次仍失败则 clone_failed 并回显 fail_reason，允许手动重试； ⑤ 列表空态 → 「尚无仓库，请先添加一个 Git 仓库」+ 新增入口。
线框要点｜异步任务口径： 克隆走 Celery io 池；A05 同步段只做「URL 校验 + 落库 + 入队」，随即返回 repo_id 与 task_id；前端以 2s 轮询刷新状态与进度，进入终态后停止轮询；失败按指数退避重试 3 次。
