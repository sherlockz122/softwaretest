# DefectGuard 产品需求规格

## 1 产品定位

DefectGuard 使用项目自身历史数据训练提交级风险模型，为历史质量分析和合入前代码评审提供可解释的风险概率与排序。目标是帮助评审者把有限时间优先投入高风险变更，而不是自动决定是否合并。

## 2 目标用户

| 用户 | 主要任务 | 价值 |
|---|---|---|
| 代码评审员和开发负责人 | 选择优先细审的候选变更 | 风险排序、因素解释、证据下钻 |
| 算法和数据工程成员 | 构建标签、特征、数据集和模型 | 版本化、可复现、防泄漏的流水线 |
| 质量负责人 | 复盘缺陷和风险趋势 | 可追溯的统计、指标和模型表现 |
| 平台管理员 | 管理运行状态和关键权限 | 可观测、可重试、权限隔离和审计 |

用户调研结论在产生匿名化访谈记录前均视为待验证假设，不作为既成事实。

## 3 产品目标与非目标

### 3.1 产品目标

- 完成真实开源仓库从采集到历史风险列表的闭环。
- 支持未合入候选变更的风险预测和解释。
- 实现 SZZ、Kamei 14、两类且总计不少于 8 种模型、两类评估指标、前端看板及工程化证据。
- 使数据版本、标签来源、训练配置、模型工件和预测结果可追溯。
- 建立 User Story、OpenSpec、PR、测试与归档之间的完整证据链。

### 3.2 非目标

- 不证明某提交一定会或不会产生缺陷。
- 不自动替代评审或直接阻止合并。
- 首期不承诺 SaaS 多租户、移动端、跨语言统一模型或生产级高可用。
- 不把统计贡献解释描述为缺陷的因果根因。

## 4 核心业务链路

### 4.1 历史数据链路

`添加仓库 → 克隆和解析 → Fix 证据 → SZZ 标签 → Kamei 14 → 时间数据集 → 训练和评估 → 历史风险列表`

### 4.2 合入前评审链路

`选择仓库与 base → 提交 candidate ref/diff → 计算候选特征 → 已发布模型预测 → 概率和解释 → 风险队列`

## 5 范围与用户故事

课程合规性和实现优先级分别管理：`Must/Optional` 表示是否属于课程核心要求，`P0/P1/P2` 表示当前交付优先级。

### E1 数据与标签

| ID | 用户故事 | 级别 | 验收摘要 |
|---|---|---|---|
| US-01 | 添加公开 Git 仓库并开始采集 | Must/P0 | 合法 HTTPS URL 创建异步任务；重复请求幂等；内网、localhost、异常端口及重定向到私网均拒绝 |
| US-02 | 查看克隆和解析进度 | Must/P0 | 展示阶段、数量、心跳和安全化错误；刷新不丢状态 |
| US-03 | 增量同步默认分支 | Optional/P1 | 只处理新提交；不重复；强推或祖先变化进入人工确认 |
| US-04 | 识别 Fix 并查看证据 | Must/P0 | 关键词或确认的 bug Issue 构成证据；普通 Issue ID 不自动判定；规则版本可追踪 |
| US-05 | 运行 SZZ 并下钻证据链 | Must/P0 | 可追溯到 Fix、修复行、blame 行和候选引入提交；失败可重试 |

### E2 特征与数据集

| ID | 用户故事 | 级别 | 验收摘要 |
|---|---|---|---|
| US-06 | 提取 Kamei 14 特征 | Must/P0 | 公式和单位符合算法规格；同版本重算幂等 |
| US-07 | 查看特征质量 | Must/P1 | 展示缺失、分位数、极端值和标签分布；支持异常下钻 |
| US-08 | 按时间创建 train/valid/test | Must/P0 | 严格时间顺序，同时间按 SHA 稳定排序，预处理只在 train 拟合 |
| US-09 | 配置类别不平衡处理 | Must/P1 | 支持类权重；采样只作用于 train；valid/test 保持真实分布 |
| US-10 | 生成最小语义输入 | Optional/P1 | 从 message 和 diff token 构建输入；词表只在 train 拟合；空 diff 可处理 |

### E3 模型训练与评估

| ID | 用户故事 | 级别 | 验收摘要 |
|---|---|---|---|
| US-11 | 选择模型和参数发起训练 | Must/P0 | 注册表至少 6 个经典模型和 2 个深度模型；非法参数入队前拒绝；请求幂等 |
| US-12 | 查看、取消和重试训练任务 | Must/P1 | 状态、进度、日志摘要可见；协作式取消；重试保留来源关系 |
| US-13 | 查看 effort-unaware 指标 | Must/P0 | Precision、Recall、F1、ROC-AUC、PR-AUC、MCC、混淆矩阵；不可计算时返回原因 |
| US-14 | 查看 effort-aware 指标 | Must/P0 | 以 LA+LD 为 Effort，报告 PofB20、Popt 和 IFA；并列分数稳定排序 |
| US-15 | 比较并发布模型 | Must/P1 | 不同数据或版本默认不可直接比较；发布操作留审计记录 |

### E4 预测与解释

| ID | 用户故事 | 级别 | 验收摘要 |
|---|---|---|---|
| US-16 | 预测候选 commit、branch 或 diff | Must/P0 | 输入 repository、base 与 candidate；历史特征截止 base；无效 ref 和超限 diff 有稳定错误 |
| US-17 | 查看概率、等级和因素 | Must/P0 | 返回校准概率、模型版本、阈值和因素方向；展示非因果声明 |
| US-18 | 查看风险队列 | Must/P0 | 默认按概率排序，同时展示 Effort；风险密度只作辅助，大变更不能被隐藏 |
| US-19 | 批量扫描并导出结果 | Must/P1 | 支持数量或时间窗限制；任务可取消和重试；导出包含模型与口径 |

### E5 看板与治理

| ID | 用户故事 | 级别 | 验收摘要 |
|---|---|---|---|
| US-20 | 查看缺陷与风险趋势 | Must/P1 | 成熟标签趋势与预测风险趋势分开展示并可下钻 |
| US-21 | 查看长任务中心 | Must/P1 | 按类型和状态筛选；展示心跳、重试和关联资源；识别 stale |
| US-22 | 管理用户、角色和禁用状态 | Optional/P2 | Viewer、Member、Admin 权限生效；是否开放注册由部署配置决定 |
| US-23 | 查询关键操作审计 | Must/P1 | 记录操作者、时间、对象、动作和结果；敏感信息脱敏 |

## 6 非功能需求

| ID | 属性 | 验收目标 | 主要证据 |
|---|---|---|---|
| NFR-01 | 安全 | 阻止本地和私网仓库 URL、重定向绕过及越权；密钥不落日志 | SSRF、RBAC 和日志安全测试 |
| NFR-02 | 可靠性 | 长任务具备幂等、心跳、有限重试、断点或明确失败；重复请求不产生重复数据 | 故障注入和幂等测试 |
| NFR-03 | 性能 | 在固定演示环境和数据规模下，热模型候选预测与列表查询 P95 不高于 1 秒 | 至少 100 次请求的压测报告 |
| NFR-04 | 隐私 | 作者邮箱默认哈希或别名化；日志和导出不含密码、令牌或原始邮箱 | 数据与日志审查 |
| NFR-05 | 可复现 | 训练记录包含代码 SHA、数据集、标签/特征版本、依赖摘要、随机种子、参数和工件哈希 | 随机抽取一个 run 重跑比较 |

性能门槛属于待验证目标。报告必须同时记录硬件、数据、模型、冷/热启动和并发口径。

## 7 成功标准

- 核心历史链路和候选预测链路均可演示并通过 E2E。
- 课程硬指标均有自动测试、报告或界面证据。
- 数据集审计证明 Unknown 被排除、时间切分正确且不存在预处理泄漏。
- 任一发布模型和预测结果均可追溯到代码、数据、参数和工件。
- 代表性 OpenSpec change 能展示从 proposal、spec、design、tasks 到实现、测试和归档的完整过程。
