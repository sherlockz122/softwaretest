本目录的当前有效规格、决策和指导是 DefectGuard 后续开发及团队同步的权威基线。目录位置不自动赋予权威：历史报告保留当时事实，reviews记录复核结论；被新决策取代的段落不指导当前实施。外来原型/原始设计已隔离到 `archive/external/`，不再读取它们确定需求、API、标签或任务顺序。

当前规则见 [基线权威与隔离决策](decisions/2026-10-14-基线权威与外来材料隔离.md)。以后吸收外部经验必须先转写为自己的可验收规格，不能把外部文件直接放回有效基线。

外部材料与远程仓库旧文档的合并规则见《00 项目基线与版本合并决策》。需求变更必须同时更新受影响的本目录文档、OpenSpec change 和追踪矩阵。

## 使用规则

1. 产品级意图以 `01` 为准，技术实现约束以 `02` 至 `04` 为准。
2. 测试完成标准以 `05` 为准，协作与交付流程以 `06` 为准。
3. `07` 是证据索引，不替代需求、OpenSpec 或测试报告。
4. 每个功能开始编码前必须存在对应 OpenSpec 场景和任务。
5. 发生冲突时暂停实现，先形成明确决策并更新相关文档。
6. 同一主题以明确生效的最新决策及已同步规格为准；总计划末尾“当前优先”说明覆盖旧批次计划。OpenSpec冲突先修正，不按旧外部原型改实现。
7. 默认不检索/打开 `archive/external/`；课程必需项已在01/05/06/07纳入，追溯归档不等于放弃课程要求。用户根目录报告/幻灯片不是外来材料，保持原文件。

## 版本策略

本目录采用 Git 历史管理版本，不再通过复制 `V1`、`V2` 文件制造并行版本。文档标题不带版本号；版本、作者、评审和变更原因由提交、PR 与文档变更记录共同追踪。
