## 1 计划调整与交付

用户扩容 D 盘并授权质量优先后，取消旧 4 GiB 项目规划上限、默认 6 GiB 严格门槛和预先限定全部采集场景为 1000 提交/250 MiB 的安排。常规检查改为容量提示，默认建议余量 20 GiB；只有显式 `-StrictStorage` 采用严格检查，低于 2 GiB 仍拒绝启动写入命令以保护数据完整性。日志轮转、缓存复用、临时数据定向 D 盘继续保留。

先补足无缓存构建、独立随机配置和新数据库卷验收，再完成 `bootstrap-application` 2.3、3.1～3.4。将登录/任务页面与交付自动化作为下一批，随后才推进采集和模型，避免接口和恢复机制尚未稳定就扩展业务。更新 [整体规划](../development/后续整体规划与空间预算.md)、存储文档、API/测试规格、追踪矩阵和 OpenSpec。

交付内容：

1. `0002_tasks` 固定 MySQL 迁移，新增 async_task/task_outbox；精确 schema readiness 升级，已有认证数据保留。约束覆盖幂等键、唯一后继、状态、计数、进度、载荷和结果上限、外键。
2. A29～A32/A35：分页查询、详情、诊断创建、取消、重试；实际 Member/Admin 操作权限、Viewer 拒绝写操作及他人任务归属检查。创建与重试同时提交任务/outbox/审计，幂等冲突安全返回。
3. 独立 scheduler：短事务领取 outbox、事务外发送、有效投递令牌写回、指数退避和超限处理；协调队列截止时间与执行租约。
4. 真实 Celery Worker：数据库执行权、心跳、有效执行令牌、协作取消、终态保护和有限自动恢复。取消、队列超时和投递失败不自动生成后继；租约过期最多自动恢复 3 次。
5. 六组件 Compose、显式维护服务、独立新环境验收脚本，以及真实组件故障和数据库事务集成测试。

接口、配置和复验命令见 [可靠任务与运行验收](../development/可靠任务与运行验收.md)。诊断任务只运行 0～30 秒的可控工作，不接受仓库、URL、脚本或代码；production 不注册诊断创建入口。

## 3 验收中修正的问题

- 将动态任务路径限定 UUID，防止 production 移除诊断创建入口后仍被通用详情路由匹配为 405。
- 修正故障验收发布器的默认队列，明确发送至 `defectguard`，避免发送到 Celery 默认队列造成补投测试超时或重复消息测试没有真正经过 Worker。
- 修正完整回滚前检验：MySQL DDL 隐式提交，必须在删除任务表前检查后续认证迁移的非空保护，避免回退到 base 时先删表再拒绝。回归验证失败回滚仍保留 task/outbox、版本和就绪状态。
- 明确 MySQL CHECK 违规通过驱动可能被分类为 OperationalError；直接约束测试检验实际 MySQL 错误码，而非只依赖异常名称。

不存在为通过验收而缩短默认租约的情况。Worker 强制退出测试等待默认执行租约/协调周期；需要快速覆盖边界的独立数据库测试只改变自身任务时间。
