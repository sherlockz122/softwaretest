## 1 实现及指导依据

依据 `docs/04` 的认证/任务契约、`docs/08` 的界面状态和交互约束、`docs/05～07` 的验收及追踪要求，以及 `bootstrap-application` 规格推进。实施前补充并发 refresh、迟到响应、不确定写操作幂等及证据场景，未更改既有“access/CSRF 仅在内存、整页刷新重新登录可接受”的协议。

交付：

1. Vue Router `/login`、`/tasks`、`/tasks/:id`、`/health`，登录后返回原任务地址；退出与统一会话失效处理。
2. 任务列表的筛选、10 项分页、自动刷新、加载/空态/可恢复错误；详情展示阶段、心跳、进度、起止时间、错误/request ID、结果及 retry_of，取消和重试遵守真实 API 状态。
3. 同页面并发 401 共用一次 refresh；退出等待 cookie 轮转并清空内存，迟到响应不恢复身份。新查询取消旧请求、切换任务清空旧对象；离开页面停止轮询。
4. 创建/重试在网络结果不确定时保留同操作的 Idempotency-Key，按钮禁止并发重复提交；确认成功后才结束该操作。整页刷新不保存键，应先查看任务列表再决定新建。
5. 固定依赖锁的 Vitest、ESLint/Prettier、Playwright，实际代码 OpenAPI 导出/漂移检查；`wang-quality.yml` 仅对 wang push/目标 wang PR 和手动执行触发，不部署或修改其他分支。
6. 扩展独立新环境脚本运行浏览器验收，保留 JUnit、日志、HTML 报告和安全截图；本机 manifest 按路径/大小/SHA-256 索引，先清理实际配置 secret、JWT 和常见凭据字段。

API 与数据库仍为第四阶段实现，schema `0002_tasks`，没有新增业务表或安装模型依赖。采集入口的容量控制明确分配至 `add-data-collection` 1.5，不为框架制造空采集入口。使用说明见 [页面与质量验收](../development/页面使用与质量验收.md)，变更清单见 [文档更新记录](../development/文档更新记录.md)。

## 3 修复与首次失败结果

首次浏览器运行 6 passed、2 failed，已保存，不覆盖。发现默认“全部状态”被序列化为 `status=`，后端正确拒绝导致列表报错，也影响响应丢失及 refresh 场景；修复为省略未选筛选值。第二次 8/8 通过，追加跨页/Viewer 界面验收后最终 9/9 通过。

同时修正任务地址切换时的旧对象展示，避免新地址加载期间仍保留旧任务操作按钮；作用域销毁和迟到结果在单元测试覆盖。退出遇到 CSRF 拒绝不再默认为撤销成功。补充显式失败退出码，使 CI 不能因 finally 清理成功而误判验收通过。

已知提示：Starlette TestClient 的 httpx 弃用提示仍有一条，不影响通过。前端测试工具依赖中有旧 glob 的 npm 弃用提示，依赖审计结果单独保留；不在本阶段升级全局 Node。后续工具升级需重新锁定并复验。
